# MVP 验收清单

更新日期：2026-11-04；以下产品级验收需逐项提供证据。规格来源：[diary-spec.md](./diary-spec.md)。

协议、浏览器与 PG 层已有[独立验证记录](./validation/collaboration-readiness-2026-10-24.md)。以下清单仍保持未勾选：原型测试不替代正式认证、浏览器输入法、存储与界面的完整验收。

## 执行方式

P0 是首版发布阻断项；P1 是体验目标，未满足时需记录影响与后续处理，不得伪称通过。每条执行结果记录测试版本/commit、设备浏览器、网络条件、操作步骤、预期与实际、截图或测试输出。勾选仅表示附有证据的通过，不能因代码存在而勾选。

测试账号：初始 A、B 属于 AB 空间，C 不属于 AB；生命周期用例验证 A/B 解绑后拒绝 A/C 绑定、仅允许 A/B 重绑；首次绑定竞争另用尚无固定搭档的独立账号。A1/A2 为 A 的两个设备。测试数据使用虚构日记，不使用真实私密内容。默认初始正文：A“今天很累，但是想到你就开心了。”；B 在逗号后插入“抱抱！”。

自动化优先覆盖状态机、权限、数据库竞态、Unicode、同步与故障；真实手机输入法、阅读位置、颜色可读性和删除手感人工验收。测试只在隔离数据库、专用 Google 测试文件夹和测试账号执行。

## 当前关系交付与产品验收的区别

关系 ADR 当前只交付邀请、绑定/解绑、原空间关系记录恢复和本人共享范围配置；已实现，验证见其[验证](./adr/2026-10-25-spaces-and-invitations.md#验证)，不依赖日记或 Yjs。范围配置逻辑用日期值验证，不以真实正文共享验证。

以下仍是完整产品验收，不因为关系交付已实现就整项勾选。AUTH-07/08/09、SHARE-01/03/10/11/12 等包含关系/配置和正文集成的混合要求：本次只证明相应关系、配置或接口隐私部分；日记冻结/恢复、补写后自动共享、未授权正文与版本隔离、旧协同队列与导出须后续实现并补证据。DATE、EDIT、SYNC/SAVE、READ/GOOGLE 均不属于本次关系交付。

## 登录与空间 AUTH

- [ ] AUTH-01 / P0：未登录不能请求日记、导出、备份状态或 WebSocket 订阅；C 即使知道 diaryId 也不能访问。
- [ ] AUTH-02 / P0：A 创建邀请、B 明确接受后加入；失效、撤销或重复使用的邀请不能再次加入。
- [ ] AUTH-03 / P0：至少 20 人竞争 A 的邀请，或 A 并发接受 B/C 的邀请，只能一对成功；A/B 互邀并发接受也只创建一个期间。每空间两位固定参与者，每账号至多属于一个永久空间且至多一个当前绑定，失败无半绑定；竞争失败者不能在胜出者解绑后改绑。
- [ ] AUTH-04 / P0：Google 登录成功但拒绝 Drive 授权，仍可编辑；Drive 备份明确显示未连接。
- [ ] AUTH-05 / P0：会话过期或访问被撤销后，HTTP 和协同连接均拒绝新写入；本地未同步文字保留为可恢复草稿。
- [ ] AUTH-06 / P0：同设备退出并切换账号，不能看到上一账号的本地日记/草稿；退出前存在未同步内容时有明确保留/恢复说明。

- [ ] AUTH-07 / P0：任一参与者二次确认后可单方解绑，无需对方同意；双方当前绑定解除，日记、空间及关系业务数据不删除，归档双方只读，C 无访问权。
- [ ] AUTH-08 / P0：A/B 首次绑定后，即使解绑，A/C、B/C 绑定仍被拒，双方固定搭档身份保留；原双方确认后复用 AB spaceId 并创建新 periodId，历史及计划/赠礼等已实现业务数据保留，关系恢复不自动开放日记。邀请确认页明确首版不支持更换搭档并核对账号；没有误绑纠正入口。
- [ ] AUTH-09 / P0：旧解绑请求在重绑后重放，只返回原关闭期间，不结束新期间；旧期间或 share epoch 的写入、订阅补发不能获得新授权，待发原文保留恢复草稿。
- [ ] AUTH-10 / P0：邀请七天到期（等于 expiresAt 也无效）、撤销、轮换和消费后不能再绑定；不指定邮箱、未登录不能接受、不能接受自己的邀请。登录/预览不产生绑定，成功绑定关闭双方其他邀请。
- [ ] AUTH-11 / P0：发起者和接受者分别确认自己的范围，可不对等开放；同人重绑可仅恢复关系而双方均不重开日记，原选择只能由本人参考，之后可独立确认重新开放。

## 日期与创建 DATE

- [ ] DATE-01 / P0：给定服务端 UTC 时间 2026-10-24T02:00:00Z，A 时区 Asia/Shanghai 创建日期为 2026-10-24，B 时区 America/Los_Angeles 创建日期为 2026-10-23；不错误合并为同一天。
- [ ] DATE-02 / P0：同用户同日期存在日记时，重复点击只打开原 diaryId；未绑定也可写，A、B 同日各一篇。绑定、解绑和重绑不改变主人、diaryId 或日期。
- [ ] DATE-03 / P0：至少 20 个请求并发创建同主人同日期，数据库仅一行，其余可定位原 diaryId；另一主人同日可独立创建，不出现孤立协同文档或错误覆盖。双人页面拼接两篇可读日记并保留编辑边界。
- [ ] DATE-04 / P0：编辑旧日记、跨午夜继续写、改变设备时区及另一方打开，原 diaryDate 均不变。
- [ ] DATE-05 / P0：设备时钟故意偏移，今天仍由有效时区和服务端 UTC 推导；无效 IANA 时区被明确拒绝。
- [ ] DATE-06 / P0：历史日期可打开/补写，缺失的过去日期可明确创建；离线不伪称新日记已成功创建。
- [ ] DATE-07 / P1：首页卡片列出本人全部日记，日记日期从新到旧、分批加载；卡片显示日期、正文开头摘要（空白日记标明）与最后修改时间，点击打开该篇；只列本人日记，离线时说明无法读取而不是显示为空。

## 日期共享与授权版本 SHARE

- [ ] SHARE-01 / P0：日历可选单日、多个不连续日/区间、全部历史与未来、从某日起持续及排除日期；端点包含当天、排除优先，相同日期集合规范化后不重复新开授权。
- [ ] SHARE-02 / P0：按 diaryDate 而非 createdAt 或查看者时区匹配：今天补写范围内过去日期会共享，范围外不共享；未来已选日期不提前建日记，后来创建按同一选择自动共享。
- [ ] SHARE-03 / P0：首次邀请/接受默认全部历史及持续共享，但本人必须明确确认，可改选或暂不开放；未确认或旧期间的选择不能自动成为本期授权。
- [ ] SHARE-04 / P0：首次开放旧日记显示授权的最新主人与固定搭档版本，双方之后只能改自己的文字；排除或解绑锁定最后已提交 V1，对方只读且看到“已停止共享，内容不再更新”。
- [ ] SHARE-05 / P0：停止后主人新增、修改、删除形成 V2，对方仍看 V1；本人确认重新选中该日才新开授权，切到最新 V2 并恢复更新，V1 冻结记录不覆写。
- [ ] SHARE-06 / P0：A/B 解绑、A 私下更新或补写，再重绑但暂不重开时，B 仍只看原冻结历史；A 确认范围后 B 可看范围内包含分开期间变化的最新版本，不套用“永久禁止开放”的旧规则。
- [ ] SHARE-07 / P0：A 的个人日记只含 A 与固定搭档 B 的文字；解绑后 A 可在保留 B comment 的个人最新视图中普通编辑 A 的文字，不能修改 B 的字；AB frozen 仍显示当时 A＋B，不跟随 A 最新变化。
- [ ] SHARE-08 / P0：B 只能获取获准日期和版本，第三人 C 不能获取 AB 内容；猜 ID、伪造 partner 参数、同步/原始 CRDT 载荷、搜索与导出不能泄露未共享正文、停止共享后的变化或稳定锚点指向的未授权正文。
- [ ] SHARE-09 / P0：取消日期后已收到的日记仍有 frozen 版本；从未开放或尚无日记的日期不生成冻结占位。列表当前只展示 live 或最后 frozen，不把历史版本伪装成重复日记。
- [ ] SHARE-10 / P0：首次开放/重开预览日期范围，说明共享当前正文及后续、不补授私人历史和撤销从新起点开始；确认后暂缓本页面输入、先保存本页面待发内容，不等待其他设备上线，以服务端执行时最新已提交正文为起点。缩小前说明对方保留只读历史，停止不等待搭档保存或上线；断网/PG 失败不提前显示已生效，取消/重开/写入竞争保持原子版本边界。
- [ ] SHARE-11 / P0：对方不能获取具体范围、排除日期、未共享日记存在与数量、阅读过滤动作；无私密锁定占位，列表计数、错误、未读及通知无旁路泄露。已共享的 frozen 状态可见。
- [ ] SHARE-12 / P0：同 requestId 的范围保存幂等返回原结果，不一致载荷拒绝；旧 revision 冲突不覆盖新设置；重绑后新请求确认相同日期集合仍建立本期间的新授权，而旧请求重试不重新应用；旧 epoch 离线操作不自动重放，保留恢复草稿。
- [ ] SHARE-13 / P0：读取、搜索、同步、导出及备份均解析相同授权版本；归档引用在历史压缩后仍可重建，快照故障不能回退个人最新全文，取消后不再输出个人变化到旧共享目标。

## 字符归属与编辑 EDIT

- [ ] EDIT-01 / P0：按示例穿插后，作者顺序是 A/B/A；过滤 A 后仍为“今天很累，但是想到你就开心了。”，过滤 B 后为“抱抱！”。
- [ ] EDIT-02 / P0：双方均可在另一方文字的任意可感知字符边界继续插入；每个新增字符（含空格、换行）归输入者。
- [ ] EDIT-03 / P0：A 删除/替换己方文字成功，不能修改 B 的文字；颜色或富文本属性操作不能伪造作者。
- [ ] EDIT-04 / P0：Backspace 遇到 B 时只跳到前方 A 文字末尾，本次不删字；Delete 对称；无己方文字时停在边界。
- [ ] EDIT-05 / P0：长按连续删除到作者边界后停止连删；松开再按才可删跳转后的己方文字；真实手机与桌面验证。
- [ ] EDIT-06 / P0：选区含 A/B 时删除、剪切、打字替换及粘贴替换均被阻止且正文不变；复制成功；纯己方选区可替换。
- [ ] EDIT-07 / P0：A 建立选区后 B 在该范围插入，再由 A 删除/替换；B 新增文字仍完整，A 不发生静默回滚或越权。
- [ ] EDIT-08 / P0：从外部富文本/伪造作者标记粘贴，得到纯文本且归当前用户；拖动文本不能绕过限制。
- [ ] EDIT-09 / P0：A 撤销自己的插入和删除，只影响 A；A 原文中已有 B 的后续插入仍保留；重做不伪造 B 的作者。
- [ ] EDIT-10 / P0：emoji 家庭组合、肤色、旗帜、组合音标、中英文混排，插入、选择、删除、同步与导出均不拆坏字符。
- [ ] EDIT-11 / P0：真实中文输入法确认前，拼音/候选字不发给 B；确认后只出现一次；远端更新不打断 composition。
- [ ] EDIT-12 / P0：绕过前端直接发送伪造 actor、修改作者、删除 B 字符或构造低层协同更新，服务端拒绝且数据库/其他客户端不受影响。
- [ ] EDIT-13 / P1：两种字体色正文清晰、没有永久作者底色；同一用户跨设备颜色一致；可借名字图例及点击识别作者；作者颜色不改变可信作者，阅读过滤另按 EDIT-14 验收。

- [ ] EDIT-14 / P0：绑定中、解绑后的个人日记及归档均可“只看我的文字”，按 authorId 过滤，包含本人写在对方日记里的想法；不删除内容、不改对方显示/权限、不产生正文/未读/备份变更、不通知对方，过滤只读且退出过滤不解除归档只读。
- [ ] EDIT-15 / P0：首版只展示主人与固定搭档的文字，没有历史 partner 切换；个人最新视图与冻结归档切换本身不产生错位或跨作者改删，不恢复搭档写权，第三人参数不能改变作者或权限范围。

- [ ] EDIT-16 / P0：按服务端提交时间每五分钟分组、两分钟无正文提交后引用最后提交版本补末点，同版本去重，共享边界独立；从当前日记进入右侧按日列表，最近在前、按需加载，完整只读预览保留作者颜色、展示本地时区；空状态不制造历史。新编辑不切走预览，返回恢复位置、保留待发内容，停止共享的搭档仍看只读冻结正文。列表元数据不泄露私人活动，历史点及获准冻结长期可重建。主人和搭档均无整篇或按作者回滚入口；查看历史不改变当前正文、共享状态、作者或撤销栈。主人只读本人历史，搭档只读获准共享轮次的起点及后续版本，重开不补授私人历史；不能通过历史版本参数或原始状态覆盖当前正文，普通编辑仍受作者保护。
- [ ] EDIT-17 / P1：超过约 26 万字（一条 1 MB 传输消息，计入编码）的粘贴在输入时被拦下并提示分段粘贴，剪贴板内容保留，不产生本地待发内容；不超过上限的大段粘贴单独成批保存。

## 协同与持久化 SYNC / SAVE

- [ ] SYNC-01 / P0：A/B 同时在同一位置连续输入不同句子，合法内容全部保留，不逐字破碎交错；最终正文、顺序及作者一致。
- [ ] SYNC-02 / P0：在不同位置并发输入、删除己方文字并接收对方插入，全部客户端最终收敛，作者保护成立。
- [ ] SYNC-03 / P0：显示对方名字、光标及选区；对方在上方插字后光标仍指向对应内容。正文与光标分别处理，普通移动不等待 PG；新字符尚未到达时暂存最新有效位置，正文到达后准确显示；光标移动不生成正文写入/未读/备份。
- [ ] SYNC-04 / P0：A1/A2 同账号并发编辑，不互相覆盖；B 的多个在线会话可辨别，不冒充独立作者。
- [ ] SYNC-05 / P0：断线、关闭页面或心跳过期后清除过期光标，不长期显示正在编辑。
- [ ] SYNC-06 / P1：阅读长文时，上方收到插入不抢焦点、不强制跳到对方光标，当前阅读内容保持稳定。
- [ ] SAVE-01 / P0：延迟服务端持久化期间本地输入立即可见，但不显示已保存到服务器；事务成功后才显示已保存。
- [ ] SAVE-02 / P0：A 离线续写已缓存日记，刷新/关闭重开后能恢复本机已持久化文字；重连与 B 的在线更新合并，不整篇覆盖。
- [ ] SAVE-03 / P0：模拟重复、丢失、乱序消息及 ACK 丢失，重试不重复插字，不因旧快照回退；比较恢复前后的完整正文及作者元数据。
- [ ] SAVE-04 / P0：服务端在“收请求后提交前”崩溃，不能提前确认/广播为已提交；重试可恢复。提交后 ACK 前崩溃，重试只应用一次。
- [ ] SAVE-05 / P0：数据库失败或服务端重启，已确认文字重启后仍在；未确认文字保留本机且状态真实。
- [ ] SAVE-06 / P0：本地存储空间不足、禁用或写入失败时，明确提示并保留当前正文可复制/下载，不误报已保存到本机；有未落盘输入时自动同步或切基线不能覆盖原文，存储恢复可保存原操作。
- [ ] SAVE-07 / P0：服务端拒绝过期/非法操作时，待发送内容保留在恢复草稿，不静默消失，也不让其他成员看到未接受的非法状态。
- [ ] SAVE-08 / P0：连续进行“输入→收到远端更新→断线→重连→刷新”，不出现合法输入先显示、稍后被旧全文全部回退的情况。

- [ ] SAVE-09 / P0：应用日志的顺序分配与 pending 插入、ACK 回执与 pending 移除分别同事务；反序 UUID、插入后修改/删除、ACK 丢失、事务中止与多标签页依赖均按持久化顺序处理，服务端不接受残留缺失依赖的更新；转草稿先查提交结果、原子安装基线，查询期间新增输入不被丢弃。
- [ ] SAVE-10 / P0：自动小批发送第一笔即时、后续按序收集，原操作 ID、字节和时间不变，固定批身份/成员发送前落库。每批一个 PG 事务/版本，任一笔失败整批零提交且无部分成功 ACK；确认丢失、本地确认失败、客户端/服务端崩溃、授权切换、多标签及长离线链不重复、不误报、不越过依赖。批量场景尚未验证，当前不得勾选。
- [ ] SAVE-11 / P0：临时故障重试原批、登录过期暂停、永久校验失败停止后续依赖；未知提交结果先查回执，升级不强制刷新。恢复草稿展示本人插入/删除/替换意图，仅查看/复制/明确删除，不自动重放或一键覆盖；载入新基线不自动删除草稿。

## 未读与时间 READ / TIME

- [ ] READ-01 / P0：B 在昨天和更早日记中间插入，A 能看到有新内容，并跳到准确位置；A 自己输入不产生自身未读。
- [ ] READ-02 / P0：A 打开长日记但未滚到下方，下方新内容仍未读；后台标签页和不可见区域不自动算已读。
- [ ] READ-03 / P0：A 先看到较晚写入的内容，未看到的较早写入仍未读；不能用最大操作序号误清除。
- [ ] READ-04 / P0：阅读标记跨设备合并；重复更新、光标、导出不产生未读；已删除文字不导致无法完成的未读定位。
- [ ] READ-05 / P0：双方互相看不到对方的阅读回执，不存在默认公开的已读时间。
- [ ] READ-06 / P0：重开保留原字符已读范围，旧未读及私人期间首次获准的对方可见新增仍未读；已读旧字不重置，删除后重输是新字。私人写后删除不输出或产生未读，删除文字不留下无法定位的未读；跨设备合并不清除未见范围。
- [ ] TIME-01 / P0：数据库时间为 UTC 时间点；同一文字在上海、洛杉矶正确推导当地时间，包含美国夏令时切换前后两个不同 UTC 时间对应的重复当地小时。
- [ ] TIME-02 / P0：离线输入重连后仍保留原客户端写入时间及服务端接收时间；设备时钟异常不改变协同排序、日期或权限。
- [ ] TIME-03 / P0：相邻同作者但不同时间批次不会因压缩丢失时间；替换的新文字记录新写入时间，点击可查看。

## 服务器备份与 Google 可读副本 GOOGLE

设计见 [server-backup-and-google-docs](./adr/2026-10-28-server-backup-and-google-docs.md)：服务器备份负责恢复，Google Doc 只供阅读。

- [ ] GOOGLE-01 / P0：Drive 授权只请求 drive.file；state、PKCE 与发起会话的校验有效；refresh token 只以密文存于数据库，不出现在浏览器存储、日志、接口返回或备份明文中。
- [ ] GOOGLE-02 / P0：关闭应用页面后后台仍可写 Doc；撤销/过期时显示需重新连接，不影响 PG 保存；重新连接后续传积压的日期。
- [ ] GOOGLE-03 / P0：自动写入与"现在备份"都生成可读 Doc，与日期页一致：日期、换行、Unicode、作者图例、双方字体颜色、穿插顺序、本人在上；重复处理复用同一份 Doc，内容未变时不写。
- [ ] GOOGLE-04 / P0：Doc 只在本人 Drive 里，退出应用仍能从 Drive 打开；没有公开链接或未经操作发送的邀请；Drive 里只有本人能在应用里看到的内容，对方未共享的日记、共享期之外的私人修改、任何人的阅读进度都不出现。
- [ ] GOOGLE-05 / P0：PG 正文提交和 outbox 同成败；后台进程重启后可续跑；重复任务、版本倒序、并发重试不让旧版本覆盖新版本，不产生多份当前 Doc。
- [ ] GOOGLE-06 / P0：Google 限流、网络失败、权限撤销、存储空间不足时重试/提示正确；始终区分已保存、已成历史与已备份到 Google，显示真实覆盖的版本和时间；需要用户处理时首页提醒。
- [ ] GOOGLE-07 / P0：服务器备份持续进行：有修改时约一分钟内 R2 出现新的加密日志，每天一次完整备份；没有密钥无法解读 R2 上的对象；R2 暂时不可用时写日记不受影响，恢复后积压日志补传。
- [ ] GOOGLE-08 / P0：在 Google 直接改过的 Doc 不被覆盖，包含检查后到写入前发生修改的竞态；改过的 Doc 改名保留、另建新 Doc 继续更新；被删的 Doc 在下次写入或每日检查时重建，不反复新建；应用不删除 Drive 里的文件。
- [ ] GOOGLE-09 / P0：应用误写空内容或删除后，能恢复到出错前一分钟（30 天内）；更早的时间可恢复到每月第一份完整备份；断开 Google 连接不删除既有文件。
- [ ] GOOGLE-10 / P0：用一条恢复命令在空环境恢复，正文、顺序、作者、日期、UTC 时间、已读、关系与共享设置一致；用户登录即对应原账号，双方可继续协同，且作者限制仍有效；记录恢复耗时。
- [ ] GOOGLE-11 / P0：损坏、解不开或不完整的备份被明确拒绝，不导入一半；每周自动恢复演练通过才打卡；每日备份或演练停止打卡、失败时，运营者在服务器宕机的情况下也能收到通知。
- [ ] GOOGLE-12 / P1：服务健康且无积压时，从形成历史版本到 Doc 写入完成约 60 秒内；实测一天写作的日志上传量；记录样本与实际值，不把目标标为无条件保证。
