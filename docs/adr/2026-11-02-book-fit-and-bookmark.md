# 主页的书放进窗口，书签画在书上，任何时候都先有一本书

- 状态：已实现
- 日期：2026-11-02
- 决策者：Ray
- 范围：技术栈
- 关联：依赖 book-surface；依赖 contents-spread；取代 book-surface 的D1 aspect 行、D6 书签位置与不变量 3 的书签部分

主页的 3∶2 书取能放进窗口的最大尺寸：宽度取窗口宽度、96rem 与「（窗口高度 − 2rem）× 1.5」的最小值并居中，内容按书的宽度缩放，右页内容更长时在页内滚动，宽窗口不再纵向滚动。「目录」书签不再固定在窗口上、按估算的位置对齐书，而是画在书上：由 `<BookSpread>` 绘在书的盒子里，宽窗口贴在右页外缘，窄窗口在单页右上角随窗口滚动时吸附在窗口顶部；目录合上时画在当前页的书上，打开时画在目录的书上，同一时间只有一个，没有书就没有书签。登录检查、各页加载与出错时也画在书上，应用脚本加载前窗口已是纸色。本 ADR 只改书的尺寸、书签的位置与加载时的呈现；目录的行为（contents-spread）和各页的内容都不变，书本表面也不预先写进 `index.html`（Ray 延后）。

## 背景与问题

Ray 在 2026-11-02 用开发服务器试用所有书页（book-surface、contents-spread 已实现）时发现三个问题，并由协调会话在 Chromium 中复现：

1. 主页的书按窗口宽度定 3∶2，不管窗口高度：1440×800 下书高 995px，1920×960 下 1057px，1280×720 下 893px，窗口要纵向滚动；右页的两地时间与作息时间线也略高于 3∶2。
2. 书签是 `position: fixed`，位置由根上的 `--book-width`、`--book-height`、`--book-top`、`--bookmark-at` 估算，主页再用 `body:has(…)` 覆盖。主页滚动时书动而书签不动；没有书的时候也显示书签。
3. 刷新时 `#root` 先空 0.3–0.5 秒且没有纸色背景（纸色由 `body:has(.book-desk)` 设置）；随后登录检查显示一行没有书的「正在打开…」，出错时同样；双人空间与邀请页等数据时也只有一行字，`/spaces/:id` 上约 0.6 秒只看得见一条书签。

## 决策依据

1. 宽窗口里主页的书完整可见，像其他书页一样不必滚动窗口（Ray 2026-11-02）。
2. 书签是书的一部分：它跟着书移动，不能脱离书单独出现。
3. 书签的位置只有一个所有者，不靠对书的位置的估算。
4. 从第一帧起看到的就是这本书的纸，等待和出错时也一样，不出现白屏或不在书上的文字。
5. 目录已有的行为不变：返回、Escape、「合上目录」与书签合上它，焦点回到书签，原页面保持挂载、`inert` 且隐藏（contents-spread）。
6. 窄窗口没有横向滚动，书签在单页滚动时仍在屏内（opening-book-home D4）。

## 决策

### D1：主页的书是能放进窗口的最大 3∶2

`fit="aspect"` 的书宽度为 `min(100%, 96rem, (100dvh − 2rem) × 1.5)`，上下各留 1rem 并居中，高度是宽度的 2/3。书是内容的尺寸容器，主页内容用 `cqw`，所以整页随书缩放；右页内容仍比 3∶2 长时，在页内滚动，和窗口高的书页一样。主页左页全部按 `cqw` 排版、总能放下，不滚动，水彩窗台可伸入页边；右页的滚动框伸入页边 2cqw，时间线两端的时刻不被裁掉。

| 窗口 | 书 |
| --- | --- |
| 1280×720 | 1032×688，窗口不滚动 |
| 1440×800 | 1152×768，窗口不滚动 |
| 1920×960 | 1392×928，窗口不滚动 |
| 宽于 56rem 但高不足约 630px | 书保持两页所需的 56rem 宽，窗口纵向滚动，书签随书移动 |
| ≤56rem | 单页，与以前相同 |

下限 56rem 是双页内容可读的最小宽度；为了不滚动而把书缩到更小，正文会小到读不清。原因：依据 1、6。

### D2：书签画在书上，同一时间只有一个

`<BookSpread>` 在书的盒子里绘出书签：一条铺满书、不接收指针的轨道，书签在其中。`<ContentsBookmark>` 通过上下文告诉书是否画书签、目录是否打开以及点它做什么：

| 状态 | 画书签的书 |
| --- | --- |
| 目录合上 | 当前页的书 |
| 目录打开 | 目录的书（展开样式，`aria-expanded="true"`，`aria-controls` 指向目录） |
| 未登录、正在检查登录或页面没有书 | 没有书签 |

位置按书的百分比给出：宽窗口距书顶 9%（主页 12.5%）、距书右缘 1.8%；窄窗口在单页右上角，`position: sticky` 使它在单页随窗口滚动时停在窗口顶部，单页离开窗口时随之离开。根上的 `--book-*`、`--bookmark-at` 变量与 `body:has(…)` 覆盖删除。

合上目录时书签从目录的书回到当前页的书，焦点落在这个书签上；其余目录行为照 contents-spread。书签在书内的 DOM 位置在两页之后，Tab 顺序与以前相同。原因：依据 2、3、5、6。

### D3：等待与出错都画在书上

- 登录检查（`RequireAuth`）等待和出错时显示一本书，「正在打开…」或「服务暂不可用，请稍后再试」与「重试」在左页；此时没有会话，所以没有书签。`auth` 因此可以引用 `book`。
- 各页在数据到达前显示空白或部分的书，与两地时间页相同：双人空间页是空白的书，邀请页是左页开篇、右页空白的书。
- `index.html` 内联纸色背景，应用脚本与样式加载前的第一帧已是纸色。

书本 SVG 不预先写进 `index.html`：Ray 于 2026-11-02 决定延后。原因：依据 4。

## 不变量

1. 宽于 56rem、高至少约 630px 的窗口里，主页的书完整在窗口内，窗口没有纵向滚动。
2. 书签只出现在书上：它在当前显示的书的元素与盒子之内，同一时间最多一个，没有书就没有书签。
3. 窄窗口的单页随窗口滚动时，书签完整位于窗口内，没有横向滚动。
4. 登录检查、页面加载与出错时窗口里都是书，应用脚本运行前窗口已是纸色。

## 备选方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| **保留固定定位，修正估算公式** | 改动最小，书签永远在屏内 | 仍是两个所有者各算一次书的位置，任何一页改了书的大小都会再错位；窗口滚动时书签仍离开书（依据 2、3） |
| **主页改用窗口高的书** | 与其他书页同一种尺寸规则 | 宽高比在 1.75 以内变化，主页按 3∶2 排的插画与时间线会被拉伸或留白，和已认可的复现不一致（依据 1） |
| **主页书不设下限，任何高度都不滚动** | 不出现窗口滚动 | 矮窗口里书缩得太小，按 `cqw` 排的字读不清 |
| **每页的书各自渲染书签，打开目录时两个都在** | 不需要上下文 | 隐藏的原页里还有一个书签，读屏与测试都会遇到两个「目录」（依据 2、5） |
| **把书本 SVG 预先写进 `index.html`** | 第一帧就有完整的书 | 书本几何会有两个所有者；Ray 决定延后 |

## 风险与代价

- 高度不足约 630px 的宽窗口仍要纵向滚动主页（D1 的下限）；书签随书移动，不会停在窗口里。
- 书签从原页的书移到目录的书时是两个不同的元素，焦点由 `ContentsBookmark` 交还；新加的页面若同时渲染两本书，会出现两个书签，需要只渲染一本。
- `index.html` 的纸色压过 `styles.css` 的深色页面背景；现在所有界面都在书里，深色变量没有使用者。

## 验证

不变量的测试在标题里带 `[adr:book-fit-and-bookmark#N]`；尺寸与位置只在真实浏览器里有意义，ADR 索引不统计浏览器测试。

1. 主页放进窗口：浏览器测试在 1280×720、1440×800、1920×960 下检查主页的书完整在窗口内、宽高比为 3∶2、窗口没有纵向滚动。
2. 书签在书上：组件测试检查目录合上时书签在当前页的书里、打开时在目录的书里、始终只有一个、合上后焦点回到书签、没有书或没有目录时没有书签；浏览器测试在主页（窗口滚动后也是）、所有日记、两地时间与目录打开时检查书签在显示的书的盒子内。
3. 窄窗口：浏览器测试在 375 与 320 像素下，单页滚到一半和末尾、目录滚到末尾时，书签完整在窗口内、在单页上，没有横向滚动。
4. 加载时的书：组件测试检查登录检查等待和出错时文字与「重试」在书的左页、没有书签；浏览器测试拦住应用脚本时检查窗口是纸色，拦住 `/api/me` 时检查有书、没有书签，拦住双人空间的数据时检查有书、书签在书上，并在整个过程中记录书签从未出现在书外。
