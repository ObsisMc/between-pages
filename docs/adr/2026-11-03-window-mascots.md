# 主页窗里的团子可以戳和摸，对方在主页上看到，团子只按作息睡觉

- 状态：提议
- 日期：2026-11-03
- 决策者：Ray
- 范围：领域
- 关联：依赖 digital-paper-interface；依赖 two-clocks；依赖 spaces-and-invitations

主页双窗里的两个团子可以互动。轻点是戳，按住拖动是摸。对自己的团子做，只在自己的屏幕上播放动画，不发出任何请求。对对方的团子做，会发给对方：服务端为每人保留一行「还没看到的戳和摸」累计，对方打开主页时自己的团子跳起来，窗下留一行「TA 在 17:02 戳了你 3 下，摸了摸你」，显示过就删除。对方的团子只在对方作息的睡觉时段里睡着，和是否在线无关；戳睡着的团子不会把它叫醒，但戳照样送到。

本文不负责：邮件或推送通知；路线图里需要通知的「想你了」（本功能不替代它）；团子的造型与窗户的画法（digital-paper-interface D4）；手机端的专门适配（随阶段 4 的手机支持）。

## 背景与问题

Ray 在 2026-11-03 看过新主页后，希望窗里的团子能互动，用来表示和对方互动；同时问，对方不在线时团子是否应该显示在睡觉。分叉会话里做了一个 spike（本地分支 `spike/mascot-poke`，不合并）：戳、摸、收到后的反应、按作息睡觉都在两个账号之间跑通，Ray 认为可行。spike 把戳和摸存在 API 进程的内存里，靠前端每 8 秒询问一次，没有测试和文档。

已有约束：

- 最近活跃时间不进入任何返回给另一位成员的接口，那相当于在线回执（authentication-and-sessions 不变量 9，规格 §8.1「不默认公开对方已读状态」）。
- 两地时间的「大概在睡」按对方作息和时区推算，不声明对方此刻在线或清醒；Ray 在 2026-10-29 决定不做「睡了、在忙」这类手动状态（two-clocks）。
- 对方的时区与作息只在绑定期间给当前搭档（two-clocks D5）。
- 双人空间记录有不改不删的动作历史、解绑后只读归档（space-records），适合心愿、纪念日这类要留下来的东西。
- 路线图把「轻触想你了」放在「等通知」一行：要对方不开应用也能知道才有用。

## 决策依据

1. 两个人打开主页时，能用很轻的动作向对方表示「我在」，并能看到对方这样做过。
2. 不暴露在线、活跃或是否看过：发送的一方得不到任何回执（规格 §8.1，authentication-and-sessions 不变量 9）。
3. 互动只属于当前绑定中的两个人；解绑后谁都发不出、也看不到（two-clocks D5 的同一边界）。
4. 戳和摸是瞬时的表达，不是要保存、回看或备份的记录；没有消费者的数据不存（AGENTS.md）。
5. 作者与发送方由服务端按会话确定，不信任客户端（ADR-0003、ADR-0006）。
6. 不新增依赖、通道或常驻连接就能满足依据 1 时，不新增。
7. 动画不能妨碍阅读和键盘使用；系统要求减少动态效果时尊重它。

## 决策

### D1：戳或摸自己的团子只在本机播放，对对方的团子做才发送

| 动作 | 自己的团子 | 对方的团子 |
| --- | --- | --- |
| 轻点（戳） | 压扁再弹回、眯眼，气泡随机一句「嘿嘿 / 痒～ / 在呢 / 别闹啦」 | 同样回弹，气泡「戳了 TA 一下」，2.5 秒内连戳显示「戳了 TA 3 下」；每次都发送 |
| 按住拖动（摸） | 跟着手歪、轻颤、眯眼笑，手经过处冒小爱心，气泡「好舒服～」 | 同样的动画，气泡「摸了摸 TA」；一次拖动发送一次 |
| 对方在睡时 | — | 不醒；戳的气泡「嘘…TA 大概在睡」，摸的气泡「TA 睡得更香了」；照样发送 |

未绑定或已解绑时，右窗是空窗，没有团子可以互动。台词、幅度与时长可以在实现 PR 里按 Ray 的验收调整，不需要改本 ADR。

原因：依据 1、4。和自己的团子玩不涉及对方，不值得一次请求或一行数据。

### D2：轻点是戳，拖过 14 像素是摸，键盘只能戳

指针按下后移动不到 14 CSS 像素就松开，算戳；超过就进入摸，直到松开。摸期间团子朝指针一侧倾斜。触屏同样适用，按在团子上拖动时页面不滚动（`touch-action: none` 只加在团子上）。团子是可聚焦的按钮，名称为「戳戳或摸摸自己的团子」「戳戳或摸摸 TA」；Tab 聚焦时显示焦点框，回车和空格是戳；摸只能用指针，键盘不提供。

系统设置了减少动态效果时，压扁、跳、倾斜、呼吸、眨眼与飘起的爱心都不播放，只换表情、显示气泡。

原因：依据 7。用一个距离门槛区分两种手势，不需要长按计时，也不会把点歪了的戳误判成摸。

### D3：服务端只存一行待看累计，看过即删，不留历史

新表 `mascot_pokes`，每个绑定期间里每个接收方最多一行：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `period_id` | uuid，引用 `binding_periods` | 主键之一；发送方是这个期间的另一个人 |
| `recipient_id` | uuid，引用 `users` | 主键之一 |
| `pokes`、`pets` | integer，≥ 0 | 还没看到的戳与摸次数 |
| `last_at` | timestamptz | 最近一次送达的时间，由服务端时钟写入 |
| `poke_sent_at`、`pet_sent_at` | timestamptz，可空 | 发送方每种动作最近一次计数的时间，只用于限频（D4） |

发送是一条带条件的 upsert：当前绑定期间存在、且距同种动作上次计数已满 1 秒，才把对应列加一。看过时按显示过的次数相减，两列都为 0 就删除这一行（D4）。不记每次戳的时间，不记谁在什么时候看过。旧绑定期间的行在重新绑定后也不会被读到（新期间是新的 `period_id`，spaces-and-invitations D2）；它们最多每人每期一行，不另清理。

这不是双人空间记录：没有动作历史、不进 Google 可读副本、不计入未读、不在顶栏亮圆点，也不出现在解绑后的只读归档里。数据库备份会带上这张表，恢复后最多重放一些还没看到的戳。

原因：依据 2、3、4、5。只存累计就足以显示「戳了你 3 下」；逐条日志会变成一份谁在什么时候想到谁的行为记录，却没有任何地方要读它。

### D4：三个接口，绑定检查与读写在同一条语句里

| 接口 | 请求 | 响应 | 说明 |
| --- | --- | --- | --- |
| `GET /api/pokes` | — | `PokesResponse` | 调用者当前绑定期间里还没看到的戳与摸；没有、或没有当前绑定时 `received` 为 `null` |
| `POST /api/pokes` | `{ kind: 'poke' \| 'pet' }` | `PokesResponse` | 给当前搭档计一次；响应仍是调用者自己的待看，不含对方的任何状态 |
| `POST /api/pokes/seen` | `{ pokes, pets }` | `PokesResponse` | 调用者已经显示过的次数；服务端从自己那行减去，减到 0 删除 |

```ts
PokesResponse = { received: { pokes: number; pets: number; lastAt: string } | null };
```

- 三个接口都要求登录，`cache-control: no-store`。发送方与接收方都由会话和 `active_bindings` 确定，请求里没有对方的 ID。
- 没有当前绑定时 `POST /api/pokes` 返回 `NOT_FOUND`，与「没有可以戳的人」一致；`GET` 不报错，返回 `null`。
- 限频内的多余发送照常返回 200，只是不计数：发送方不能借响应推断任何东西。
- `seen` 按次数相减而不是整行删除：显示和确认之间新到的戳留在行里，下一次询问再显示。

原因：依据 2、3、5。按次数确认让每次戳在接收方那边恰好显示一次。

### D5：主页打开时每 10 秒询问一次，不推送

主页显示且标签页可见时，每 10 秒请求一次 `GET /api/pokes`，回到标签页时立即请求一次；离开主页就停。有待看的戳摸时：接收方自己的团子笑着跳两下，发送方窗口上冒出「戳了你 3 下，摸了摸你」这样的气泡，窗下一行写「TA 在 17:02 …」，本次停留期间收到的会累加在这一行里；随后发送 `seen`。

现有的实时连接只为日记编辑打开，主页不连接；为一个每 10 秒的轻量查询新建订阅通道不划算。没有打开主页的人在下次打开时看到。

原因：依据 1、6。10 秒的延迟对「我刚戳了你」足够；不打开应用也能知道属于通知，见路线图的「等通知」。

### D6：对方的团子只在对方作息的睡觉时段里睡

右窗团子睡着的条件，和两地时间显示「大概在睡」完全相同：绑定中、对方的时区已知、对方设了作息、当前时刻落在对方的睡觉时段里（`two-clocks` 的 `asleepAt`）。任一条件不满足就醒着。睡着时闭眼、张小嘴，旁边飘「z z Z」。自己的团子不睡：打开主页的人当然醒着。

不使用在线状态、最近活跃时间、页面是否打开或任何连接信息，本功能也不新增这类接口。

原因：依据 2。作息是对方自己设的、已经给搭档看的信息；在线状态是 authentication-and-sessions 不变量 9 明确不给的信息，而且「开着网页」本身并不说明人醒着。

### D7：模块边界

| 位置 | 职责 | 可引用 |
| --- | --- | --- |
| `apps/web/src/avatar` | `Mascot` 拆成影子、身子、手三层，增加 `idle`、`poked`、`happy`、`asleep` 四种表情；只负责画，不知道手势 | 不变（无） |
| `apps/web/src/windows` | 团子上的可聚焦按钮、轻点与拖动的区分、倾斜、气泡、爱心、减少动态效果；只发出 `onPoke`、`onPet`，不调用接口 | 不变（`avatar`） |
| `apps/web/src/pokes`（新） | 询问、发送与确认的查询；连戳计数；把收到的次数写成中文；只在绑定中启用 | `api`、`windows`（只用类型） |
| `apps/web/src/pages/HomePage.tsx` | 组装：自己的窗只播放，对方的窗发送，按 `asleepAt` 决定睡着 | 增加 `pokes` |
| `packages/contracts/src/pokes.ts` | `PokeKind`、`SendPokeRequest`、`SeenPokesRequest`、`PokesResponse` 与三条路由 | — |
| `apps/api/src/pokes/`、`store/pokes.ts`、`routes/pokes.ts` | 服务、带绑定条件的读写、路由 | 与 `clocks` 相同 |

`checks/verify-dependency-direction.ts` 随实现 PR 同步。

原因：依据 4、6。动画和手势留在 `windows`，网络留在 `pokes`，两者都不需要知道对方。

## 失败与恢复

| 情况 | 结果 |
| --- | --- |
| 发送请求失败或离线 | 本机动画照常播放，这一次不重试、不排队；不提示错误（这不是要保证送达的内容） |
| 询问失败 | 下一个 10 秒再问；待看的行留在服务端 |
| `seen` 失败 | 行未减少，下次询问会再显示一次；本次停留期间前端不重复播放同一批 |
| 发送时恰好解绑 | 条件 upsert 找不到当前期间，返回 `NOT_FOUND`，前端不提示 |
| 服务器从备份恢复 | 最多出现恢复点之后已看过的戳再显示一次 |

## 不变量

1. 戳或摸自己的团子不发出任何请求。
2. 只有当前绑定中的两人能互相发送和看到；从未绑定、已解绑和第三人都不能，旧绑定期间的待看在重新绑定后不出现。
3. 发送方得到的任何响应都不含对方是否看过、何时看过、是否在线的信息。
4. 每次计数的戳与摸在接收方主页上恰好显示一次：确认前不丢，确认后不再出现。
5. 对方团子是否睡着只由对方的时区与作息推出，和「大概在睡」一致；本功能不让任何接口返回在线或活跃时间。
6. 同一发送方的同一种动作每秒最多计一次。
7. 系统要求减少动态效果时没有动画，表情与气泡照常。
8. 服务端不保存戳与摸的历史：确认后删除，不进 Google 可读副本，不计入未读与入口圆点。

## 备选方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| 按在线状态让团子睡或醒 | 更「实时」，一眼知道对方在不在 | 等于在线回执，违反 authentication-and-sessions 不变量 9 和规格 §8.1；开着网页也不说明人醒着（依据 2） |
| 每次戳摸记一行，保留历史 | 可以回看、统计「这个月戳了多少次」 | 变成行为记录，没有任何界面要读它（依据 4） |
| 走 space-records 的动作模型 | 现成的未读、圆点和动作历史 | 动作历史不改不删、解绑后只读归档，与瞬时表达相反；还会在顶栏亮圆点（依据 3、4） |
| 用 WebSocket 实时推送 | 对方立刻看到 | 主页没有连接，需要新的订阅通道与鉴权；10 秒询问已满足依据 1（依据 6） |
| 等阶段 4 的邮件通知再做（路线图「想你了」） | 对方不开应用也能知道 | Ray 2026-11-03 希望先在主页上有互动；本功能不替代通知那一项，那一项保持原状（依据 1） |
| 继续存在 API 内存里（spike） | 不需要迁移 | 重启即丢，多个进程之间不一致，违背「保存」来自 PG 提交（依据 5） |
| 戳自己的团子也发给对方 | 多一种表达 | 对方看到「戳了自己」没有意义，徒增请求（依据 4） |

## 风险与代价

- 主页打开时每人每 10 秒一次很小的查询；两个人的规模下可以忽略，不需要索引以外的优化。
- 新增一张表和一次迁移；按 AGENTS.md，表结构变更须 Ray 同意（见落地顺序 1）。
- 触屏上的拖动只在桌面浏览器的触摸模拟里看过；真机验证随阶段 4 的手机支持。
- 旧绑定期间可能各留一行没看过的累计，不清理。

## 未解决的问题

- 台词、气泡位置、爱心大小与颜色：默认沿用 spike，实现 PR 里按 Ray 的验收调整。
- 收到时是否在「此刻」入口亮圆点：默认不亮（D3），只在主页上表现。

## 验收标准

- 不变量 1：组件测试戳和摸自己的团子后没有任何请求。
- 不变量 2、3、6：`*.db.test.ts` 通过 `app.inject()` 验证未绑定、解绑、第三人与重新绑定的结果，限频内的重复发送不计数，发送的响应与对方是否看过无关。
- 不变量 4：`*.db.test.ts` 验证显示与确认之间新到的戳在下次询问时仍在；浏览器测试中两个账号互戳，接收方看到一次，刷新后不再出现。
- 不变量 5：组件测试按作息与时区切换睡着与醒着，没设作息时醒着；检查 `PokesResponse` 与 `/api/clocks` 都不含活跃时间。
- 不变量 7：组件测试在减少动态效果下不加动画类名，气泡仍出现。
- 不变量 8：`*.db.test.ts` 验证确认后行被删除；Google 可读副本与未读接口不受影响。
