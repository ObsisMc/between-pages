# ADR-0005：以服务端权威操作验证 Yjs

日期：2026-10-24。状态：第一轮验证通过；生产协同内核与数据格式仍待决策。

## 背景

用户要求优先使用持续维护的开源库，验证 Yjs 的作者权限和断线不丢字。既有自研原型是行为基线，不作为生产算法默认选择。前端状态管理方向已确认为 TanStack Query + 按需使用 Zustand，二者不承担协同正文的多份可写状态。

## 本轮决定

沿用 ADR-0002 的路径 A，以 Yjs 公共共享类型替代实验插入树：服务端校验语义操作后生成 Yjs 更新，客户端维护已提交副本与本地未确认意图。服务端拒绝客户端指定 actor、authorId、clientID、原始 update 及其他未定义字段。

数据库保存完整权威记录，包括对应二进制更新的 base64 编码；先提交，再 ACK/广播。重复 operationId 必须来自相同 actor 且载荷一致，返回原记录及原 Yjs 更新。不会在重试时生成新的插入或新的备份任务。

字符使用不可变应用 ID、来源 actor 和插入操作 ID。来源由服务端写入。删除目标只能是自己的字符；个人撤销/重做只能切换自己的编辑操作。逻辑墓碑保留锚点，使撤销自己的原句不会把对方插入的文字一起删除。

## 替代方案

- 任意 Yjs 更新直接 apply：通用 CRDT 没有本产品作者权限；对照攻击测试可删除他人字符，拒绝作为默认写入通道。
- 接收客户端二进制更新并完整检查其所有影响：仍可研究，但来源伪造、隐藏结构和被拒绝更新的依赖链需要单独证明，本轮未完成。
- 标准 y-prosemirror/Hocuspocus provider：不能从通用认证推断字符权限和提交确认，未直接采用。
- 自研插入树：保留为回归对照，暂不确定长期维护。

## 后果和限制

Yjs 负责文档序列与共享类型、增量编码和副本合并；来源校验、提交顺序、个人撤销语义与离线意图重放仍是本项目代码。**这不是零自定义代码的现成协同方案，也不是已验证的多主离线二进制互传。**

原型通过同一浏览器行为测试，只能说明该适配路线有实际证据。尚未选择生产 schema：逐字符对象、操作元数据和完整日志重建可能带来明显开销，须测大文档、历史长度、快照/墓碑压缩、旧客户端升级和移动端存储路径，再决定是否采用。

验收证据见 [Yjs 验证报告](../validation/yjs-collaboration-2026-10-24.md)，运行方式见 [原型说明](../../prototypes/yjs/README.md)。不替代既有日期、作者身份、PG 持久确认及 Google 备份 ADR。
