# 所有书页共用主页复现的 SVG 书本、纸纹、衬线字与小角色

- 状态：已采纳
- 日期：2026-11-02
- 决策者：Ray
- 范围：技术栈
- 关联：取代 home-decorative-assets；依赖 opening-book-home；依赖 book-frontend-workspace

主页复现（home-decorative-assets）的视觉系统推广到所有书页：`src/book` 提供唯一的书本表面（内联 SVG 封面、层叠页边、书脊折痕、投影和 128px 缓存纸纹块），`<BookSpread>` 的所有使用者共用它，原 `book.css` 的纯色纸面与主页专用的 `HomeBookSurface` 都去掉。日记工作区、目录、两地时间、心愿与礼物、纪念日、双人空间、备份、登录、邀请和旧日记链接都放进这本书：宽窗口是一张窗口高的展开双页，每页在书页内各自滚动；窄窗口是一张带纸纹的单页，随窗口滚动。字体用随项目提供的 Noto Serif SC，作者头像用圆润的小角色。文字与控件仍全部是真实 HTML。水彩窗台只留在主页、登录和邀请的左页，日记工作区仍不放窗户、砖墙和藤蔓（book-frontend-workspace D1）。本 ADR 不改变任何页面的数据、权限或交互规则；目录的呈现见 [contents-spread](./2026-11-02-contents-spread.md)。

## 背景与问题

书页前端（#51–#60）用 CSS 画纸：纯色纸面、一条硬边和中缝的窄阴影。Ray 认为观感不够，在 2026-11-02 接受了 Codex 在独立分支复现的主页（SVG 书本、纸纹、水彩插画、衬线字），并决定所有书页都用同一套外观，目录也改为整本书的一页。主页复现的 ADR 把样式限定在 `.home`（其 D2），代码也在 `pages/HomeBookSurface.tsx` 与 `home.css`，别的页面无法复用。主页书本按固定宽高比（1536∶1024）随宽度缩放，而日记工作区的两页需要固定在窗口高度内各自滚动；其余功能页现在是一栏 28rem 的普通页面，没有书。

复现中实测 WebKit 在两倍像素密度下点击后的帧约 0.6–1.5 秒。Ray 决定性能以后再看，本轮不为速度删减纹理或细节。

## 决策依据

1. 所有书页的纸张、书脊、页边、字体和小角色要与已认可的主页复现一致（Ray 2026-11-02）。
2. 装饰只有一个所有者：书本几何、纸纹与素材只在 `src/book` 和 `public/book/` 定义一次，页面只提供内容。
3. 文字、输入、焦点、滚动和点击区域必须是真实 HTML，不能被装饰盖住或跨过中缝（book-frontend-workspace D1、home-decorative-assets 不变量 2）。
4. 日记工作区的两页各自滚动、列表位置与已读判定不能因换外观而改变（book-frontend-workspace D3–D6）。
5. 窄窗口不横向溢出，书签留在屏内（opening-book-home D4、book-frontend-workspace 不变量 6）。
6. 本轮不以性能为由删减外观，但也不靠重试、等待或加大超时掩盖慢帧；不新增 npm 依赖。

## 决策

### D1：`src/book` 拥有唯一的书本表面，`BookSpread` 总是画在它上面

`src/book/BookSurface.tsx` 是主页 `HomeBookSurface` 的搬迁：同一组 SVG 路径（封面、四层页边、左右页、纸纹层、书脊明暗线、底部投影），`preserveAspectRatio="none"`，描边加 `vector-effect="non-scaling-stroke"`，所以书被拉成别的宽高比时线宽不变。纸纹仍是 `<pattern>` 引用的 128px SVG 块，噪声滤镜只在这一小块上运行一次，整本书没有滤镜或模糊。

`<BookSpread left right fit? className?>` 自己渲染表面，调用方不再各自引入：

| `fit` | 书的大小 | 使用者 |
| --- | --- | --- |
| `aspect`（主页） | 宽度取窗口与 96rem 的较小值，高度按 1536∶1024 随宽度；内容用容器单位排版 | 主页 |
| `window`（默认） | 高度为窗口高度减上下各 1rem，宽度取窗口、96rem 与「高度 × 1.75」的较小值并居中；两页各自在页内滚动 | 其余所有书页 |

宽高比上限 1.75 防止宽而矮的窗口把书压扁；高而窄的桌面窗口则书变高，页边路径随之拉长。页内滚动区域的底部不做渐隐：渐隐下仍在可见区域内的对方文字会被算作已读（book-frontend-workspace D5），而看不清的字不该算。书本表面不随页面状态变化，只绘制一次（组件不接收参数，页面更新时不重绘）。

窄窗口（≤56rem，沿用现有断点）不画双页：表面换成铺满的纸色与同一纸纹块，书页随窗口纵向滚动，左页内容在前、右页在后。

书本表面只在浅色纸面下绘制；书页不跟随系统深色主题（home-decorative-assets 已对主页如此）。`styles.css` 的深色变量保留给不在书里的界面（目前没有），`book.css` 的深色变量删除。原因：依据 1、2、3、4、5。

### D2：共享素材在 `public/book/`，主页专属插画留在 `public/home/`

| 文件 | 位置 | 用途 |
| --- | --- | --- |
| `paper-grain.svg` | `public/book/` | 纸纹块（从 `public/home/` 移来） |
| `mascots.svg` | `public/book/` | 一对小角色（品牌、目录分组标题）；单个角色的头像是 `<Avatar>` 里的内联 SVG |
| `leaf.svg` | `public/book/` | 书签上的叶子 |
| 字体文件 | `public/book/fonts/` | 见 D3 |
| `windows-watercolor.webp`、`windows-unbound.webp` | `public/home/` | 主页、登录与邀请左页的水彩窗台，由 `src/book` 的 `<BookOpening>` 引用 |

`public/book/README.md` 记录每个文件的来源与许可，`public/home/README.md` 只保留插画与生成提示词。素材都由本站提供，运行时不访问图片或字体服务。原因：依据 2。

### D3：衬线字体随项目提供完整的 Noto Serif SC，按 Unicode 区段切片

所有书页的标题、标签和正文（包括日记正文）都用 Noto Serif SC。字体以 Google Fonts 发布的同一套切片随项目提供：约 100 个 woff2 文件、每个带 `unicode-range`、字重 400–700 可变，合计约 5.7 MiB，放在 `public/book/fonts/`，`@font-face` 写在 `book.css`。浏览器只下载页面实际用到的字所在的切片。字体缺失或未加载完时回退到 `'Songti SC', 'Source Han Serif SC', serif`，`font-display: swap`。

主页现在的 20 KB 固定文案子集删除：它只覆盖写死的字，任何新文案或用户名都会在同一个词里混出两种字体。原因：依据 1、2。

### D4：作者头像是小角色，名字始终以文字同时出现

`<Avatar>` 把首字圆圈换成单个小角色轮廓：作者槽 1 暖橙、槽 2 雾蓝，没有槽时用纸面上的淡墨色；有日记但没写字时只画描边（原「空心」）。角色内不再写首字；`aria-label` 仍是显示名，日期页与列表中名字以可见文字写在角色旁边（book-frontend-workspace D1 已定小角色作头像、颜色与角色不能单独说明身份）。大小在同一处固定，所有使用处一致。`avatar` 仍不引用其他模块：轮廓是组件内的一段内联 SVG 路径，颜色取作者变量。原因：依据 1、3。

### D5：每个功能页按内容分到左右两页

功能页从一栏 28rem 改成 D1 的书。各页把已有的段落分到两页，不增删数据或操作：

| 页面 | 左页 | 右页 |
| --- | --- | --- |
| 日记工作区 `/days`、`/days/:date` | 不变（book-frontend-workspace D3） | 不变 |
| 两地时间 `/clocks` | 标题、两个时钟、今天共同醒着的时间 | 作息 |
| 心愿与礼物 `/wishes` | 删除通知、TA 的心愿 | 我的心愿、我在准备、礼物墙 |
| 纪念日 `/anniversaries` | 标题、只读说明、通知、纪念日列表 | 新纪念日表单；只读时空白 |
| 一个纪念日 `/anniversaries/:id` | 名称、日期与说明 | 历年的这一天 |
| 双人空间 `/spaces/:id` | 标题、对方、绑定记录 | 我的共享范围、解绑 |
| 备份 `/backup` | 标题、服务器备份说明、Google Drive 连接 | 备份进度、备份记录 |
| 登录 `/login`、邀请 `/join` | 主页左页的开篇（品牌、短句、水彩窗台，无日期） | 登录方式；邀请预览与接受 |
| 旧链接 `/diaries/*` | 这篇日记与它的历史，在页内滚动 | 「在所有日记中打开这一天」 |

每页左上角保留「← 序言」（工作区窄页的「← 所有日记」不变）。「有 N 处新内容 · 跳到第一处」跳转在记录所在的那一页内滚动。窄窗口按表中先左后右的顺序排成一页。见面计划等以后的页面同样按这张表的规则加入。原因：依据 1、3、4。

### D6：书签是同一个丝带书签

主页复现的丝带书签（渐变、叶子、横排两字）成为全站书签：宽窗口贴在右页外缘、与书的顶部对齐；窄窗口在书页内右上角，页首内容为它让出位置。位置随 D1 的书计算，固定在窗口内。行为见 contents-spread。原因：依据 1、5。

## 不变量

1. 登录后每个书页的内容都在共享书本表面之上，页面不另画书本或纸面。
2. 所有业务文字、时间、日记正文和控件都是真实 HTML；装饰图像不可聚焦、不是链接、对辅助技术隐藏。
3. 宽窗口的每一页内容都在本页的滚动区内，不越过中缝或书底；窄窗口在 1280、375 与 320 像素宽下没有横向滚动，书签完整位于窗口内。
4. 头像不单独表达身份：每个头像的可读名称是显示名，并在旁边以文字出现。
5. 日记工作区换外观后，左右两页仍各自滚动，右页的阅读与已读判定只计实际在本页可见区域内的文字。

## 备选方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| **书随内容变高，窗口滚动** | 和普通网页一样滚动，功能页不用拆成两栏 | SVG 页边拉得很长后变形明显，和主页不像（依据 1）；工作区本来就要求两页各自滚动（依据 4） |
| **每个页面复制一份主页 SVG** | 每页可单独微调 | 同一几何有多个所有者，改一处漏一处（依据 2） |
| **只扩充现有字体子集** | 只多几十 KB | 用户写的字和新文案不在子集里，同一行混两种字体；每次改文案都要重做子集 |
| **只靠系统衬线字体** | 不增加仓库体积 | Windows、Android 和 Linux 常没有中文衬线字，退回黑体，与参考差别最大（依据 1） |
| **功能页保持一栏，只换纸面** | 改动小 | 一栏页面在宽窗口上不是书，和主页、目录不成一本（依据 1） |

## 风险与代价

- WebKit 在两倍像素密度下的慢帧（约 0.6–1.5 秒）会出现在每一页，而不只主页；本轮记录实测，不优化（依据 6）。浏览器测试若因此超时，报告时间，不加重试或超时。
- 字体约 5.7 MiB 进入仓库；首次打开一页中文约下载几百 KB 切片。
- 功能页拆成两页后，一页很长而另一页很短时会有留白；内容区按页滚动，不会被截断。
- 书页固定为浅色，系统深色主题下也是浅色纸面。

## 未解决的问题

- 心愿的商品图、日历与礼物墙等探索稿里的版式：本轮只把现有段落放进左右页，不按探索稿重排单条记录；各功能以后单独做。
- 性能优化（合成层、更少的层叠页边、预解码插画）：Ray 于 2026-11-02 决定以后再做；默认不做。到时先看 WebKit 下 `anniversaries.spec.ts`：基线 23.6 秒，本次 29.2–30.1 秒，卡在 30 秒预算上（[验证记录](../validation/book-pages-reproduction-2026-11-02.md)）。
- 各页的纸面、字体、头像与比例的视觉验收：待 Ray 对照截图确认；确认前保持已采纳。

## 落地顺序

1. 把 `HomeBookSurface` 搬进 `src/book/BookSurface.tsx`，`BookSpread` 加 `fit`，素材移到 `public/book/`，字体切片入库；主页改用它，外观与复现一致。
2. 日记工作区与目录（contents-spread）放进 `window` 书；头像换成小角色。
3. 功能页按 D5 分到左右页；登录与邀请加开篇左页。
4. 更新组件与浏览器测试（几何检查覆盖新页面），截图，更新 `apps/web/README.md`、路线图、README 状态行与验证记录；同一 PR 带上 Codex 的主页复现提交。

## 验收标准

- 不变量 1、3 由 `e2e/book.spec.ts` 在 Chromium 与 WebKit 下对主页、`/days`、`/days/:date`、目录和每个功能页做 1280×800、375 与 320 宽的几何检查验证。
- 不变量 2 由浏览器中的文字、焦点与链接检查验证；装饰图像在组件测试里不可聚焦、`aria-hidden`。
- 不变量 4 由 `avatar` 与日期页组件测试验证。
- 不变量 5 由既有 `day-feed`、`DaysWorkspace` 与 `reading.spec.ts` 测试在新外观下继续通过验证。
- 纸面、字体、头像与各页比例由 Ray 对照截图确认；WebKit 帧时间写入验证记录。
