# 应用可以装到桌面和 iPhone 主屏幕，离线也能打开并说明离线，图标上的圆点提示未读，不做推送

- 状态：提议
- 日期：2026-11-18
- 决策者：Ray
- 范围：技术栈
- 关联：依赖 ADR-0003；依赖 diary-collaboration-kernel；依赖 production-deployment；依赖 unread-and-day-page；依赖 space-records；依赖 book-frontend-workspace；依赖 email-reminders

网页应用成为完整的 PWA，可以装到桌面 Chrome、Edge，macOS Safari 的程序坞，以及 iPhone 的主屏幕上：

- **安装与更新：** 由 `vite-plugin-pwa` 生成 service worker，只预缓存构建出的页面文件，从不缓存 `/api/` 的响应。新版本发布后显示"有新版本 · 刷新"，用户点了或者应用的窗口全关掉以后才换到新版，从不自动刷新。
- **离线：** 离线时打开应用，看到书页外壳和"现在离线，联网后会自动打开"，而不是浏览器的错误页或"服务暂不可用"。用着用着断网时，每一页都有同一条提示："现在离线。写下的字先存在这台设备上，联网后自动发出。"它不说"已保存"。"已保存到服务器"仍然只出现在每篇日记自己的保存状态行，并且只来自服务器的确认。
- **未读：** 站点导航上有任何"有新内容"，或者有对方的日记没读时，已安装的图标上亮一个不带数字的圆点，全部读完就清掉。iPhone 上圆点需要通知权限：第一次打开主屏幕应用时，一张卡片请用户点一下「好的」，弹出 iOS 自己的权限窗；之后的开关都在 iPhone 的系统设置里，应用里没有开关。应用从不发通知。
- **手机：** iPhone 由真机清单验收，清单里发现的布局和输入问题另开 PR 修。

不新建任何存放日记正文或其他私人内容的地方，也不改服务器、Caddy 和接口。

本文不负责：

- 推送通知（Web Push）与应用关着时更新圆点；应用关着时的提醒仍靠邮件（email-reminders）。
- 离线阅读本机日志里的日记、离线的日期索引（规格第 4 节；2026-10-28 推后，Ray 于 2026-11-18 决定继续推后）。
- 应用关着时在后台补发（Background Sync）。
- Android、iPad 的验收，以及手机界面的重新设计（需要时另写 ADR）。
- 退出登录时锁住本机日志（kernel D7 的遗留，见 `apps/web/README.md`）。

## 背景与问题

Ray 于 2026-11-17 提出：应用要能安装，离线也能打开并清楚提示离线，能看到未读，暂时不做推送；排在邮件提醒之后。2026-11-18 讨论时他补充"PWA 我就是想给手机用"。他和搭档用的都是 iPhone。

现状：

- **安装：** `apps/web/public/manifest.webmanifest`（`standalone`，纸色 `theme_color`）与各尺寸图标已经存在（#86），桌面 Chrome、Edge 现在就能安装。
- **没有 service worker：** 离线时页面文件都加载不了，打开应用只看到浏览器的错误页。
- **启动要先问服务器：** 页面加载后先请求 `GET /api/me`（`RequireAuth`）。这个请求没有回答时，整个应用只显示"服务暂不可用，请稍后再试"。所以只加 service worker 的话，离线打开看到的是这一页。
- **用着用着断网：** 已经打开的日记照常写，本机日志先存，联网后由 sender 自动补发（kernel D7、D13），保存状态行显示"暂时无法同步，已保存在本机"。其他页面各自报错，例如日记页换日期时显示"离线时无法读取这一天"，日期索引显示"无法读取"。没有统一的离线提示。
- **本机日志：** IndexedDB 里存有这台设备打开过的日记正文、待发内容与恢复草稿，没有加密，退出登录时也还没上锁。日记页按日期向服务器查日记，所以离线时本机日志里有正文也打不开。要离线阅读，日志得记下每篇日记的日期与作者，冷启动时还得记住上次登录的是谁。
- **未读：** 站点导航上「一起」里各功能的圆点来自 `GET /api/space/unread`，每 45 秒读一次（space-records D8）。日记的未读来自 `GET /api/days` 的列表未读，不带参数的 `GET /api/days/next-unread` 返回最新一个有未读的日期，没有时返回 `null`（book-frontend-workspace D5）。已安装的图标上什么也不显示。应用关着时由邮件提醒（email-reminders）。
- **协议升级：** 服务器回 `PROTOCOL_UNSUPPORTED` 时，保存状态行显示"有新版本，请刷新页面；未保存的内容会保留"，不强制刷新（kernel D10）。
- **缓存规则：** 生产环境的 web 容器（`ops/deploy/web.Caddyfile`）给 `/assets/*` 一年 `immutable` 缓存，不存在的文件返回 404。其余文件（`index.html`、`/fonts/`、图标、manifest）都是 `no-cache`，每次向服务器确认。Cloudflare 按这些响应头缓存（production-deployment D3）。
- **字体：** Noto Serif SC 按 Unicode 范围切成约一百个 `woff2`，共约 6 MB，放在 `/fonts/`，文件名不带内容哈希。浏览器只下载页面用到的切片（digital-paper-interface D4）。
- **手机：** 2026-10-24 起手机工作后置（ADR-0006 的范围前提，路线图"已确认的范围"）。窄屏布局在 56rem 以下已经存在，但从没在真机上验过，手机输入法里的连删（EDIT-05）也没验过。
- **iPhone 的限制：** 主屏幕应用要从 Safari 的分享菜单"添加到主屏幕"（iOS 16.4 起支持本文用到的全部接口）。它有自己的 cookie 与存储，所以要在应用里再登录一次，本机日志也与 Safari 里的不互通。它不受 Safari 对脚本存储"7 天不用就清掉"的限制。图标角标（Badging API）要先允许通知才显示，而请求通知权限必须由用户的一次点按触发。

需要回答的问题：

- service worker 用库还是手写？版本更新怎么生效？和 Caddy、Cloudflare 的缓存规则怎么配合？
- 离线能做到什么？要不要离线阅读？会不会把日记正文写进新的缓存？
- 离线提示对"保存"怎么说？
- 图标上要不要显示未读？显示什么？
- 手机做不做？做到什么程度？

## 决策依据

1. 能装到 Ray 与搭档的 iPhone 主屏幕和桌面上，像应用一样打开（Ray 2026-11-17、2026-11-18）。
2. 离线也能打开，并且清楚说明离线，不出现浏览器错误页或"服务暂不可用"（Ray 2026-11-17）。
3. "已保存"只能来自服务器在 PG 提交后的确认（ADR-0003、ADR-0006）；离线提示不能让人以为已经保存。
4. 不新开存放日记正文或其他私人内容的地方；没有专门的决定，不把明文日记写进新的缓存。
5. 写字时不被版本更新打断；没发出的输入不丢（kernel 不变量 9、10、31：协议升级提示刷新，不强制刷新）。
6. 图标上的未读与应用内的圆点一致：只来自服务器，不透露多少条，不透露对方没共享的日记或未揭晓的礼物（SHARE-11）。
7. 不做推送（Ray 2026-11-17）。
8. 用流行、维护活跃的库，不手写缓存与版本管理（Ray 2026-11-17 的依赖原则）。
9. 一个职责只有一个归属；没有消费者的东西不预建（AGENTS.md）。
10. 不改服务器、Caddy 与 Cloudflare 的现有配置（production-deployment：更新是一条人工命令，站点 Caddy 在仓库之外）。

## 决策

### D1：用 vite-plugin-pwa 生成 service worker，只缓存页面文件

**依赖（精确版本）：** `apps/web` 的 devDependency 加 `vite-plugin-pwa` 2.0.0（MIT，每周约 740 万次下载，2026-10-03 发布，peer 支持 Vite 8）；dependency 加 `workbox-window` 7.4.1（注册与更新握手在浏览器里用它）。`workbox-build` 7.4.1 随插件进来，只在构建时运行。

**配置（`vite.config.ts`）：**

| 项 | 值 | 原因 |
| --- | --- | --- |
| 方式 | `generateSW`，`registerType: 'prompt'`，`injectRegister: false` | 由 Workbox 生成整个 worker；注册与更新提示由应用自己做（D2） |
| manifest | `manifest: false` | 继续用 `public/manifest.webmanifest`，只有一份 |
| 预缓存 | `index.html`、`assets/**/*.{js,css}`、`favicon.svg`、`favicon.ico`、`apple-touch-icon.png`、`icon-*.png`、`manifest.webmanifest` | 离线打开应用需要的全部文件。`/assets/` 带内容哈希，`index.html` 由 Workbox 按内容算版本 |
| 导航回退 | `navigateFallback: '/index.html'`，`navigateFallbackDenylist: [/^\/api\//]` | 任何页面地址离线都能打开；`/api/` 永远直接走网络 |
| 字体 | `/fonts/*.woff2` 用 `StaleWhileRevalidate`，缓存名 `fonts`，最多 200 个 | 6 MB 字体全部预缓存太重（尤其在手机上）。用过的切片离线可用，没用过的回退到系统字体 |
| 其他请求 | 不加任何 runtime caching | 尤其不缓存 `/api/` 的任何响应（依据 4） |
| 旧缓存 | `cleanupOutdatedCaches: true` | 新版生效后删掉旧版的预缓存 |
| 开发 | `devOptions.enabled: false` | 开发服务器不注册 worker，现有 e2e 和 Vite 热更新不受影响 |

**和缓存规则的配合（不改 Caddy、Cloudflare）：**

- `sw.js` 与 `workbox-*.js` 在站点根目录，落在 `no-cache` 规则下。浏览器检查 worker 更新时本来就绕过 HTTP 缓存（`updateViaCache` 默认值），每次导航或调用 `registration.update()` 都会拿到最新的 `sw.js`。
- `/assets/` 的一年 `immutable` 不变。预缓存按文件名里的哈希判断版本，不重复下载没变的文件。
- 旧页面请求已不存在的 `/assets/` 文件仍然是 404。worker 生效前，旧版的文件都在旧的预缓存里，所以打开着的旧页面不会缺文件（D2）。现在的路由没有按需加载的分块，以后加了也一样。
- WebSocket（`/api/sync`）不经过 service worker。

原因：依据 4、8、10。Workbox 解决了预缓存清单、版本比对、旧缓存清理与导航回退这些容易写错的部分。只缓存页面文件，所以 Cache Storage 里不会出现任何私人内容。

### D2：新版本提示刷新，从不自动切换

- 发现新的 worker 在等待时，所有已登录页面的顶部（`SiteLayout`）与未登录页面显示一条不挡内容的提示："有新版本 · 刷新"。点"刷新"后，新 worker 接管（`skipWaiting`），这个窗口重新加载。其他打开着的窗口看到同一条提示，不自动重新加载。
- 不点的话，等应用的所有窗口都关掉以后，下次打开就是新版。iPhone 上从多任务里划掉主屏幕应用也算关掉。
- 应用长时间开着时（iPhone 上的主屏幕应用可能几天不关）：页面回到前台时，以及前台每小时一次，调用 `registration.update()`。
- **协议过旧：** 某篇日记的保存状态变成 `upgrade` 时，立即调用 `registration.update()`。新 worker 等待后出现"有新版本 · 刷新"，点它就加载服务器上的新版。保存状态行的文字改为"有新版本，请点顶部的「刷新」；未保存的内容会保留"。只用浏览器自己的刷新的话，旧 worker 会先拿缓存里的旧页面回答，新版要再等一轮，所以文字要指向这条提示。
- 重新加载不丢东西：没发出的输入和恢复草稿都在本机日志里，加载后照常补发或显示（kernel 不变量 9、10、20）。

原因：依据 5。自动切换会在写字时换掉页面底下的代码，旧页面也拿不回已删除的旧文件。日记内核对协议升级的规则本来就是提示刷新、不强制刷新。

### D3：离线打开应用时，显示外壳和离线说明

- 离线时打开应用（或者刷新）：worker 提供页面文件，应用照常启动，`GET /api/me` 得不到回答。`RequireAuth` 区分两种失败：

  | 情况 | 显示 |
  | --- | --- |
  | 请求没有任何 HTTP 回答（网络错误） | 书页外壳与"现在离线，联网后会自动打开" |
  | 有 HTTP 回答但是错误（例如 5xx、Cloudflare 的 52x） | 照旧"服务暂不可用，请稍后再试"与"重试" |
- 离线页不显示名字，也不显示任何日记或空间内容：此时服务器没有确认登录，本机日志也不按日期列出日记（本文不负责离线阅读）。
- 联网后（D4 判定恢复）自动重新请求 `GET /api/me`，不用点。
- 登录页离线时，"使用 Google 登录"不跳转，旁边说明"现在离线，联网后再登录"。

原因：依据 2、4。现在的"服务暂不可用"会让人以为服务器坏了。离线时最诚实的说法就是离线；显示更多内容，就得在服务器没确认登录时展示日记。

### D4：全站一条离线提示，以请求 API 没有回答为准

**判定（`src/api` 拥有，`callApi` 是唯一入口）：**

- `callApi` 的每次结果都更新一个"是否连得上 API"的状态：收到任何 HTTP 回答（包括错误）算在线；`fetch` 抛出网络错误算离线。
- `navigator.onLine === false` 与 `offline` 事件直接算离线（这个方向可靠）。`online` 事件不直接算在线：连着 Wi-Fi 但没网时它也是 true。它只触发一次立即探测。
- 离线期间每 10 秒，以及收到 `online` 事件时，用 `callApi('health')`（`GET /api/health`）探测一次，有回答就恢复在线。
- TanStack Query 的 `onlineManager` 跟随这个状态：离线时暂停请求，恢复后重新请求，不另写重试。
- 这个状态只用于显示。sender、sync-client 与本机日志不读它，各自照旧按自己的回答重连与补发（kernel D13）。它不参与"是否已保存""是否发送"的判断。

**提示：** 离线期间，所有已登录页面的站点导航下方显示同一条提示："现在离线。写下的字先存在这台设备上，联网后自动发出。"恢复在线后提示消失。

- 提示只说本机做了什么，不出现"已保存"。每篇日记的保存状态行照旧，是唯一说"已保存到服务器"的地方（SAVE-01）。
- 本机存不进去时（稀少），由保存状态行现有的"本机未落盘"提醒负责（kernel D7），全站提示不改口。
- 各页面自己的离线报错（"离线时无法读取这一天"等）保留，说明的是那一块内容读不到。

原因：依据 2、3、9。离线状态只有一个归属：所有 API 请求都经过 `callApi`，在那里判定最准。提示不说"已保存"，是因为离线时根本没有服务器确认。

### D5：已安装的图标上，有未读时亮一个不带数字的圆点

- **何时亮：** 站点导航给出的空间记录未读（`GET /api/space/unread` 的三项）任何一项大于 0，或者 `GET /api/days/next-unread`（不带参数）返回了日期，就调用 `navigator.setAppBadge()`（不带数字）；都没有时调用 `navigator.clearAppBadge()`。
- **数据：** 都是现有接口，数字都是服务器算的：对方没共享的日记、未揭晓的礼物本来就不在里面。不加接口，不在客户端另算未读。
- **何时更新：** 只在应用打开期间，跟随导航每 45 秒读一次。窗口在后台但没关时也读（`refetchIntervalInBackground`），只在浏览器支持 Badging API、并且（需要权限时）已经得到通知权限时这样做（D6）。退出登录时清除。离线时保持原样。
- **在哪里显示：** 浏览器支持 Badging API 时才调用，不支持时什么也不做。桌面 Chrome、Edge 的已安装应用不需要权限；Safari（macOS 程序坞与 iPhone 主屏幕）要先有通知权限（D6）。
- **限制：** 没有推送，应用关着时圆点停在最后一次的状态：对方之后写的不会让它亮，在别的设备上读完也不会让它灭。下次打开应用后 45 秒内纠正。

原因：依据 6、7、9。数字会把按天计的日记和按条计的记录加在一起，含义不清；圆点和导航上的"有新内容"说的是同一件事。

### D6：iPhone 上第一次打开主屏幕应用时，一张卡片请用户点一下，之后交给系统设置

- **需要通知权限的浏览器（Safari）：** 还没请求过权限（`Notification.permission === 'default'`）时，主页显示一张卡片："图标上的未读圆点需要通知权限，只用来显示圆点，不会发通知。"只有一个按钮「好的」，没有关闭按钮和"不用了"。
- 点「好的」调用 `Notification.requestPermission()`，弹出 iOS 自己的「允许 / 不允许」。选哪个都行，请求过以后卡片不再出现。

  | 系统窗里选 | 之后 |
  | --- | --- |
  | 允许 | 圆点开始工作 |
  | 不允许 | 没有圆点；以后要用，在 iPhone 的「设置 → 通知 → Between Pages」里打开 |
- **以后的开关都在系统设置里：** iPhone 上是「设置 → 通知 → Between Pages」（关掉"标记"就没有圆点）。应用里没有圆点开关，也没有为它新增设置页，不在本机保存任何圆点设置。
- **为什么卡片不能跳过：** iOS 只有在网页应用请求过一次通知权限之后，才把它列进「设置 → 通知」；只能在用户点按时请求。如果卡片能被跳过，设置里就永远没有这一项，用户以后想要也打不开。不点「好的」，下次打开应用时卡片还在。
- **不需要权限的浏览器（桌面 Chrome、Edge）：** 没有卡片，有未读就亮圆点。
- 应用从不调用 `new Notification()`、`showNotification()`，也不订阅推送。通知权限只用来让 Safari 显示圆点。

原因：依据 6、7、9。Ray 于 2026-11-18 确认：开关属于 iPhone 自己的通知设置，应用只负责让 iOS 弹出一次权限窗。应用里再做一个开关，会和系统设置重复，两者还可能不一致。

### D7：桌面与 iPhone 由真机清单验收，Android 与 iPad 不屏蔽也不宣称

| 平台 | 怎么安装 | 本文验收 |
| --- | --- | --- |
| 桌面 Chrome、Edge | 地址栏的安装按钮 | 是 |
| macOS Safari 17+ | 文件 → 添加到程序坞 | 是 |
| iPhone Safari（iOS 16.4+） | 分享 → 添加到主屏幕 | 是，真机 |
| Android Chrome、iPad | 浏览器自己的安装入口 | 否：不屏蔽，不宣称支持 |

**iPhone 上用户要知道的：** 主屏幕应用要单独登录一次。在 Safari 里写下但还没发出的字留在 Safari 那边的本机日志里，要回 Safari 打开那篇日记才会发出。这两点写进 `apps/web/README.md` 的已知限制与真机清单，应用里不另加说明页。页面不延伸到刘海与状态栏下方（不加 `viewport-fit=cover`），避免为安全区改布局。

**真机清单**（实现时写成 `docs/validation/` 下的记录）：iPhone 上依次检查——

1. 从 Safari 添加到主屏幕，图标与名字正确，以独立窗口打开；
2. 在主屏幕应用里用 Google 登录，登录后回到应用里而不是 Safari；
3. 写一段，看到"已保存到服务器"；
4. 开飞行模式继续写：出现离线提示，保存状态行说已保存在本机；关飞行模式后变成"已保存到服务器"，对方看到；
5. 飞行模式下从主屏幕冷启动：看到离线页；联网后自动打开；
6. 发布新版本后：出现"有新版本 · 刷新"，点后是新版，没发出的字还在；
7. 未读圆点：卡片出现、点「好的」弹出系统权限窗、允许后对方写字 45 秒内圆点亮、读完后消失、退出登录后清除；在「设置 → 通知 → Between Pages」里关掉"标记"后不再显示；
8. 手机输入法：中文输入、连删到作者边界（EDIT-05）、粘贴；
9. "下一处未读"在窄屏上的跳转。

桌面 Chrome 与 macOS Safari 检查第 1、3～7 项。清单里发现的布局、输入问题另开 PR 修，不在本文范围内重新设计手机界面。

原因：依据 1。Ray 要在手机上用，而手机的不确定性只能在真机上排除。只验 Ray 和搭档用的平台，其余平台不屏蔽也不宣称。

## 失败与恢复

| 情况 | 结果 | 恢复 |
| --- | --- | --- |
| 浏览器不支持或注册失败 | 在线时与现在一样，离线时打不开 | 无需操作 |
| 部署后旧窗口还开着 | 旧版继续运行，提示"有新版本 · 刷新" | 用户点刷新，或关掉所有窗口 |
| 旧版与服务器协议不兼容 | 保存状态 `upgrade`，未发的字留在本机日志 | 立即检查更新，点"刷新"进新版后补发 |
| 发布了有问题的 worker | 所有人停在坏版本，直到下一次更新 | 修复后重新部署：`sw.js` 是 `no-cache`，下次联网打开就能发现；最坏情况部署一版 `selfDestroying: true` 的构建，注销 worker 并清缓存 |
| 浏览器清掉了缓存 | 下次在线打开时重新预缓存 | 无需操作 |
| 连着网但到不了服务器（门户页、Cloudflare 出错） | 有 HTTP 回答：显示"服务暂不可用"或页面自己的错误；没有回答：显示离线 | 恢复后自动消失 |
| 应用关着时对方写了新内容 | 圆点不亮 | 邮件提醒；下次打开后 45 秒内亮 |
| 通知权限被拒 | 没有圆点 | 在 iPhone 的「设置 → 通知 → Between Pages」里打开 |

## 不变量

1. service worker 与 Cache Storage 里只有构建出的页面文件、图标、manifest 与字体文件；`/api/` 的请求都不经过缓存，任何 API 响应、日记正文与其他私人内容都不写进 Cache Storage。
2. 离线时打开应用，显示书页外壳与离线说明，不显示浏览器错误页或"服务暂不可用"。
3. 只有请求没有任何 HTTP 回答时才算离线；服务器返回错误时显示"服务暂不可用"。
4. 离线提示不出现"已保存"；"已保存到服务器"只来自服务器的确认，离线状态不参与是否已保存、是否发送的判断。
5. 新版本只在用户点"刷新"或应用的所有窗口关掉后生效，应用从不自己重新加载页面。
6. 保存状态为 `upgrade` 时，点一次"刷新"就进入服务器上的新版本，不会停在缓存里的旧版本。
7. 图标圆点只来自服务器给的未读（空间记录未读与日记列表未读），不带数字；没有未读与退出登录时清除。
8. 应用从不显示系统通知，也不订阅推送；只在用户点按后请求通知权限。
9. 开发服务器不注册 service worker。

## 备选方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| **手写 `sw.js`** | 不加依赖，每一行都清楚 | 要自己生成预缓存清单、比对版本、清理旧缓存、写更新握手，约 100～150 行容易出错的代码，违背依据 8 |
| **新版自动切换（`skipWaiting` + 重新加载）** | 所有人总是最新版 | 可能在写字时重新加载；会删掉打开着的旧页面还要用的文件，违背依据 5 |
| **缓存 API 响应（`GET /api/days` 等用 NetworkFirst）** | 不改本机日志就能离线看列表和日记 | 把明文日记与列表写进新的缓存，违背依据 4；与本机日志重复保存，违背依据 9；解绑或停止共享后，离线时还会显示旧的授权内容 |
| **离线阅读本机日志里的日记** | 满足规格第 4 节，离线也能读写打开过的日记 | 要改本机日志的结构（基线记日期与作者），还要在服务器没确认登录时显示正文，而本机日志退出时还没上锁；Ray 于 2026-11-18 决定继续推后 |
| **只看 `navigator.onLine`** | 一行代码 | 连着 Wi-Fi 但没网时仍是 true，提示不出现，违背依据 2 |
| **带数字的角标** | 一眼知道有多少 | 日记按天、记录按条，加在一起的数字含义不清，违背依据 6 |
| **不做角标** | 没有"应用关着时状态过期"的问题 | Ray 要在图标上看到未读，违背依据 1、6 |
| **iPhone 不做角标** | 不碰通知权限 | Ray 要在 iPhone 图标上看到未读（2026-11-18），违背依据 1、6 |
| **应用里的圆点开关与"这台设备"设置页，卡片带"不用了"** | 不想要圆点的人不用碰系统权限窗 | 与 iPhone 的通知设置重复；点了"不用了"就从没请求过权限，系统设置里也没有这一项，以后想要也打不开（Ray 2026-11-18），违背依据 9 |
| **只做桌面** | 不需要真机检查 | Ray 要在 iPhone 上用，违背依据 1 |
| **Web Push** | 应用关着时也能更新圆点、提醒 | 违背依据 7 |

## 风险与代价

- **停在旧版：** 已安装的应用可能运行旧版本，直到用户点刷新或关掉窗口。与服务器协议不兼容时由 `upgrade` 兜住（不变量 6）；兼容的旧版只是缺新功能。
- **坏的 worker：** 一次有问题的发布会让所有人停在坏版本，直到下一次更新。恢复见"失败与恢复"。
- **iPhone 存储分开：** 在 Safari 里写下但没发出的字不会出现在主屏幕应用里，要回 Safari 打开那篇日记。
- **圆点会过期：** 应用关着时不更新，下次打开后才纠正。
- **iPhone 未验证的行为：** 主屏幕应用里的 Google 登录跳转、输入法与窄屏布局都要真机清单确认；清单可能带出若干修复 PR。
- **缓存体积：** 页面文件全部预缓存，字体只缓存用过的切片；多占的空间与现在浏览器的 HTTP 缓存相当。

## 未解决的问题

- Android 与 iPad：默认不屏蔽、不验收、不宣称支持；有人要用时再加真机清单。
- 离线阅读：默认继续推后；以后做时，与"退出登录时锁住本机日志"一起设计。

## 落地顺序

1. **第 1 个 PR：service worker、更新提示与离线。** 范围：D1～D4 与"模块与边界"里除角标外的部分。完成条件：构建出的应用离线能打开并显示离线页，在线时断网出现提示、恢复后消失，发布新版后出现"有新版本 · 刷新"。从此生产环境的页面由 service worker 提供。
2. **第 2 个 PR：图标圆点与权限卡片。** 范围：D5、D6。完成条件：桌面 Chrome 的已安装应用在有未读时亮圆点，读完后消失；Safari 上出现权限卡片。
3. **上线与真机清单。** Ray 按 `ops/deploy/README.md` 更新生产环境，在 iPhone 与桌面上按 D7 的清单检查，结果写进 `docs/validation/`。发现的问题各开一个 PR。

**自主实现约定：**

- 预先批准的依赖：`vite-plugin-pwa` 2.0.0（devDependency）、`workbox-window` 7.4.1（dependency），精确版本。
- 预先批准的检查改动：在 `checks/verify-dependency-direction.ts` 加 `pwa` 子模块的规则；在 `playwright.config.ts` 加一个对构建产物（`vite build` + `vite preview`，`/api` 代理到 API）运行的 Chromium 项目，只跑 PWA 的 e2e。
- 不需要数据库迁移，不改接口与 contracts。
- 必须停下来问 Ray 的情况：需要缓存任何 `/api/` 的响应；需要改 Caddy、Cloudflare 或部署脚本；需要新接口；iPhone 上的某项行为与本文写的不一致。
- 每个 PR 在同一 PR 里更新 `apps/web/README.md`、路线图对应行与根 README 的状态行。

## 验收标准

- 生产环境：桌面 Chrome、Edge 与 iPhone 能安装，独立窗口打开；离线冷启动显示离线页，联网后自动进入；D7 清单在 iPhone 与桌面上通过，并有记录。
- 不变量 1：e2e（构建产物，Chromium）在用过日记页之后列出 Cache Storage 的全部条目，只有页面文件与字体；构建配置的单元检查确认 `/api/` 在导航回退的排除名单里，且没有其他 runtime caching。
- 不变量 2：e2e（构建产物）先在线打开一次，再 `context.setOffline(true)` 后重新加载，看到离线页；恢复网络后自动进入主页。
- 不变量 3：jsdom，`GET /api/me` 抛网络错误时显示离线页，返回 503 时显示"服务暂不可用"。
- 不变量 4：jsdom，离线状态下打开日记，全站提示里没有"已保存"，保存状态行只在服务器确认后显示"已保存到服务器"；sender 的测试不受连通状态影响。
- 不变量 5、6：e2e（构建产物）部署第二个构建后出现"有新版本 · 刷新"，不点就不变，点后加载新版且没发出的字仍在；jsdom，保存状态为 `upgrade` 时调用一次检查更新。
- 不变量 7：jsdom 替换 `navigator.setAppBadge` 与 `clearAppBadge`，按服务器的未读亮与清，不带参数，退出时清除。
- 不变量 8：jsdom，权限只在点「好的」后请求，请求过以后卡片不再出现；代码检查确认没有 `showNotification`、`new Notification`、`pushManager`。
- 不变量 9：现有开发服务器上的 e2e 照常通过，且页面上没有已注册的 worker。
