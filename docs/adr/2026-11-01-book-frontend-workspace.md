# 书页式前端以目录连接页面，日记用双页工作区和按日期连续浏览

- 状态：已采纳
- 日期：2026-11-01
- 决策者：Ray
- 范围：领域
- 关联：依赖 opening-book-home；依赖 unread-and-day-page；依赖 diary-collaboration-kernel；依赖 space-records；依赖 two-clocks；依赖 wishes-and-gifts；依赖 meeting-plans；依赖 anniversaries；D1 展开双页、D2 书签与目录呈现、D3 左右并排与D7 书页视觉被 digital-paper-interface 取代

已采纳的[开篇主页](./2026-10-31-opening-book-home.md)作为书的序言；本提议把「目录」「今天的日记」「所有日记」接成可用的前端路径。桌面日记工作区左页读写所选日期，右页按新到旧连续展示可读的日记全文；窄窗口用单页列表和单页日期编辑。日记列表按需加载，支持跳到日期及下一处未读。书页、书签、小角色是界面语言，正文、控件和状态仍由真实 HTML 呈现。本 ADR 决定前端信息架构与交互；不改变日记作者与共享规则，也不批准新依赖、数据库迁移或尚未实现的双人空间功能。尚无后端的自由 note／随笔／草稿文档不在本轮范围。心愿、见面和纪念日的图片在本文只作后续视觉参考。

## 背景与问题

现有桌面 Web 已有个人与双人日期页、按日期分页的摘要列表、逐字未读、两地时间、关系管理和备份入口，但页面尚未采用书页视觉。用户在 2026-10-31 至 11-01 的讨论中选择书本开篇主页；要求进入主页时不直接看到日记，保留目录书签；所有日记按日期连续滚动、懒加载，能跳日期与下一处未读；桌面选日记后在左页编辑，右页保留列表；窄窗口进入单页编辑。用户指出过跨中缝排字、角色头像大小不一、右页内容越过书底以及手机书签出屏的问题。现有[日记工作区视觉稿](../design/2026-10-31-visual-exploration/images/30.webp)已修正了主要构图，仍是示意而非实现规范。

用户于 2026-11-01 决定书页前端改版提前，排在见面计划之前（[路线图](../roadmap.md)）。同日与用户逐条确认了日期跳转、双向未读、右页的未读口径、正在写的日记、刷新与路由，写入 D3–D6、D8。

## 决策依据

1. 书页风格要温暖、简约、有辨识度；中缝、纸面和小角色不能妨碍阅读、输入与导航（用户 2026-10-31）。
2. 主页只在用户主动进入后才显示日记内容；今天与所有日记应有清楚的独立入口（opening-book-home D1）。
3. 旧日记应能连续往下读，跨尚未加载的日期仍可直接定位，不必逐篇点开（用户 2026-10-31）。
4. 桌面列表与编辑并存，窄窗口保留可用的单页路径；编辑时不能丢失列表位置（用户 2026-10-31）。
5. 列表未读与正文未读遵守已有「看见才算读」及授权规则；预取、滚动定位和路由切换不能制造已读或透露私密文字（unread-and-day-page D2–D6）。
6. 保存、作者、分享和备份状态来自现有权威数据；视觉层不能宣称尚未持久化的内容已保存（ADR-0003、diary-collaboration-kernel）。
7. 心愿、见面、纪念日尚无正式后端；图片中的页面不应被误认为现有能力或替代各自已采纳的领域 ADR。

## 决策

### D1：书页是布局容器，文字与交互控件保持真实和可访问

宽窗口使用展开双页，视觉中缝由留白与阴影表现。每页是独立的内容容器；标题、正文、按钮、滚动条与焦点均不得跨过中缝。正文不做透视或弯曲变形，避免靠近中缝的字难读或选不中。纸纹和轻微不规则边缘只作装饰，主要对比度和点击目标由真实控件保证。日记工作区不放[早期稿](../design/2026-10-31-visual-exploration/references/gutter-feedback.webp)中的窗户、砖墙和藤蔓；小角色保留作作者头像，固定可识别的脸部特征与一致的占位尺寸，形状可有轻微变化。角色、颜色、未读圆点不能单独承担身份或状态说明。

书本外形不要求逐像素模仿生成图，也不把整页图片当界面。日期、星期、时钟、日记文字、未读和保存状态均从数据生成。列表页底部可以有渐隐，但渐隐不得遮住最后一条可读内容或操作。原因：依据 1、5、6。

### D2：书签打开目录，目录只展示有去处的功能

全站书签标「目录」，宽窗口贴在书页外缘，窄窗口放在页内且始终处于可视区域。打开目录后，当前可用的路径按「日记」「一起」「管理」组织：今天的日记、所有日记、两地时间、双人空间、备份等入口只在对应页面可到达时显示。心愿与礼物、见面计划、纪念日等随功能实现后加入，不先放没有目的地的菜单项。未绑定时不显示无法使用的双人内容入口；解绑后的只读历史仍可通过已有空间入口访问。

目录是导航层，不显示日记摘要。日记入口和返回主页也保留在相关书页内，用户不必为主要动作先打开目录。键盘焦点、Escape 关闭、浏览器后退及当前页位置都要可预期。原因：依据 1、2、7。

### D3：桌面以左页编辑所选日期，右页连续阅读所有日记

从主页「打开今天的日记」进入 `/days/<查看者当地今天>`；从「浏览所有日记」进入 `/days`，即同一工作区的列表状态：宽窗口右页是列表，左页只有「从右页选一天」和「写今天」，不默认打开某一天。`/days/:date` 在宽窗口是左页编辑这一天、右页列表停在这天附近。原首页的日期列表移到 `/days`。宽窗口左页显示所选日期的双人日期页：按[日期页规则](./2026-10-28-unread-and-day-page.md#d6对方共享了某一天时这一天打开为日期页)上下排列两篇，保留各自的作者、可见性、未读、历史、光标与保存状态。右页按日期显示可读的日记全文，日期之间有清楚的间距；只读阅读，不在列表卡片里挂第二套编辑器。选右页的一天后左页切到那天并开始读，点「编辑」才把焦点交给左页的现有日期编辑流程。当前已选日期在列表里有非颜色独占的定位提示。

左页与右页分别滚动；右页滚动只发生在书页内。选一天即导航到 `/days/:date` 并记入浏览器历史，宽窄窗口相同；后退回到上一个日期或列表。列表的跳转目标与滚动位置存于浏览器历史状态，不写进网址；切换所选日期不重置右页滚动位置，后退时恢复原日期及视野位置。`/diaries/:diaryId` 与 `/diaries/:diaryId/shares/:epochId` 本轮保留，旧链接照常打开；应用内的日记入口改走 `/days/:date`，是否重定向待改版后按使用情况再定。直接打开日期深链接时，左页先显示该日，右页随后加载这一天附近的列表，不因列表尚未就绪阻塞编辑。自己的未来日期按现有服务端规则不能创建；对方未共享或不存在的日期保持不可区分。原因：依据 3、4、5、6。

### D4：所有日记按需加载全文，跳到日期后可双向继续滚动

右页以日期为分组，从新到旧滚动。首次只加载有限数量的日期元数据；接近可见区域的日期才读取可读正文，滚到边界时自动取下一批。离开视野的长文可以卸载显示节点，但必须保留滚动锚点和已读状态。加载中、已到尽头和失败重试都在书页内表达；失败不能让未读圆点凭旧缓存继续亮着。页面尺寸由实际文字决定，不能用固定高度裁断正文。

「跳到日期」支持选择尚未加载或根本没有日记的一天：先定位日期，再加载它前后相邻的可读日期；之后可以向上回到较新日期，也可以向下继续读更旧日期。目标日没有日记时显示空日期状态，不自动创建个人日记，也不暴露对方未共享的存在与否。跳转到任意位置不能靠从第一页逐页拉到目标日。

现有 `GET /api/days?before=` 只返回向旧日期翻页的摘要，不能单独完成双向定位。在同一路由增加与 `before` 互斥的 `after=<date>`：返回比锚点新、离锚点最近的一页日期，仍按日期降序排列；响应增加 `nextAfter`，上方还有更新日期时为本页最新的一天，否则为 null。跳到日期 X 时并行请求 `before=<X 的后一天>`（X 及更旧）与 `after=X`（更新），不另设一次返回前后两侧的查询；X 没有日记时两侧仍返回相邻日期，页面在其间显示这天的空状态。不带查询与原有 `before` 的语义不变。正文在日期接近视野时，用现有 `diary`／`sharedDiary` 获准状态读取接口取得，按现有 `readRanges`／`reportRead` 判未读，不为列表里的每篇日记建立实时编辑会话。若需要数据库迁移或新依赖仍按 AGENTS.md 先询问。原因：依据 3、5、6。

### D5：列表未读与下一处未读保持现有语义

右页按[未读与日期页 ADR](./2026-10-28-unread-and-day-page.md)显示日期级未读圆点，并在有新内容的作者段落附近给出细小提示；圆点不代替「未读」文字说明。列表预取只获取数据，只有活动页面中真正进入视野约一秒的对方文字才上报已读；被书页遮住、在渐隐下不可读、隐藏或卸载的文字不算。自己写的文字不产生自己的未读。左页编辑时右页若确实可见，右页的阅读行为仍按同一规则记录；同一字跨两页重复出现只上报其实际已读区间。

右页的未读分两种口径（[unread-and-day-page D2](./2026-10-28-unread-and-day-page.md#d2未读按字判定日记里实时列表只计已成历史的文字)）：已加载的正文按「日记里」的口径，由浏览器用正文和 `readRanges` 实时计算，对方刚写的字也算；尚未加载的范围按「列表」的口径，只计已成历史的文字。日期圆点在正文加载前取列表结果，加载后按正文重算。

未读跳转是右页内上下居中的两个圆形按钮：底部 ↓ 往更旧找，顶部 ↑ 往更新找，各自只在该方向确有未读时出现，不绕回另一端；它们取代列表里「上面／下面有新内容」的方向提示。按钮只有箭头，约 40–44px，可读名称为「上一处未读」「下一处未读」，悬停或聚焦时显示同样文字；按钮留出底部间距，不遮住最后一行或操作。查找先在已加载正文中从当前视野往该方向进行；已加载部分没有时，以已加载范围的边界日期请求新增的 `GET /api/days/next-unread?before=<date>` 或 `?after=<date>`（二者互斥），服务端按列表口径返回该方向最近的有未读的获准日期，或「没有」。页面在进入列表和每次跳转后向两个方向各查一次并记住结果，点击时直接跳转。不能为搜索而把全部历史正文拉进浏览器。点击按钮是用户主动跳转，不抢左页的编辑焦点；仅打开页面或预取不会自动跳走。

服务端查找先用 SQL 排除不含对方文字的日记，再逐篇判定；每个（查看者，日记）的判定结果缓存在 API 进程内存中，键为最后一次已成历史的提交、最近一个历史点和查看者该篇已读区间行的哈希，任一变化才重建正文重算。缓存只是可随时丢弃的计算副本，不是 unread-and-day-page 否决的未读表，无迁移。原因：依据 3、5。

### D6：窄窗口从单页列表进入单页日期编辑

宽度放不下两页时变成一张可纵向滚动的书页，不缩小桌面双页。`/days` 先显示单页全文列表；选某天或点「编辑」进入 `/days/:date` 的单页日期页，返回后恢复列表的日期与滚动位置。「跳到日期」与 D5 的圆形未读按钮在列表页仍可触达；书签位于屏内。窄窗口交互为响应式 Web 设计，不宣称实体手机浏览器已通过验收；正式手机支持按[路线图](../roadmap.md)另行安排。原因：依据 1、4、5。

两地时间与邀请沿用 opening-book-home，完整作息设置继续由已有页面承担。心愿与礼物、见面计划、纪念日各自遵守已采纳的领域 ADR；它们的图像是视觉探索，待各功能实施前逐页核对字段、权限和空状态：

| 心愿与礼物 | [心愿桌面](../design/2026-11-01-wishes-exploration/images/03-desktop-refined.webp)、[心愿窄页](../design/2026-11-01-wishes-exploration/images/04-mobile-refined.webp)、[私密准备与礼物墙](../design/2026-11-01-wishes-exploration/README.md) | 准备和卡片在揭晓前仅送的人可见；无商品链接或预览时用纯文字，不建空图片框 |

### D8：右页折叠正在写的日记，展开的全文按版本刷新

右页不显示写到一半的正文。两种情况折叠成一行：查看者在左页打开的自己那篇，显示「正在左页编辑」；最近一个历史点之后仍有提交的日记（约两分钟内有人写过），显示「TA 正在写」或「你在别处正在写」，附「在左页打开」。后者由 `GET /api/days` 每篇新增的布尔字段给出，沿用内核的历史点规则，不是在线状态，也不声明对方此刻在场。折叠的文字不可见，不上报已读；该日有未读时圆点照亮，圆形按钮跳到这天时停在折叠处。

展开的全文沿用原首页列表的刷新时机：进入、窗口获得焦点、每 45 秒，只取视野附近日期的元数据。某篇的 `updatedAt` 变化时，视野附近的立即重读正文，远处的标为过期、接近视野再读；「正在写」转为否时展开并重读；冻结的共享不再变化，跳过。重读后视野上方高度变化时保持正在读的那一行不动。左页换到另一天时，原先折叠的自己那篇展开并重读。列表因此比实际写入晚约两到五分钟，与原首页列表相同。不为右页的日记建立 WebSocket 推送（D4）。原因：依据 4、5、6。

## 失败与恢复

| 情况 | 页面行为 |
| --- | --- |
| 列表元数据或正文读取失败 | 保留已显示的可读内容，给当前批次重试入口；不把未确认的旧未读结果当成最新状态 |
| 跳转目标不存在、尚未共享或超出可写日期 | 展示不泄露对方隐私的日期空状态；只有服务端允许时才显示「写这天」 |
| 编辑同步离线或提交失败 | 左页沿用现有本机日志、恢复草稿与服务器确认后的保存状态；右页不伪造「已保存」 |
| 查找下一处未读失败 | 该方向的圆形按钮不出现，不显示「没有未读」；下次刷新或跳转时重查 |
| 日期跳转时有远端更新 | 保留当前编辑光标与列表阅读锚点；不强制自动滚到远端写入处 |
| 纸张装饰加载失败或关闭动效 | 正文、入口、未读、保存和书签仍以真实控件可用 |

## 不变量

1. 书页正文、输入与操作均在单页内容边界内，窄窗口无因书签或中缝导致的横向溢出。
2. 首页初次出现时无日记正文或摘要；目录与首页各有通向今天及所有日记的可发现入口。
3. 桌面所选日期只在左页编辑，右页连续全文列表可独立滚动，切换日期后保留列表位置。
4. 日期跳转能定位尚未加载的一天，随后可向较新和较旧日期继续浏览，空日期不会自动创建日记。
5. 列表预取、隐藏和不可读区域不会上报已读；上下两个方向的未读跳转都能跨未加载日期定位，按钮只在该方向确有未读时出现。
6. 窄窗口的列表与编辑为可返回的单页路径，返回后保持原列表位置，目录书签始终在屏内。
7. 未授权的对方正文、未揭晓礼物和已解绑后不可看的两地时间不会因列表、目录或装饰元素泄露。
8. 页面显示的作者、保存、分享与备份状态来自对应服务端或已有同步会话的权威状态。
9. 右页不显示左页正在编辑的那篇，也不显示最近一个历史点之后仍有提交的日记正文；折叠的文字不上报已读。

## 备选方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| **列表内直接挂编辑器** | 选中后不用看另一页 | 长列表会同时承担阅读、同步与输入，滚动锚点和作者边界难保持（依据 4、5、6） |
| **从第一页逐页加载直到目标日期** | 复用当前单向分页接口 | 多年日记时跳转慢且传输大量无关内容（依据 3） |
| **整本书始终双页并模拟翻页** | 视觉一致 | 窄窗口太挤，也妨碍连续搜索旧日记（依据 1、3、4） |
| **把书页做成整张背景图并叠加热点** | 静态稿容易还原 | 文字选择、输入、缩放、焦点与不同长度正文会失真（依据 1、6） |

## 风险与代价

- 连续全文比摘要列表传输和渲染更多内容；必须靠视野附近读取、分批加载、滚动锚定和真实长文测试控制成本。
- 双页各自滚动可能让用户忽略右页还有旧内容；应有明确的滚动区域与底部渐隐，末尾状态可见。
- 未读跨页定位需要后端能力；只改 CSS 或仅复用现有摘要接口不能兑现 D4、D5。全部已读时查找要走到最旧一篇，首次靠重建正文，之后靠 D5 的缓存；缓存为空时的耗时须实测，不达标则改为每次只查有限篇数并带续查游标。
- 生成图有示例文字和局部不准确文案；如[月历图](../design/2026-11-01-dates-exploration/README.md)的「接下来的重要日子」包含已过去日期，正式界面应改为「本月的重要日子」或只列未来事件。

## 未解决的问题

- 见面计划与纪念日详情、礼物墙的最终交互排版：各功能后端落地前结合其领域 ADR 另行审阅，当前图片不作为像素规范。
- 小角色的最终图形资产、色值与字体文件：实施时在不改变 D1、D2 身份和可读性规则的范围内确定；不因图像生成稿而新增依赖。
- 窄窗口 Web 的响应式验收包含在本 ADR；实体手机输入、系统剪贴板和浏览器兼容验收仍按路线图后置。

## 落地顺序

1. 先实现契约与 API：`GET /api/days` 的 `after` 与 `nextAfter`、每篇的「正在写」字段（D4、D8），`GET /api/days/next-unread` 的 `before`／`after` 与判定缓存（D5）；全文复用现有获准状态读取，沿用已读区间和作者边界。合同或路由变化生成 OpenAPI。用约三年、两人每天一篇的数据实测全部已读时 `next-unread` 的耗时，缓存为空与已满各测一次，目标 p95 不超过 300ms。任何数据库迁移或新依赖依 AGENTS.md 单独取得许可。本 ADR 本身不预批准它们。
2. 在 `apps/web` 以现有日期页编辑会话为左页，在右页建立只读、按需加载的列表；先让跳日期、双向未读按钮、折叠与刷新、滚动位置与错误恢复工作，再接入书页容器。路由按 D3 的 `/days` 与 `/days/:date`，深链接直接可用。
3. 把主页换成已采纳 opening-book-home 的开篇，把「目录」及现有可达入口接上；邀请、两地时间、空间与备份使用现有数据。首页日记摘要只在所有日记里显示。
4. 在桌面与窄窗口验证长文、空列表、多人跨日、冻结共享、未绑定、解绑、缺作息、离线、错误和键盘操作。实现行为的同一提交更新 `apps/web/README.md`；开始阶段 4 时按路线图更新状态。心愿、见面、纪念日页面分别等相应功能落地再做。

## 验收标准

- 浏览器打开首页时无日记文字；两个主入口、目录和返回路径均可操作（不变量 1、2）。
- A/B 账号下从新到旧滚动多页完整正文，选旧日后左页编辑且右页位置不丢；长文和宽窄窗口均不越中缝或书底（不变量 1、3、6）。
- 从未加载的日期跳转，向上向下继续加载；空日期不创建，未授权日期无可推断痕迹（不变量 4、7）。
- 浏览器测试：预取不标已读，实际可见约一秒才标；↑ 与 ↓ 跨批次都能到达仍未读的正文，无未读的方向不出现按钮，编辑焦点不被抢走（不变量 5）。
- 对方写入后两分钟内，右页该篇折叠为「TA 正在写」，历史点形成后的下一次刷新展开为新正文；左页正在编辑的那篇不在右页重复出现（不变量 9）。
- `next-unread` 全部已读时的实测耗时记录在验证文档，满足落地顺序 1 的目标或已改为有限篇数查找。
- 保存、作者、分享、备份及私密礼物的状态来自既有服务端语义；断线后不提前显示已保存（不变量 7、8）。
- 相关测试标题按 `[adr:book-frontend-workspace#<编号>]` 标记不变量；运行与变更相符的前端、API、契约、格式、lint、typecheck 和文档检查。
