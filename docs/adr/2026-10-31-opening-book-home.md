# 主页以一本书的开篇呈现，两地时间与日记入口融入书页

- 状态：已实现
- 日期：2026-10-31
- 决策者：Ray
- 范围：领域
- 关联：依赖 spaces-and-invitations；取代 unread-and-day-page 的D3 首页位置；取代 two-clocks 的D4 首页呈现

主页是一段不直接展示日记正文的开篇（`/`，`apps/web/src/pages/HomePage.tsx`）。宽窗口显示展开的两页书：左页是日期、简短序言和两扇窗的插画，右页显示双方当地时间、共同醒着的时段及当前位置，并提供「打开今天的日记」「浏览所有日记」两个清楚的入口。导航以书签或书页元素融入界面，不使用固定在顶部或左侧的传统导航栏。窄窗口改为一张可纵向滚动的书页，带标注「目录」的书签留在页内、屏幕内。未绑定时展示邀请入口。本 ADR 只决定主页的信息与呈现；所有日记的连续列表、列表内编辑和未读交互由 [book-frontend-workspace](./2026-11-01-book-frontend-workspace.md) 决定。

## 背景与问题

现有首页直接列出按日期合并的日记卡片与摘要，打开页面便可能让旁人看到私密内容。已采纳的 two-clocks D4 把时间压成列表上方的小条，而用户现在希望时间和共同醒着的时段成为首页的主要信息。用户在 2026-10-31 确认书本开篇方向，并指出手机版书签不能伸出手机屏幕。现有未读与日期页能力仍可用于「所有日记」页面；当前代码形态不代表新的主页布局。

## 决策依据

1. 主页打开时不应直接露出当天或历史日记的文字；用户主动进入日记后才显示内容。
2. 双方当地时间、共同醒着的时段和当前时刻应一眼看懂，同时避免把作息推算说成实时在线状态。
3. 今天的日记与所有日记都要有独立、明显的入口；无限列表的具体交互尚未确定。
4. 简约、温暖、有一点手绘活力的书页风格要保留；内容与导航应自然融入书本，不像套在书本上的常规应用栏。
5. 书签保留为导航线索；窄窗口下不能伸出设备或导致横向滚动。
6. 首版目标仍是桌面 Web，窄窗口要可用；手机正式支持与列表交互可另行验收。

## 决策

### D1：主页只展示开篇信息，日记内容在主动进入后出现

首页不渲染日记正文、摘要、当天双人页面或按日期排列的卡片。入口「打开今天的日记」进入查看者当地今天的现有日记/日期编辑流程；入口「浏览所有日记」进入独立的按日期浏览页面。前者是 `/days/<查看者当地今天>`，后者是 `/days`；列表加载、跳转、未读和编辑的规则见 book-frontend-workspace。

这提供的是打开应用时的视觉隐私，不代替登录、分享权限或设备锁屏。主页仍可显示两人时间与关系信息，因此在旁人能看到屏幕时并非完全隐藏私人信息（依据 1、3）。

### D2：时间以两地时钟、共同醒着的时段与「现在」组成一个信息区

绑定中显示双方当地时间及当地日期；跨日时日期要能看出差异。按 two-clocks D1–D3 的时区和作息规则计算以查看者当地今天为基准的共同醒着时段，用时间轴和文字同时标出区间与当前时刻。区间带「按作息推算」说明；当前不在区间内也保留「现在」标记。时间轴应能容纳零段或多段重叠，不能假定每天只有一个区间。

任一方作息缺失时保留可得的当地时钟，并给出补全作息的入口；对方时区还不可得时不猜测时间。时间是时区与作息的推算，不声明对方此刻在线或清醒（依据 2）。见面计划、纪念日等后续功能是否在主页露出，另行决定。

### D3：宽窗口用双页，窄窗口用单页滚动

宽窗口的左页承载标题、日期、短句与两扇窗/两个软乎乎的抽象角色；右页承载 D2 的时间区与 D1 的两个入口。人物和插画烘托气质，不能代替功能文字与可点区域。暖奶油色纸面、克制的橙蓝色、细节不完全对称的手绘感是视觉方向；不要求照搬生成图的字形、阴影或像素位置（依据 4）。

空间不足时，布局转成一张从开篇、时间到两个入口自然向下滚动的书页。文字和按钮保持可读、可点，不缩小双页强塞进窄屏，不出现横向滚动。断点按内容所需宽度确定，不由某个手机机型决定（依据 5、6）。

### D4：书签作为目录入口，始终留在可见书页内

书签打开目录，供进入已存在的产品页面及返回主页；主行动「打开今天的日记」「浏览所有日记」仍直接写在书页上，不藏在目录里。宽窗口书签可贴书页外缘；窄窗口改成页内右上角的「目录」书签，并避开安全区域。书签应有文字、键盘焦点和可触达的点击区域，不只靠插画形状暗示功能（依据 4、5）。

### D5：未绑定时用邀请入口替代双人信息

未绑定用户保留开篇结构，展示自己当地时间与清楚的邀请/绑定入口；不显示虚构的 TA 时间和重叠时段。已解绑时也不继续展示对方的时区或作息，沿用 two-clocks 的权限边界（依据 2）。

## 不变量

1. 主页初次渲染不会出现任何日记正文或摘要；日记文字只在用户主动进入日记或所有日记页面后出现。
2. 绑定中且数据齐全时，主页同时可见双方当地时间、共同醒着的时段和「现在」；推算结果有明确说明。
3. 主页有两个独立、明确的入口，分别通向今天的日记和所有日记。
4. 窄窗口的「目录」书签完全位于页面和设备可视区域内，页面不因书签横向溢出。
5. 未绑定或已解绑时，主页不展示对方时区、作息及推算出的共同醒着时段。

## 备选方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| **直接以日记列表为首页** | 历史日记一步可见 | 打开即露出摘要，也挤占时间信息的位置（依据 1、2） |
| **顶部导航加卡片面板** | 熟悉、容易实现 | 与用户确定的书页开篇气质不符（依据 4） |
| **所有页面都模拟翻书** | 视觉隐喻统一 | 连续浏览历史日记时会妨碍快速滚动（依据 3） |
| **手机上缩小双页，书签留在外侧** | 布局与桌面一致 | 内容过小，书签可能出屏（依据 5） |

## 风险与代价

- 书本隐喻可能降低入口可发现性；所以两项主要行动直接显示，目录书签必须标字。
- 插画与纸张装饰会占空间，窄窗口需优先保障时间与入口的可读性。
- 生成图只表达气质和大致构图，含示意时间与日期；桌面图的星期文字有误，实际界面必须由日期逻辑生成。
- 本决定仅部分取代 unread-and-day-page D3 的「列表位于首页」和 two-clocks D4 的「首页顶部小条」；它们的数据、未读规则和时间计算仍有效。

## 未解决的问题

- 所有日记页面的连续列表、未读标记与跳转、列表内编辑：已由 book-frontend-workspace 决定并实现；本 ADR 只保证入口和主页隐私边界。
- 「目录」中具体列哪些未来功能：按功能实际落地情况决定，不预留无去处的入口。

## 验证

5 条不变量都有标题带 `[adr:opening-book-home#N]` 的测试：页面在 jsdom 组件测试与 Chromium、WebKit 浏览器测试（`e2e/book.spec.ts`，真实 API 与一次性 PostgreSQL）中验证。

1. 无日记文字：jsdom 中主页不出现日记正文、不请求 `/api/days`（`apps/web/src/pages/HomePage.test.tsx`）；浏览器中写过日记的账号打开主页，页面没有那段文字，也没有任何 `/api/days`、`/api/diaries` 请求，打开「目录」后仍没有。
2. 时间区：jsdom 中两地时钟、跨日的日期、零段与多段共同醒着、「现在」与「按作息推算」（`apps/web/src/two-clocks/two-clocks.test.tsx`）；浏览器中绑定而双方都没设作息时，两个时钟与「设置作息」可见，不出现推算的时段。
3. 两个入口：jsdom 中「打开今天的日记」通向 `/days/<当地今天>`、「浏览所有日记」通向 `/days`；浏览器中两者可见，目录的「所有日记」进入 `/days`。
4. 书签在屏内：浏览器在 375×740 与 320×640 下，主页、`/days`、`/days/:date`（含 400 个字母的长词与长链接）、滚到页底以及目录打开时，书签都完整位于窗口内，窗口没有横向滚动，书页里的文字和控件都不超出窗口；书签可用键盘打开。这一条只能在浏览器里验证；ADR 索引只统计 `*.test.ts(x)` 与 `checks/verify-*` 里的标记，不含 `e2e/*.spec.ts`，所以索引显示 4/5。
5. 未绑定与解绑：jsdom 中未绑定只显示自己的时钟与邀请、解绑后显示原空间与恢复邀请（`HomePage.test.tsx`、`two-clocks.test.tsx`）；浏览器中从未绑定与解绑后的两人都只看到「此刻」，没有 TA 的时间、共同醒着的时段或「设置作息」。

书页的观感、纸面与窄页可读性等需要人判断的部分见[手动验证清单](../validation/book-frontend-manual-2026-11-01.md)：**尚未执行**，由 Ray 在合并前执行。
