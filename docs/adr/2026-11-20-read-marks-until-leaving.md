# 读到的新字留一层浅色标记，直到离开「我们的日记」

- 状态：已实现
- 日期：2026-11-20
- 决策者：Ray
- 范围：领域
- 关联：依赖 unread-and-day-page；依赖 book-frontend-workspace

对方的新字被读到以后（判定和上报照旧，约一秒），标记不立刻去掉，而是变浅，一直留到离开「我们的日记」（`/days/:date?`）：去其他页面、刷新或关掉应用才清除。连续读和日期页共用这份记录，由 `DaysWorkspace` 按日记、按字的身份持有，所以在一处读到的字到另一处仍是浅色；只有在本页屏幕上被读到的字才变浅。读到后的浅色标记不算未读，不进入任何计数、提示或跳转。对方的字由实时广播送到、送到时就在眼前的，直接画浅色；打开时载入和重连补上来的字照常是实色。于是实色只表示"还没见过的新字"，浅色表示"这次进来后见过的新字"。

本文补充 unread-and-day-page 和 book-frontend-workspace，不取代其中任何一条：已读的判定、存储与上报不变，浅色标记离开就消失，不是永久标记。本文不负责标记的样式（荧光笔颜色与深浅、页边竖条、编辑器里的画法、跳转高亮），它们写在各模块 README 里；也不负责共享页面（#120）。

## 背景与问题

issue #112：对方的新字不好找。Ray 在 iPhone 上验收时（第 9 项）看不清哪里是新内容。原因有三处：

- 连续读里，未读字用 `<mark>` 画出，露在视野里约一秒算读过以后重新画成普通文字，标记随之消失；跳到未读时的高亮挂在这个元素上，也被一起截掉，往往没淡完就没了。
- 日期页用编辑器（`DayEditor`）显示，对方的未读没有任何常驻标记，只有"有 N 处新内容"和跳转时的高亮。
- 高亮颜色在纸色上本来就很淡。

2026-11-20 与 Ray 定下的方案（#112 的评论"定下的方案"）分四个方向：A 赭石荧光笔和页边竖条，B 读到后标记先留着，C 编辑器里也画，D 跳转高亮更明显。A、C、D 只是样式，写进模块 README；B 改变了"未读标记什么时候消失"这一行为，而 unread-and-day-page D4 只说过"跳到之后短暂高亮后淡出；不留永久标记"。不写下来，以后的改动很容易把它改回"读到就消失"，或者把保留做成永久标记，所以单写这份 ADR。

约束：未读定位标记是临时阅读辅助，不用永久底色区分作者（规格 §8.1）；已读按字的身份记录，约一秒可见才算读（内核 D15，§8.1 实施默认）；连续读和日期页的已读是同一套判定（book-frontend-workspace D5）；被隐藏的字不计已读（unread-and-day-page 不变量 7）。

## 决策依据

1. 读者要能看清刚才哪些字是新的；约一秒就消失的标记，往往还没看清就没了（#112，Ray 2026-11-20）。
2. 已读的判定、存储与上报不变：仍是约一秒可见、按字的身份、只属于读者本人（内核 D15，unread-and-day-page D2、D4）。
3. 标记是临时的，不变成永久按作者区分的底色（规格 §8.1）。
4. 同一个字在连续读和日期页里应是同一种状态，因为两处的已读本来就是同一套判定（book-frontend-workspace D5）。
5. 计数、提示和跳转只指向还没读的字，否则"有 N 处新内容""下一处未读"会指向已经看过的地方。
6. 断网重连、从后台回来时补上来的字，必须看得出是新的。
7. 标记不改变正文、不产生提交、不让对方知道，不抢焦点、不移动阅读位置（unread-and-day-page D5、不变量 14）。

## 决策

### D1：这次进来后读到的新字变浅，不去掉

对方的一个字有四种显示状态：

| 状态 | 条件 | 显示 | 算未读 |
| --- | --- | --- | --- |
| 未读 | 不在读者的已读区间里（unread-and-day-page D2） | 实色标记，所在行有页边竖条 | 是 |
| 未读，正在眼前送到 | 未读，且符合 D5 | 与保留相同的浅色标记，没有竖条 | 是 |
| 保留 | 这次访问（D2）中由本页报为已读 | 浅色标记（约实色的一半深浅），没有竖条 | 否 |
| 无标记 | 其他已读的字 | 普通文字 | 否 |

**进入保留的条件**：本页（连续读或日期页里任何一篇的已读追踪器）一次 `reportRead` 上报成功后，这次上报送出的字中，上报前本页还不知道已读的那些进入保留。"本页知道的已读"是这次访问中本页为这篇日记拿到过的全部已读区间的并集，来自 `readRanges` 或 `reportRead` 的回答（回答是服务端的全部已读），由 D3 的那一层持有，会话重建时不清空。上报前本页对这篇还一无所知（`readRanges` 失败或还没回来）时，这次送出的字不进入保留：宁可少标，不把以前读过的字标成新字。

所以：进来以前读过的字没有标记，第二次进来不会看到上次读过的字；在另一台设备上读过、这次没在本页露过面的字也没有标记，只有在本页屏幕上被读到的新字才是浅色。

自己写的字从来不是自己的未读，也不会进入保留。原因：依据 1、2。

### D2：保留到离开「我们的日记」

"这次访问"从进入 `/days/:date?` 开始，到离开为止：

| 清除保留 | 不清除 |
| --- | --- |
| 去心愿、设置、主页等其他页面 | 滚出视野 |
| 刷新页面、关掉应用 | 在连续读和日期页之间切换 |
| | 在日期索引里换日期 |
| | 连续读里某篇折叠成"TA 正在写"后再展开，或按新版本重新读取正文 |
| | 日期页上某一篇的会话重新打开（例如对方重新共享） |

保留只在内存里，不写进浏览器存储，也不上报服务端。写进存储会让它跨访问留下来，越积越多，变成 §8.1 不允许的永久标记；上报服务端则需要新表和接口，而它只对这一次访问有意义。代价是在应用内来回切换页面时保留会丢，回来后读过的字是普通文字。原因：依据 1、3、7。

### D3：连续读和日期页共用一份，由 `DaysWorkspace` 持有

保留记录是一个按日记分开、按字的身份（clientID 与 clock，与已读区间相同）记的集合，由 `DaysWorkspace` 这一层持有，连续读（`day-feed`）和日期页（`diary` 的日期页会话）都从这里读、往这里写。不放在单篇 `FeedDiary` 或日期页的会话里：它们在折叠、重新读取、换日期、切换视图时会卸载或重建，重建后的已读追踪器从 `readRanges` 起步，只知道"已读"，分不清是这次读的还是以前读的。连续读和日期页同是 `/days/:date?` 这一个路由，实现时确认在两者之间切换时 `DaysWorkspace` 不卸载；若会卸载，把记录移到这个路由下不卸载的最近一层，规则不变。

这一层在 `diary` 里，`day-feed` 不能引用它（web 子模块的依赖方向），所以记录由 `DaysWorkspace` 往下传给连续读和日期页；记录的类型和区间运算放在两者都引用的 `read-tracker`。

记录按字的身份，而不是按位置：编辑时标记跟着字走，不错位；对方删掉的字不在正文里，标记自然消失，记录里的这几项不再画出。原因：依据 4。

### D4：保留态不算未读

保留态的字不计入"有 N 处新内容"、方向提示、"下一处未读"与圆形未读按钮、日期圆点和应用角标。例：在连续读里已经全部看过的一天，点进日期页后不再提示"有 N 处新内容"，但看过的字仍是浅色。

日期页的计数、方向提示、日期圆点和角标都按已读区间计算，保留不改变已读区间，所以它们不需要改动。连续读的圆形未读按钮不同：它在页面里找未读的 `<mark>` 元素（`day-text-unread`），所以保留态必须用另一个 class 或另一种元素，不能被它选中；日期页的"下一处未读"按已读区间算出的未读段查找，不看标记，所以 D5 直接画浅色、还没上报的字仍是它的跳转目标。本条写下来，是为了不让以后把保留态当成未读去数。原因：依据 2、5。

### D5：实时看着出现的字直接画浅色

对方的字由同步连接上的实时广播（`commit` 消息）送到，送到那一刻就在可见区域里，且页面在前台，就直接画成浅色，不先画实色。其他来源照常是实色：

| 字从哪来 | 送到时 |
| --- | --- |
| 实时广播 `commit`，送到时在可见区域、页面在前台 | 浅色 |
| 实时广播 `commit`，送到时在视野外 | 实色 |
| 打开页面时载入的正文 | 实色 |
| 连接建立、重连、补缺口时的 `synced` 补发 | 实色 |
| 页面在后台或锁屏时送到 | 实色 |
| 连续读按版本重新读取的正文 | 实色 |

`synced` 补上来的字不算"出现在眼前"：从后台切回、断网重连时，对方离开期间写的字一次到达；若画成浅色，正好看不出这是新内容（依据 6）。

这一条只改显示，不改已读：这些字仍是未读，照样在可见约一秒后上报为已读，然后进入 D1 的保留态，外观不变。出现后不到一秒就滚出视野、还没算已读的字回到实色，"下一处未读"照样会跳到它。连续读里对方正在写的那篇整篇折叠（book-frontend-workspace D8），正文也不经同步连接，所以这一条实际只发生在日期页。原因：依据 1、2、6。

### D6：哪些字不显示标记

被"只看我的文字"或日期页视图切换隐藏的字，未读和保留标记都不显示，也不计已读（unread-and-day-page 不变量 7）；隐藏期间它们的保留记录不变，重新显示时照旧。标记、保留与 D5 的显示都不改变正文、不产生提交、不让对方知道，不抢焦点、不移动阅读位置。原因：依据 3、7。

### 不在本文：样式

以下是 #112 同时定下的样式，只作背景，写在相关模块 README（`day-text`、`editor-binding`、`diary`、`day-feed`、`read-tracker`）里，改它们不需要新 ADR：

- A：赭石荧光笔涂字的下半截，两位作者同一种颜色；未读所在行的左边距一条赭石竖条，只标实色的未读（D1）。
- C：编辑器里也画未读和保留两种标记，和只读视图共用一份样式；保留态另用一个 class，`UnreadArrows` 只找未读的（D4）。
- D：跳转高亮换成赭石、闪两次约三秒，结束后停在荧光笔上；跳到的那段在高亮期间不被重建。

本文只要求：未读、保留、无标记三种外观彼此看得出区别，且都不按作者区分颜色。

## 失败与恢复

| 情况 | 结果 |
| --- | --- |
| 已读上报失败 | 这些字保持未读，下次检查重报（现有行为）；上报成功后才进入保留。外观：原本实色的仍是实色；D5 直接画浅色的字仍按 D5，留在视野里保持浅色，滚出视野回到实色 |
| 已读区间读取失败、页面不知道已读 | 现有行为不变；在本页第一次知道这篇的已读之前，上报的字不进入保留（D1） |
| 同步连接断开后重连 | 补上来的字是实色（D5）；已在保留里的字不受影响 |
| 记录所在的一层意外卸载 | 保留丢失，读过的字成为普通文字；未读照常，不会出现找不到的未读 |

## 不变量

1. 保留态的字不算未读：不计入"有 N 处新内容"、方向提示、"下一处未读"、圆形未读按钮、日期圆点和应用角标。
2. 只有这次访问中由本页上报成功、且上报前本页不知道已读的对方文字进入保留；进来以前读过的字、只在其他设备上读过的字和自己写的字不进入保留。
3. 在连续读和日期页之间切换、换日期、滚出视野、折叠后再展开或重新读取正文，都不清除保留；离开「我们的日记」、刷新或关掉应用后，保留全部清除。
4. 同一个字在连续读和日期页里显示同一种状态。
5. 保留只在本页内存里，不写进浏览器存储，不上报服务端，不让对方知道。
6. 只有送到时就在可见区域且页面在前台的实时广播文字直接画浅色；打开时载入、`synced` 补发和在后台送到的文字是实色。
7. 保留与直接画浅色都不改变已读的判定与上报：直接画浅色的字在约一秒可见后照常上报，没上报就滚出视野的字回到实色并仍是未读。
8. 被"只看我的文字"或视图切换隐藏的字不显示未读或保留标记。
9. 标记跟随字的身份：编辑后不错位，被删掉的字不再画出标记。

## 备选方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| **读到就去掉标记**（现状） | 最简单；屏幕上只有真正没读的字 | 约一秒就消失，读者往往没看清哪些字是新的，跳转高亮也被一起截掉（依据 1） |
| **读到后留固定几秒再淡出** | 不需要跨页面的记录 | 几秒对慢读者不够、对快读者多余；切到日期页后已经淡掉，两处状态不一致（依据 1、4） |
| **保留写进浏览器存储或服务端，跨访问留下** | 下次打开还能看到上次读过的新字 | 越积越多，接近按作者的永久底色，违反 §8.1（依据 3）；服务端还要新表和接口 |
| **连续读和日期页各自保留** | 不用把记录提到 `DaysWorkspace` | 同一个字在两处状态不同；会话重建后从 `readRanges` 起步，分不清这次读的和以前读的（依据 4） |
| **浅色标记也算未读，直到离开** | 计数和跳转能回到看过的字 | "有 N 处新内容""下一处未读"指向已经看过的地方，失去找新内容的作用（依据 5） |
| **实时送到的字一律先画实色** | 规则统一，不用区分来源 | 看着对方写时，眼前每个新字都先亮成实色再变浅，闪烁且没有信息（依据 1） |
| **`synced` 补发的字也直接画浅色** | 与 `commit` 同样处理 | 从后台回来、重连时对方离开期间写的字一到就是浅色，正好看不出新内容（依据 6） |

## 风险与代价

- 在应用内去别的页面再回来，保留就没了；Ray 用过后觉得不够时再考虑放宽 D2 的范围（见重新评估条件）。
- "在可见区域、页面在前台"在送到那一刻判断，判断时机和已读追踪器的检查不同步，边缘的一两个字可能先浅后实或相反；不影响已读与计数。
- 长时间停在「我们的日记」，保留记录随读到的字增长；按字的身份合并成区间存放，日常规模下可以忽略。

## 验证

- 实现：#112 拆分的第 2 个前端 PR（读后保留，叠在第 1 个"荧光笔、编辑器里的标记、跳转高亮"之上，2026-11-20 提交，待 Ray 确认后合并）。保留记录是 `read-tracker` 的 `createReadMarks()`（`ReadMarks`），由 `DaysWorkspace` 用 `useState` 持有，传给 `DayFeed` 和 `DayEditor`，再到每篇的已读追踪器（`createReadTracker` 的 `marks`）；D5 的显示是同一单元的 `createArrivals()`，每个日期页会话一份，`sync-client` 的 `onCommits` 多给一个 `live`（`commit` 为真，`synced` 为假）。连续读和日期页同是路由 `/days/:date?` 的一个元素，切换时 `DaysWorkspace` 不卸载（D3 的前提成立）。连续读里跳转高亮被截掉的原因在 jsdom 里复现：读到后 `<mark>` 被重建成 `<span>`，挂在旧元素上的 class 随之消失；修法是保留态仍是 `<mark>`（只换 class），高亮改为 React 不管的 `data-flash` 属性。
