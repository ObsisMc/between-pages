# ADR-0001：共享日记、用户归属与日期模型

- 状态：已采纳
- 日期：2026-10-24
- 决策者：Ray
- 范围：领域
- 关联：无

> 迁移说明（2026-10-25）：ADR 改为新格式，本文正文冻结。原状态行为：已采纳。来源：用户确认的产品规则。

## 背景

双方通常每天写一篇随笔，在原文任意位置添加自己的想法，不需要引用、段落评论或句子关系。两人跨时区，既希望按当地日期创建，又要在双方设备上看到同一篇固定日期的日记。

## 决策

1. 一个空间每天最多一份共享文档，双方共同编辑，不拆成两篇个人日记。
2. 每个字符只归一个用户，保留有序内容及不可变作者；不创建语义句子 ID 或回复树。连续同作者区段可压缩，但不丢时间和读取定位信息。
3. 允许任意字符边界插入；只允许改删自己的文字。删除遇到对方文字时跳转；混合作者选区修改整体阻止。前后文字仅靠作者和顺序即可恢复单方阅读。
4. 每次“写今天”由请求者有效 IANA 时区与服务端 UTC 时间推导日期。文档创建后 diaryDate 固定；同一空间日期唯一，由 PG 约束并发。
5. UTC 时间点、日记 DATE、IANA 时区分别建模。顺序不依赖客户端时钟；写入时间与接收时间分开记录。
6. 作者色属于用户映射，正文用字体色，不用永久底色。颜色不是可信作者数据。
7. 未读记录稳定文字范围，不用单个最大操作序号；读取进度不默认公开给另一方。

## 替代方案

- 一人一天一篇：不符合共同穿插续写。
- 统一北京时间归档：用户明确选择创建者当地日期。
- 段落评论、引用回复、句子身份：增加交互和结构约束，没有当前需求。
- 仅保存彩色 HTML：作者可被样式伪造，且不足以表达稳定定位和时间。

## 后果

同一时刻双方的“今天”可能是两篇不同日期文档，需清晰展示日期。删除保护增加编辑器实现成本，但无需开发复杂的语义回复模型。字符索引必须适配 Unicode 可感知字符。

## 验证与参考

验收：DATE-01～06、EDIT-01～13、READ-01～05、TIME-01～03。
