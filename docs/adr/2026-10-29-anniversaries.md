# 纪念日按公历每年重复，各自设提前多久提醒，可数在一起的天数，并与礼物和日记相连

- 状态：提议
- 日期：2026-10-29
- 决策者：Ray
- 范围：领域
- 关联：依赖 space-records；依赖 two-clocks；依赖 wishes-and-gifts；依赖 meeting-plans

双人空间里记重要的日子：生日（标明是谁的）、在一起的日子，以及自己命名的其他纪念日，都按公历每年重复。每人对每个纪念日各自设提前几天提醒，到了提醒期首页小条显示一行，例如"TA 的生日还有 5 天 · 看看 TA 的心愿"，当天显示"今天是 TA 的生日"。纪念日可以打开"第 N 天"计数（在一起的日子默认打开），第 100、200……天以及第 520、1314 天像周年一样提醒。送礼时场合可以选具体的纪念日，礼物墙能按它筛选；纪念日页列出历年的这一天，能点到那天的日期页并看到那年为它送的礼物。纪念日也显示在见面计划的按月日历里。

本文不负责：农历（用户 2026-10-29 决定先只做公历）；邮件或推送提醒（阶段 4）；节日（如情人节）的内置列表；一次性的事件（属于见面计划）。共用规则见 space-records。

## 背景与问题

异地时，重要的日子既是盼头也是压力：生日礼物要提前几周寄，周年那天不能见面也想有点仪式。路线图原把纪念日排在第二批；用户于 2026-10-29 决定提到第一批一起设计，因为它和见面日历、首页小条、礼物的场合都有交集。用户确认这个功能要做到四件事：不忘记重要的日子、看到在一起多久了、和送礼连起来、回看历年的这一天。

## 决策依据

1. 重要的日子提前出现在首页，异地寄礼物来得及；两人需要的提前量不同（用户 2026-10-29 选择各自设，默认 7 天）。
2. 能看到在一起多久了，整数日子有仪式感，但首页不每天占位（用户 2026-10-29 选择纪念日页常显示、整数日上首页）。
3. 纪念日、心愿与礼物连起来：快到时能顺手去看心愿单，礼物能标明为哪个纪念日送（用户 2026-10-29）。
4. 能回看历年这一天的日记与礼物（用户 2026-10-29）。
5. 日期两人都能纠正，名称归记的人（用户 2026-10-29）。
6. 不新增依赖，先只做公历（用户 2026-10-29）。
7. 共用规则沿用 space-records；首页位置由 two-clocks D4 给出；日历由 meeting-plans D6 给出。

## 决策

### D1：三种纪念日，都按公历每年重复

| 种类 | 必填 | 说明 |
| --- | --- | --- |
| 生日 | 是谁的（A 或 B）、月、日 | 年份可选；有年份时显示"28 岁生日" |
| 在一起的日子 | 年、月、日 | 每个双人空间至多一个 |
| 其他 | 名称（最多 30 字）、年、月、日 | 例如"第一次见面""认识的日子" |

每个纪念日可加备注（最多 200 字）。都按公历每年在同月同日重复；2 月 29 日的纪念日在平年按 2 月 28 日。

作者是记它的人：名称、备注、种类与生日归属只有作者能改，删除也只有作者能做（space-records D3、D6）。日期两人都能改，作为动作记录（space-records D4）。

原因：依据 5、6。

### D2：第 N 天与整数日

每个纪念日有"显示第 N 天"的开关（需要有年份）：在一起的日子默认打开，生日默认关闭，其他默认关闭。开关两人都能切换（动作）。打开时纪念日页常显示"在一起第 785 天"；纪念日当天算第 1 天，按查看者当地的今天计算。

**整数日**：打开计数的纪念日，第 100、200、300……天以及第 520、1314 天是整数日。整数日和每年的周年日一样按 D3 提醒、在日历里标出。

原因：依据 2。

### D3：提醒是每人各自的设置，到了提醒期首页出现一行

每人对每个纪念日各自选提前几天提醒：不提前（只在当天）、1、3、7、14、30 天，或不提醒。这是个人设置，不是空间记录，对方看不到。默认 7 天；自己的生日默认只在当天。

在某个纪念日（周年日或整数日）的提醒期内，首页小条显示一行（two-clocks D4）：

| 情况 | 文字 |
| --- | --- |
| 提醒期内，对方的生日 | "TA 的生日还有 5 天 · 看看 TA 的心愿"（链到对方的心愿单） |
| 提醒期内，在一起的日子或其他 | "在一起 2 周年还有 5 天"、"第 1000 天还有 5 天"，附"看看 TA 的心愿" |
| 提醒期内，自己的生日 | "你的生日还有 5 天"，不附心愿链接 |
| 当天 | "今天是 TA 的生日"、"今天是在一起 2 周年"、"今天是在一起第 1000 天" |

首页这一行一次只显示一个纪念日：当天的优先，其次日期最近的，同一天多个时按生日、在一起的日子、其他的顺序。提醒期与"今天"都按查看者当地日期计算。

原因：依据 1、3。

### D4：礼物的场合可以是一个具体的纪念日

wishes-and-gifts 的"场合"改为二选一：

- 一个具体的纪念日，例如"TA 的生日""在一起的日子"；
- 或一个通用场合：节日、见面、没什么理由。

礼物墙可以按某个纪念日筛选。礼物记下纪念日的 ID 与当时的名称；纪念日被删除后，礼物上保留当时的名称，不再链接。

原因：依据 3。原来的"生日""纪念日"两个通用场合由具体的纪念日取代，礼物能回答"哪年的哪个生日送的"。

### D5：纪念日页回看历年的这一天

纪念日页列出从起始年份（生日没有年份时，从这个纪念日被记下的那年）到今年的每一年：那年的日期（点开进入日期页 `/days/:date`，看两人那天的日记）、那年场合为这个纪念日的礼物（按礼物日期的年份归入）。日期页按共享规则显示，没共享或没写的日子照常显示空页。

原因：依据 4。只链接，不复制日记内容。

### D6：纪念日显示在见面日历里

见面计划页的按月日历（meeting-plans D6）同时显示纪念日：每年的周年日与打开计数的整数日，用与见面不同的样式标在那一天，点击进入纪念日页。

原因：依据 7。一个日历看全两人的重要日子。

### D7：动作清单

| 动作 | 对象 | 谁能做 |
| --- | --- | --- |
| 改日期 | 纪念日 | 两人 |
| 打开 / 关闭第 N 天 | 纪念日 | 两人 |

名称、备注、种类、生日归属的修改与删除由作者做。提醒设置是个人设置，不是动作，也不计入对方的未读。本功能没有私密状态。

## 数据与模块

- **表**：
  - `anniversaries`（共用列见 space-records）：种类、生日归属、名称、备注、年（可空）、月、日、显示第 N 天及最后修改人与时间；每个空间至多一个"在一起的日子"由部分唯一索引保证；
  - `anniversary_reminders`：`user_id`、纪念日、提前天数或不提醒；只返回给本人。
  - wishes-and-gifts 的 `gifts` 把场合改为"通用场合或纪念日 ID 加名称副本"。
- **服务端**：`apps/api/src/anniversaries/` 服务，只经 `space-records` 写入；计算下一个周年日、整数日与首页那一行；为礼物墙提供纪念日列表。
- **网页**：`apps/web/src/anniversaries/`（纪念日列表与详情、提醒设置），导入 `space-common` 与 `api`；首页那一行由 `two-clocks` 经 `api` 读取，日历中的纪念日由 `meetings` 经 `api` 读取，模块之间互不导入。
- 迁移与新表在实现 PR 中生成；本 ADR 采纳即视为预先批准。

## 失败与恢复

| 情况 | 结果 | 恢复 |
| --- | --- | --- |
| 两人同时记"在一起的日子" | 唯一索引只允许一个，后到的被拒，提示已有 | 打开已有的那个修改日期 |
| 非法日期（2 月 30 日；生日以外没有年份） | 请求被拒 | 改正后提交 |
| 删除纪念日时有礼物以它为场合 | 删除照常，礼物保留名称副本 | 无需处理 |
| 改日期时刚好解绑 | 写入被拒（space-records D5） | 重新绑定后再改 |

## 不变量

1. 纪念日按公历每年重复，2 月 29 日在平年按 2 月 28 日；每个空间至多一个"在一起的日子"。
2. 纪念日的日期两人都能改并记录操作人；名称、备注、种类与生日归属只有作者能改。
3. 第 N 天以纪念日当天为第 1 天，按查看者当地日期计算；整数日是第 100 的倍数天及第 520、1314 天。
4. 提醒设置只属于本人，只返回给本人，修改它不产生对方的未读。
5. 首页至多显示一个纪念日：当天的优先，其次最近的；对方的生日与共同纪念日附心愿单链接，自己的生日不附。
6. 礼物的场合是一个通用场合或一个纪念日；纪念日删除后礼物仍显示当时的名称。
7. 纪念日页的历年列表只链接日期页，不复制或泄露未共享的日记。

## 备选方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| **支持农历** | 适合过农历生日的家庭 | 需要农历换算依赖与闰月规则（依据 6）；等真有农历的日子要记再加 |
| **纪念日只有作者能改** | 符合"文字归作者" | 记错日期时对方不能纠正（依据 5） |
| **首页一直显示"在一起第 N 天"** | 每天都看得到 | 小条更挤；用户选择只在整数日上首页（依据 2） |
| **只有在一起的日子能计数，只算每 100 天** | 更简单 | 用户要求可选开启，并要 520、1314 |
| **两人共用一个提前天数** | 设置更少 | 送礼的人需要更早知道，过生日的人不需要（依据 1） |
| **统一提前 7 天** | 不用设置 | 国际快递可能来不及（依据 1） |
| **场合只保留通用分类** | 不改礼物的设计 | 回答不了"哪年的哪个生日送的"（依据 3、4） |
| **纪念日单独一个日历** | 互不干扰 | 两人的重要日子分在两处看（依据 7） |
| **首页同时显示所有快到的纪念日** | 不会漏 | 小条变挤；最近的那个最重要 |

## 风险与代价

- 两人当地日期不同，可能一人看到"今天是"而另一人还是"还有 1 天"；这是两地本来的情况。
- 生日没有年份时历年列表从记下的那年开始，更早的年份看不到。
- 礼物场合从"类别"改为"类别或纪念日"，wishes-and-gifts 同步修改；两份 ADR 一起评审，不存在旧数据。

## 未解决的问题

- 节日（情人节、七夕）是否内置。默认做法：不内置，需要时作为"其他"纪念日自己记（七夕是农历，随农历一起考虑）。

## 落地顺序

1. **本 ADR 采纳**：与 space-records、two-clocks、wishes-and-gifts、meeting-plans 一起评审，第一批设计完后合并（用户 2026-10-29 决定纪念日提到第一批）。
2. **实现**：在心愿与送礼之后（它带来 space-records 共用部件，且场合依赖本文的纪念日）；可与见面计划先后实现，后实现的一方接入日历。一个 PR 完成迁移、契约、服务、网页模块、首页那一行与依赖方向规则。
3. 实现后本文转为"已实现"，路线图与 README 状态行同步。

## 验收标准

- 2 月 29 日的纪念日在平年显示于 2 月 28 日；第二个"在一起的日子"被拒（单元测试与 DB 测试，不变量 1）。
- 对方能改日期、不能改名称；历史记录改日期的动作（API 测试，不变量 2）。
- 第 N 天与整数日在跨年、闰年、两人不同时区下正确（单元测试，不变量 3）。
- 提醒设置只出现在本人的响应里，修改后对方没有未读（API 测试，不变量 4）。
- 首页那一行在多个纪念日同时进入提醒期时只显示一个且顺序正确，自己的生日不带心愿链接（单元测试与组件测试，不变量 5）。
- 礼物以纪念日为场合，删除纪念日后礼物显示原名称（API 测试，不变量 6）。
- 历年列表的链接指向日期页，未共享的日记不出现在纪念日页的任何响应里（API 测试，不变量 7）。
- 验证某条不变量的测试标题带 `[adr:anniversaries#<编号>]`。
