已由自动测试覆盖、这里不再重复的（Chromium、WebKit，真实 API 与一次性 PostgreSQL）：

- `e2e/book.spec.ts` 覆盖布局与导航：
  - 宽窗口 1280×800 与窄窗口 375、320 px 下，书页里的文字和控件不越过中缝、书底或窗口边，窗口不横向滚动，长文（400 个字母的长词、长链接）也一样。
  - 「目录」书签始终完整在屏内，用键盘可以打开，Tab 在目录里循环，Escape 与浏览器后退能关闭。
  - 主页不出现日记文字，也不请求日记。
  - 从未绑定、绑定但没设作息、解绑后，两人的主页与目录条目各自正确。
- `e2e/book.spec.ts` 也覆盖右页列表：
  - 两人跨几天写的日记按日期从新到旧排列，冻结的共享保持冻结时的文字。
  - 空列表有提示；跳到没人写的日期时什么也不创建。
  - 离线与接口出错时显示失败行与「重试」，凭不可信的列表亮起的圆点和 ↓ 会熄灭。
  - 列表和日期跳转可以只用键盘操作。
  - 窄窗口的 ↑/↓ 在屏内，能跳到尚未加载的日期。
  - 断网时左页显示保存在本机，右页不显示这段文字。
- `e2e/workspace.spec.ts`：选日期、后退恢复日期与列表位置、深链接、窄窗口单页往返。
- `e2e/feed-unread.spec.ts`：宽窗口的 ↑/↓ 跨 50 天未加载的日期，左页编辑器不失焦。
- `e2e/reading.spec.ts`、`e2e/day.spec.ts`、`e2e/diary.spec.ts`：在屏上约一秒才计已读、日期页、保存与离线恢复。
- jsdom 组件测试（`apps/web/src/**`）：折叠「正在写」与刷新、滚动锚点、未读按钮的查找顺序、目录的焦点。

## 准备

1. 在 `claude/web-acceptance-0314ec` 分支最新提交上：`nvm use && npm ci`。没有 `.env` 时 `cp .env.example .env`；**不要**设 `HISTORY_IDLE_MS`，这样历史点按真实的两分钟形成。
2. `npm run db:up`，然后 `npm run db:migrate`。
3. `npm run dev:oidc`、`npm run dev:api`、`npm run dev:web` 各开一个终端，打开 <http://localhost:5173/>。
4. 两个浏览器（或同一浏览器的两个独立配置，如 Chrome 的两个用户；无痕窗口与普通窗口也可以），分别用「开发登录」登录 A、B。A 在主页点「生成邀请链接」，B 打开链接，保持默认范围（全部历史与以后）接受。这样两人共享全部日期。
5. 准备很多日期：在 B 的页面打开开发者工具的 Console，粘贴下面的代码。它给 B 建过去 60 天的空日记，和测试用的接口相同：

   ```js
   const tz = Intl.DateTimeFormat().resolvedOptions().timeZone;
   for (let i = 1; i <= 60; i++) {
     const d = new Date();
     d.setDate(d.getDate() - i);
     await fetch('/api/diaries', {
       method: 'POST',
       headers: { 'content-type': 'application/json' },
       body: JSON.stringify({ timezone: tz, date: d.toLocaleDateString('sv') }),
     });
   }
   ```

6. A 在 `/days` 用「跳到日期」打开 60 天前、30 天前和昨天，点「写这天」，各写两三段话；30 天前那篇写长一些（粘贴十几段）。写完等两分钟以上，让历史点形成。
7. 窄窗口：开发者工具的设备模式（Toggle device toolbar），宽度设成 375 与 320。也可以直接把窗口拖窄到 56rem（约 900 px）以下。

## 已知情况

- API 进程刚启动后，每人第一次找未读要几秒（实测三年数据缓存为空约 6 秒，见[耗时实测](./book-frontend-next-unread-2026-11-01.md)），这段时间圆形按钮不出现。处理方案是提议中的 ADR（PR #55），本轮不改。
- 列表不会卸载离开视野的长文，打开很久后会占更多内存；右页的新内容靠 45 秒刷新，不是推送。其余见 `apps/web/README.md` 的 Known limitations。
