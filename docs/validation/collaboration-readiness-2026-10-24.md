## 1. 结论与进入下一阶段的条件

建议结束本轮技术可行性验证，进入技术栈确认与开发流程规范阶段，随后开始正式实现。

已有证据支持：浏览器可提供字符级穿插编辑，服务端可执行不可变作者权限，本地未同步操作可在断网/刷新后恢复并合并，PG 提交和幂等可避免确认丢失后的重复写入。原型不是可上线产品，也未将实验序列内核自动选定为最终生产实现。

## 4. 关键要求与验证结果

| 要求 | 实际验证方式 | 判断 |
| --- | --- | --- |
| 只能改自己的文字 | 绕过 UI 直接删除/替换对方 ID；伪造 author/actor；撤销对方操作；HTTP 会话身份测试 | 服务端拒绝，正文/版本/outbox 不变 |
| 不因重连丢字 | 已缓存日记断网续写、IndexedDB 落盘、离线刷新、另一方在线插入、恢复网络 | 本机 pending 与远端操作合并，已输入内容保留 |
| 不被旧状态回退 | 有待发文字时读取旧快照和乱序日志；观察最终正文与浏览器编辑器 | 旧读取日志并集，不覆盖全文或清空 pending |
| 确认丢失不重复 | COMMIT 成功后丢 ACK、重试、20 路相同操作并发、8 路依赖批次并发 | 稳定 ID 幂等，只提交一次 |
| 保存状态真实 | PG 提交前失败、文件/IndexedDB 适配器故障 | 未确认内容保留，状态不宣称已保存 |
| 进程崩溃恢复 | SQL 已写入但 COMMIT 前 SIGKILL；COMMIT 后 ACK 前 SIGKILL | 前者回滚可重试，后者新服务读回原操作 |
| 多标签页不丢本地草稿 | 同账号两个标签页并发写入同一个 IndexedDB journal，再刷新/同步 | 事务内合并，不最后写入覆盖；旧快照不能复活已确认/已拒绝操作 |
| 对方编辑位置 | WebSocket 在线位置、前方插字、断开页面 | 光标按稳定标识移动，离开后清除；不进入正文日志 |
| 删除跳过对方 | 桌面键盘、长按重复事件、移动端 beforeinput 事件 | 首次只跳转；混合选区删除/替换/剪切阻止；连删到边界停止 |
| 中文 composition | CDP 开始/提交/取消、期间对方插入、选中对方文字后 composition | 未确认拼音不共享；完成只新增一次；取消不产生幽灵文字；越权替换拒绝 |
| 字符完整性 | 跨操作重音符、emoji 家庭、肤色、旗帜、组合作者边界 | 按整篇文本 grapheme 处理，不仅按单次输入切分 |
| 剪贴板归属 | Chromium 原生剪贴板粘贴 HTML 作者标记、复制含光标的选区；三引擎 handler fixture | 只取纯文本，作者是输入者，复制不带光标名字；混合剪切不改正文 |
| 高延迟连续输入 | 每个 HTTP 请求额外延迟 250ms，连续键入，观察对方显示和本地光标 | 批量提交后保留文字与选区，延迟样本见下节 |

权限身份来自测试 resolver，尚非 Google 登录；验证的是可信身份进入权限层后的行为。生产 session、Google 身份绑定和空间成员校验仍需正式实现与验收。

## 5. 验证中发现并处理的问题

1. **字符边界不能按每次输入独立切分。** 重音和旗帜可能由后续操作补成。底层改为稳定 Unicode scalar ID，编辑器在整个可见文本上按需计算 grapheme。跨作者共同形成的 grapheme 采用保守保护，部分修改被阻止；正式设计需要记录这一罕见边界的交互说明。
2. **多标签页整份覆盖 journal 会造成风险。** IndexedDB readwrite 事务内合并 committed/pending/recovery，并通过 BroadcastChannel 吸收新操作；已确认或已拒绝操作不会被迟到的快照重新变成 pending。
3. **逐条网络往返不适合连续输入。** 加入最多 64 条、带依赖顺序的原子批次。任何一条非法则整个批次不提交；合法离线链和丢 ACK 重试有独立 PG 测试。
4. **整篇反复计算编辑边界会卡顿。** 缓存当前文档与偏移，按需定位 grapheme，避免每次按键完整生成所有字符组；子节点顺序在插入时维护，不每次遍历重新排序。
5. **逻辑时钟不能由客户端任意跳跃。** 服务端拒绝超出当前因果进度的计数，避免恶意跳到上限后阻止另一人继续输入。已有核心与 PG 回归测试。
6. **浏览器自动化事件有平台差异。** Firefox 会清空不可信 ClipboardEvent 构造器中的数据；三引擎 handler 测试明确使用 fixture，另加 Chromium 原生剪贴板用例。没有把 fixture 的通过当成所有 OS 剪贴板都已验证。

以上改动均留在 prototypes 下；没有把诊断编辑器包装成正式日记产品。

## 6. 性能与网络样本

### 本地长文

环境：本机 headless Chromium、内存后端；加载完成后冻结网络同步，连续输入 20 个字符，保留全部样本。

| 正文长度 | 加载至原型可见正文 | 同步输入处理 p95 | 最终新增文字 |
| --- | ---: | ---: | --- |
| 10,000 字符 | 212ms | 8ms | 全部保留 |
| 100,000 字符 | 638ms | 79ms | 全部保留 |

这里测量的是编辑处理函数耗时，不是 OS 键盘到屏幕完成绘制的端到端延迟，也不是手机性能承诺。样本每种长度仅 20 次；加载是本机测试路径，不含真实跨国网络。原始样本见[performance.json](./artifacts/collaboration-2026-10-24/performance.json)。

早期全量计算版本在十万字下出现过 161ms 的处理样本；这促使本轮调整边界计算和缓存。不同轮样本量不同，不据此声称精确百分比加速。

### 对方可见延迟

Chromium 连续输入 20 个字符，每个 API 请求人为增加 250ms 等待；观察另一浏览器看到字符的时间。

| 后端 | p95 | 最大值 |
| --- | ---: | ---: |
| 内存 | 986ms | 996ms |
| 真实 PG | 1013ms | 1017ms |

延迟覆盖的是该受控场景中的 HTTP 等待和同步过程。WebSocket 本身仍在本机运行；不能称为“真实中美 RTT 500ms 已验收”，也没有验证所有网络带宽/丢包组合。

## 7. 仍不应直接上线的原因

- **阅读滚动尚未独立验收**：光标定位已验证，长文阅读时的内容滚动锚定仍需正式界面测试。
- **真机尚未验收**：实体 iPhone/Android 的 OS 中文输入法、候选词替换、切后台、强制退出、低内存与网络切换；Linux WebKit 不替代 macOS/iOS Safari。
- **原型不是最终序列实现**：存在完整日志重建与永久墓碑；需审查序列内核、冻结协议和 IndexedDB schema 版本，确定快照、压缩、升级与旧客户端兼容策略。
- **大操作仍有上限**：单条限制 4096 UTF-16 长度和 4096 删除目标。正式大段粘贴/删除需受限分块、明确事务语义及恢复测试；当前不会把超限操作伪称保存成功。
- **身份为测试 fixture**：正式 Google 登录、会话过期、退出后缓存隔离、邀请与空间边界尚未实现；不能以固定测试 token 部署到公网。
- **生产服务未实现**：多实例房间路由、限流、异常断开超时、监控、数据库维护与备份 worker 仍需工程化。
- **本轮没有验证其他产品模块**：日记日期创建、精确时间元数据、未读进度、Google 导出/备份上传仍以规格为准，不能因协同通过而勾选这些验收。

这些已知事项有明确实现/验收归属，不需要继续用原型代替整个产品开发。正式发布前保留真机和生产集成门槛。

## 8. 下一阶段建议

先确定技术栈和流程，随后开始正式实现。倾向的组合是 TypeScript、React/Vite、ProseMirror、Node 常驻 API/WS、PostgreSQL、IndexedDB 和 PG outbox；其中 React、API 框架、ORM 与认证库只是建议，没有在本轮假装已经集成。

最重要的正式设计决定是：保留“服务端理解并验证每条编辑”的信任边界；编辑器和同步库都不能绕开它。若改为其他协同方案，必须继承本轮性质/攻击测试并重新证明作者保护。

推荐落地的产物是简短 AGENTS.md、模块契约、测试策略、协议/存储 ADR、PR 完成标准及配套检查。先定栈，再写能实际运行的命令和 CI；本轮只给出[准备方案](../implementation-preparation.md)，等待下一步决策。
