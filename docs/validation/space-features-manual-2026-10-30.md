# 心愿、礼物与纪念日手动验证

日期：2026-10-30 写好清单。**状态：未执行，由 Ray 在 PR #48（心愿与送礼）、#50（纪念日）合并前在开发环境执行。** 本文是[心愿与送礼 ADR](../adr/2026-10-29-wishes-and-gifts.md)、[纪念日 ADR](../adr/2026-10-29-anniversaries.md)与[对方当地日期 ADR](../adr/2026-10-30-partner-local-dates.md)落地后的人工走查：两个人各用一个浏览器，B 放在与 A 不同的时区，从界面上把主要流程走一遍。执行人把每格填成"通过"或"未通过：现象"；有未通过时先修复再合并。项目进度只见[开发路线](../roadmap.md)。

已由自动测试覆盖、这里不再重复的：揭晓前收礼人的所有响应与没人准备时相同、揭晓只发生一次、与解绑并发的写入、链接读取只访问公网地址（`apps/api/src/app.wishes.db.test.ts` 等）；2 月 29 日、整数日（含 520、1314）、夏令时与跳过午夜的时区、第二个"在一起的日子"的并发、响应不含对方时区（`apps/api/src/anniversaries/dates.test.ts`、`apps/api/src/app.anniversaries.db.test.ts`）；UTC−11 与 UTC+14 两人的生日与礼物日期（`e2e/anniversaries.spec.ts`，Chromium、WebKit）。

## 准备

1. 在 `feat/anniversaries` 分支（已包含 #48）：`npm run db:up`，然后 `npm run db:migrate`（迁移 `0007`～`0009`）。
2. `npm run dev:oidc`、`npm run dev:api`、`npm run dev:web`、`npm run dev:worker`（链接预览要它）各开一个终端。
3. 两个浏览器窗口（或两个 Chrome 配置），分别用"开发登录"登录 A、B；A 生成邀请，B 接受。
4. A 用平常的时区。B 放到 `Pacific/Kiritimati`（UTC+14）：在 B 的窗口打开开发者工具 → More tools → Sensors，把 Location 下的 Timezone ID 填成 `Pacific/Kiritimati`，整个验证期间开发者工具不要关；或者用 `TZ=Pacific/Kiritimati` 启动一个单独配置的 Chrome。然后 B 刷新首页，让它上报时区；A 的首页两地时间小条显示 B 那边的时间就说明成功。
5. 两人的日期不同时才看得出"按对方的日期"：B 在 UTC+14，A 在北京时间 18:00 以后、或在美国几乎全天，B 已经是 A 的第二天。下面"B 的今天"指 B 电脑上的日期。
