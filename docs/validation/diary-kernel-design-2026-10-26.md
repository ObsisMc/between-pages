## 干净基线

[原始观测](./artifacts/diary-kernel-2026-10-26/baseline-observations.json)；[TAP 输出](./artifacts/diary-kernel-2026-10-26/baseline-results.tap)。17 项检查通过，其中 1 项是仓库未改动检查。

- 在隔离副本中清理删除内容后，测试用私人删除文字不再出现在基线载荷中，当前可见字符 ID、作者和顺序保持一致。
- 200 组可复现 Unicode、碎片化删除和并发样例中检查了 41,812 个相对位置；连续切换 50 轮基线，旧归档保持可读。
- 把干净基线合并进旧实例会保留旧实例的私人删除内容，因此所有当前协同实例必须从基线重新加载。
- 复现了原始重复请求包可能携带私人删除文字的情况：原样中继会泄露，但干净接受状态仍不含该文字。从该状态重新编码的测试增量不含这些内容。
- Yjs 本身会接受符合合并条件的旧更新；共享轮次与同步起点拒绝由应用检查模型承担，不能因 ID 保留而省略。
- 单次约 101,497 UTF-16 单位的内存清理与序列化观测为 5.82ms。该数值不是生产延迟目标，不包含 PG、网络、浏览器或并发负载。

边界：没有真实 PG、WebSocket、IndexedDB、生产编辑器或完整共享集成。作者和授权检查为诊断模型。原字符 ID、时钟及删除长度等结构信息仍保留，不保证隐藏历史编辑规模；写入时间与未读的正式映射还需要集成验证。

## 本地日志及依赖顺序

[最终观测](./artifacts/diary-kernel-2026-10-26/journal-observations.json)；[最终 TAP](./artifacts/diary-kernel-2026-10-26/journal-results.tap)。33 个浏览器场景通过，另有 1 项仓库未改动检查，共 34 项通过。

验证使用真实 Chromium IndexedDB、渲染的 textarea、真实 localhost HTTP 请求、离线模式、连接故障和真实渲染进程崩溃。服务端仍为临时内存模型，不是 Fastify/PG/WebSocket/正式会话。

### 从失败到通过

初版 23 个浏览器场景未使用严格的缺失依赖拒绝规则，不能证明随机 ID 排序下补发安全。补验接入仓库既有 `prototypes/yjs-standard/authority.mjs` 的 Authority.check；原型文件未修改，已知 clientID 作者绑定由测试环境预先登记，不信任请求里的作者。

加入新检查后旧逻辑有 8 项失败，覆盖 UUID 反序、顺序号未持久化、ACK 丢失后越过队首、本地 ACK 事务失败、插入后删除、跨标签依赖、并发发送与长离线依赖链。

失败证据：[旧模型观测](./artifacts/diary-kernel-2026-10-26/journal-before-ordering-observations.json)、[旧模型 TAP](./artifacts/diary-kernel-2026-10-26/journal-before-ordering-results.tap)。修正后最终 33 项场景全部通过，没有将缺失依赖留在 Yjs 等待队列中后仍返回成功。

### 得到的约束

1. 本地写入序号、序号计数递增和 pending 记录同 IndexedDB 事务提交，读取后按序号发送，不按随机操作 ID 排序。
2. 同账号、同日记跨标签页共享 Web Lock；单笔模型等待队首服务器 ACK 与本地原子确认完成后再继续，任何失败停止推进并保留后续内容。
3. 重试保留原 operationId 和原更新字节，同 ID 不同载荷被拒；ACK 与移除 pending 同事务，乱序 ACK 不回退基线或清除后续编辑。
4. 本机落库失败时保留可复制的内存输入，阻止自动加载服务器状态、切基线或发送未落盘操作；存储恢复后可重试原操作。
5. 跨起点切换先查提交回执；已提交但未收到 ACK 的内容不重复进入草稿。转草稿、pending 清理和新基线同事务，查询期间新增 pending 则中止切换。
6. 旧标签页在写事务内重查当前上下文；账户之间本机数据隔离。页面崩溃及持久浏览器配置重启后，已完成本机事务的 pending 可以恢复。

边界：配额不足通过注入 QuotaExceededError 验证；另有真实事务 abort，不代表测试过物理磁盘写满或操作系统断电。只覆盖 Chromium，编辑器为临时 textarea。现有 Authority 是探索原型，不是完成的生产纯文本校验器。

## 不由这些证据证明的事项

- 自动小批发送尚未验证。33 个场景验证的是逐笔确认与本地顺序；后续已确认固定批身份、一个 PG 事务/版本、任一笔失败整批拒绝及无部分成功 ACK，但未补充相应执行证据。ADR 的 Q8 保留批量故障恢复验证与性能参数，不再是失败语义选型。
- 正式 PG 事务、提交后广播、多实例补同步、会话撤销、生产 ProseMirror 绑定以及 Firefox/WebKit 仍须在正式实现中复验。
- 只读历史界面、五分钟分组、两分钟停笔末点、长期保留、跨轮次未读及正文与光标协调是用户确定的规则，本轮未做相关产品验证。ADR 中的输入、远端正文与光标延迟是待测验收目标，既有观测不能证明其达标。
- 观测中的 workspace/repositoryUnchanged 表示各次临时验证结束时没有修改项目文件；本次将文档与既有结果落盘是之后明确授权的操作。
