# 双人每日日记 MVP 功能规格

版本：0.5；日期：2026-10-26；状态：产品规则已按讨论更新，功能以验收证据为准；项目进度只见[开发路线](./roadmap.md)。

## 1. 目标与边界

每人每天有一篇个人日记，未绑定也能写。绑定后，双人空间按日期拼接双方获准共享的日记，底层保留两篇文档的主人、ID 和编辑边界。双方可在对方开放的日记正文中穿插想法，准确区分实际作者。

当前先做桌面 Web，手机浏览器与原生客户端后置（2026-10-24 用户确认），见 [ADR-0006](./adr/0006-formal-stack.md)。不要求每天写，不提供打卡、断签惩罚、回复倒计时或默认公开的已读状态。

MVP 包含：个人日记、固定唯一搭档绑定、邀请、自助解绑与原空间恢复、灵活日期共享范围、冻结与重新开放、双方文字展示及只看本人文字、作者保护、实时协同、未读、离线待同步、Google 可读导出与可恢复备份。

暂不包含：见面计划、愿望清单、赠礼等关系业务的具体实现，图片/附件/语音，复杂排版，独立评论线程或引用回复树，Google Docs 双向编辑，账号删除或删除历史空间的自助流程。首次绑定后更换搭档及误绑纠正也暂不提供，场景与重新评估问题见[未来功能清单](./future-features.md)。共同计划、赠礼等未来数据属于双人空间，解绑归档保留，同人重绑恢复；这不改变个人日记的归属。首版正文采用纯文本与换行，完整离线新建日记不是 MVP 要求。

本次关系 ADR 的独立交付只包含邀请、绑定/解绑、原空间关系记录恢复及范围配置，不包含上述 MVP 全部能力。配置保存不等于正文共享，界面须说明“范围已设置，日记共享尚未开放”；个人日记、授权版本、冻结/重开和协同需后续内核 ADR 设计及验收后接入。接入时已有配置仅供本人参考，实际发布前须明确确认。

## 2. 核心不变量（已确认）

| 编号 | 规则 |
| --- | --- |
| INV-01 | 每个有效字符只有一个不可变 authorId；ownerId 表示日记归属，作者仅为主人与固定搭档，不因解绑改变。 |
| INV-02 | 新增文字归当前经过认证的用户，不继承光标旁文字的作者。 |
| INV-03 | 用户只能修改、删除自己写的文字，主人也不能改对方文字；历史版本只读，不支持回滚，后端执行相同保护。 |
| INV-04 | 插入对方文字中间不改变已有文字作者和相对顺序；各视图用稳定位置定位。 |
| INV-05 | 同一主人、同一 diaryDate 最多一篇个人日记；日期与归属不随绑定变化。 |
| INV-06 | 合法编辑最终收敛，旧全文不得覆盖新输入；权限变化后待发原文保留恢复草稿。 |
| INV-07 | 已保存只代表 PG 提交，已备份只代表指定授权版本的真实备份完成。 |
| INV-08 | 对方只读获准版本和主人与固定搭档的文字；停止共享冻结，再次开放须本人确认后切到最新版本。 |
| INV-09 | UTC 时间点与 diaryDate 分开保存，日期共享按 diaryDate 判断，不按 createdAt 判断。 |
| INV-10 | 首版每个账号首次绑定后搭档固定；解绑后只能与原搭档恢复唯一空间，不自动重新开放日记。 |
| INV-11 | 每篇日记只含主人与固定搭档的文字；范围、私密日记信息和阅读过滤只对本人可见。 |

作者不是段落或回复树身份。comment 是穿插正文，隐藏不改写或删除字符；归档保留原作者、顺序、时间及冻结版本。

## 3. 用户、关系与共享 [AUTH / SHARE]

### 3.1 身份和绑定

应用用户有独立稳定 userId，Google 身份按 issuer + subject 绑定，不以邮箱作为永久身份；认证见 [authentication-and-sessions](./adr/2026-10-24-authentication-and-sessions.md)。登录与 Drive 授权分离，拒绝 Drive 不阻止登录或写作。

首版每个账号只对应一位固定搭档。首次双方确认绑定后，双方搭档身份保留，解绑也不能与第三人重新绑定。首次双方确认才创建永久双人空间，每个账号至多属于这一个空间；原双方重绑复用原 spaceId 并建立新 periodId。双方权限平等，不设管理员。未绑定或解绑后仍可独立写个人日记。

邀请七天有效、可撤销、一次性，不指定邮箱；用户手动分享链接，持有者登录、核对身份并明确接受才绑定。每人同时一个有效邀请，轮换立即废止旧链接；成功绑定使双方其他未使用邀请失效。任一方已有当前搭档时拒绝绑定；打开链接、预览和登录不预留或自动绑定。接受时还须检查双方既有永久空间，任何一方已确定另一位搭档都拒绝；并发首次绑定至多确定一对。确认页须说明首版绑定后不支持更换搭档，并让双方核对账号；当前没有误绑纠正入口。

任一参与者可二次确认后单方面解绑，无需对方批准。解绑关闭当前期间、解除双方绑定、冻结 live 日记共享，保留空间和业务数据。双方可看归档，固定搭档身份不清除，第三人不能访问或加入。归档计划/赠礼等只读，原双方重绑后才恢复相应业务操作。

### 3.2 各自选择共享日期

双方分别决定自己的范围，不要求互相开放同样多的日记。日历支持单日、多个不连续日期/区间、全部历史与未来、从某日起持续共享及排除日期；端点包含当天，排除优先。判断使用固定 diaryDate，与实际创建时间、当前查看者时区无关。已选日期以后补写日记，也按同一范围自动共享。

首次邀请/接受默认“全部历史＋以后持续共享”，必须本人确认，可修改或选择暂不开放。发起者先确认自己的范围再生成邀请，接受者确认自己的范围再绑定；双方只看自己的设置。

同人重绑先恢复关系和原空间，旧共享范围仅供本人参考，不自动重新生效。每人分别确认是否开放，可以仅恢复关系、暂不开放，之后独立调整。扩大范围或重新选中日期前，明确提示将开放最新版本，可能包括分开期间新增或修改的内容。

### 3.3 停止共享与再次开放

取消已共享日期或解绑，保留最后已提交的授权版本，对方仍可只读查看，停止收到后续新增、修改和删除。列表标“已停止共享，内容不再更新”。取消未创建或从未共享的日期，不创建冻结占位。

再次确认开放同日，切换到当前最新的主人＋这位搭档版本并持续更新，可以包含分开期间的修改或补写；不覆写个人日记或旧冻结记录。该规则替代讨论早期的“分开期间永久不开放”。普通列表显示当前 live 或最后 frozen 版本，不默认把历次版本展开成重复日记。

日期选择描述“哪些日期正在更新”，不是对方全部可读历史。停止共享不承诺收回对方已复制、导出或持有的旧版本。共享范围修改、解绑和写入竞争时，以事务提交的授权版本边界为准。

### 3.4 权限与可见性

本人可看个人最新日记，包含本人最新正文与固定搭档保留的文字，主人仍只能修改自己的文字；搭档只能看唯一空间获准共享的版本。解绑后，本人在个人入口继续修改自己的文字，不改变对方的冻结副本，也不恢复对方写权。AB 历史归档使用当时冻结的 A＋B，不能用 A 最新全文替换。首版没有历史搭档切换或按搭档分支的正文；第三人不能获取正文或原始协同载荷。

对方可知已收到的日记和 frozen 状态，不能查询主人的具体范围/排除日期、未共享日记存在与数量、阅读过滤行为。未开放日期与没有日记一样，不显示私密锁定占位；搜索、列表计数、错误、未读和通知执行同一边界。

所有 HTTP、订阅、协同写入、导出与备份状态按资源的个人/空间/期间/共享版本授权，ID 本身不是凭证。冻结后旧写入被拒；再次开放的新 epoch 不能使旧队列自动获得新权限，待发原文保留可恢复草稿。服务器不能把未授权全文发出后仅由客户端隐藏。

详细状态机、数据与实现依赖见 [spaces-and-invitations](./adr/2026-10-25-spaces-and-invitations.md)，该技术设计已采纳，尚未实现。

## 4. 日期与创建 [DATE]

1. 本人点击“写今天”，服务端用当前 UTC 时间和请求中的有效 IANA 时区推导 diaryDate，不依赖设备时钟。
2. 查找当前会话用户该日个人日记，存在则打开，否则创建；不要求绑定，不接收客户端 ownerId。
3. PG 对 `(ownerId, diaryDate)` 唯一，重复点击和并发打开同一 diaryId；不同用户同日各一篇。
4. 跨午夜继续写、换时区、另一人访问或绑定变化均不重算原 diaryDate。
5. 双方当地日期可以不同；同日双人页面只拼接可读的两篇，保留各文档边界。
6. 可打开/补写过去日期，明确创建缺失日记，首版不提供未来日期创建。共享范围可选未来日期，但不提前生成日记。

记录 createdTimezone 解释日期来源。时区默认设备值，可在设置修正；无效 IANA 时区明确拒绝。创建时刻与记录日期分别保存，例如今天补写十月五日的日记，按十月五日选择决定共享。

离线可读本机已缓存且有相应权限上下文的日记并续写；尚无法确认“写今天”的目标时不伪造已创建，联网后再确认。服务端拒绝旧授权时保留本地恢复草稿，不把它当作共享正文。

## 5. 正文与作者归属 [EDIT]

### 5.1 自由插入

光标可位于任意用户可感知字符的边界，不要求整段。可在对方句子、对方插入内容中继续输入。正常输入、回车、粘贴均归当前用户。粘贴只取纯文本，不接收可伪造作者的富文本元数据。单次粘贴不超过约 30 万字（1 MB），超过时提示分段粘贴，不丢失剪贴板内容。

例：A 写“今天很累，但是想到你就开心了。”；B 在逗号后写“抱抱！”；顺序为 A“今天很累，”、B“抱抱！”、A“但是想到你就开心了。”。A 的前后部分都仍归 A，无需额外原句 ID。

存储可合并作者与写入元数据均相同的相邻文字区段，但不能因合并丢失时间或未读定位信息。空格和换行也有作者，不存在无主的可编辑字符。

### 5.2 修改、删除与选区

- 用户可删除自己的文字；替换自己的文字表现为删除旧内容、插入当前用户的新内容。
- 光标前是对方文字时按 Backspace：跳过连续的对方文字，停在向前最近的己方文字末尾；本次不删字。
- 光标后是对方文字时按 Delete：跳过连续的对方文字，停在向后最近的己方文字开头；本次不删字。
- 对应方向没有己方文字，停在文首或文末，不删除内容；方向键、点击与触控移动不受作者限制。
- **实施默认**：长按连删到达对方文字时执行跳转并停止本次连删，需要松开并重新按键，避免无意删去远处己方内容。
- 非空选区含对方文字时，阻止删除、剪切及输入/粘贴替换，保留原文并轻提示。复制允许，不能悄悄只删己方部分。
- 空选区粘贴允许；仅含自己文字的选区替换允许。因并发插入导致选区出现对方文字时，修改不得误伤新出现的对方内容。
- 撤销与重做只影响当前用户自己的操作，不能删除或重写对方文字。不能通过撤销把对方后来插入的内容一并移除。
- 拖动文本首版禁用，避免隐式跨作者剪切；移动自己的文字可用剪切粘贴，粘贴记为新写入。

### 5.3 输入法与字符边界

中文输入法 composition 尚未确认的拼音、候选字只在本地显示；确认后的正文才参与共享。远端更新不能中断输入法或把合成中的文字发给对方。

“字符”按用户可感知字符处理：不得拆开 emoji、肤色修饰、组合音标或代理对。协同库内部 UTF-16 索引与编辑器边界之间必须适配。换行统一规范，输入法、虚拟键盘删除和系统替换都走作者保护规则。

### 5.4 显示

正文通过两种可读的字体颜色区分作者，统一背景；默认不用作者底色。可点击文字查看作者和时间，并提供名字图例，不能只依靠颜色识别。颜色映射按稳定 userId 保存，双方设备上同一个人的颜色一致。

**已确认**：日记文字作者只包含主人与固定搭档，不提供 partner 选择器。绑定中和解绑后均可“只看我的文字”，按当前查看者 authorId 过滤，包含写在对方日记里的本人文字；过滤只读，不改数据、不通知对方。恢复完整的当前作者视图且具备相应权限后才能编辑，归档始终只读。个人入口与冻结归档分别寻址；个人入口可修改自己的最新文字，冻结归档整体只读。

### 5.5 历史版本只读

**已确认（2026-10-26）**：历史版本仅供只读查看，首版不支持整篇或按作者回滚，主人和搭档均无例外。不提供“恢复此版本”或以历史状态覆盖当前正文的入口。

主人可查看本人日记的已提交历史；搭档仅可查看各获准共享轮次的起点与该轮后续版本。重新开放不补授私人期间的历史，已获准冻结记录继续保留。浏览历史不改变当前正文、作者、共享状态或个人撤销栈。复制历史文字后粘贴仍属于当前用户的新输入，遵守作者保护。

历史从当前日记进入，采用右侧按日时间列表，最近在前、分批加载；选择后只读预览完整正文、保留原作者颜色，时间按查看者本地时区展示。无可查看历史时显示空状态。预览时收到新编辑不自动切换，只提示当前正文有更新；返回当前时恢复位置并保留待发输入，停止共享的搭档仍返回只读冻结正文。

持续编辑每五分钟形成一个历史点，取组内最后已提交版本；连续两分钟没有正文提交，补最后一个点，同版本不重复。以服务端提交时间为准，双方正文编辑均参与停笔判断，光标不参与；历史点引用已有提交，不延迟保存。开放、停止共享和重开独立成点，不跨私人/共享边界合并。列表条目、数量与修改者均按权限生成，不泄露私人活动；首版逐字差异高亮后置。历史点及获准冻结记录长期保留，不自动过期，压缩不得破坏正文、作者、时间和获准历史重建。具体设计见[内核 ADR D6](./adr/2026-10-26-diary-collaboration-kernel.md#d6历史版本只按已有授权读取重开不补授私人历史)。回滚作为未来待评估功能记在[未来功能清单](./future-features.md)，不预建恢复接口或权限例外。

## 6. 实时同步与编辑位置 [SYNC]

双方在线且日记处于 live 共享时，同步获准版本的新增、修改、删除及光标；frozen 不接收后续正文变化。对方光标使用作者颜色和名字；选区可使用临时的淡色选区效果，此效果不作为正文作者底色。

光标基于稳定相对位置或等价机制定位，不能只发送容易因插入失效的整数下标。网络断开后标记离线，过期的光标状态清除；光标移动不修改正文、不产生未读、不进入备份。

正文与光标可共用 WebSocket，但分别处理；光标只保留最新位置，不落 PG，不排在正文保存队列后。若位置引用尚未到达的新文字，暂存最新有效位置，等获准正文到达再准确显示。

远端更新不抢焦点、不强制滚到对方位置，尽量锚定当前阅读内容。光标在同一位置并发输入时不保证时间先后排序，但必须保留合法内容并最终一致，不得把普通连续输入拆成不可读的逐字交错；具体冲突排列由协同技术验证确定。

同一账号在多个设备编辑也必须合并，不能互相覆盖；作者相同，设备会话不同。**实施默认**：只展示另一位成员的光标，多个会话可区分为手机／电脑；不把自己的另一个设备冒充对方。

## 7. 本地保存、持久化与恢复 [SAVE]

编辑立即显示；随后写入本地持久化待发送队列，再同步到服务端。明确区分本地尚在写入、仅本机保存/等待同步、已保存到服务器、保存失败。不能在仅进入服务端内存或广播给另一设备时显示已保存。

本机采用应用管理的 IndexedDB 日志：原操作 ID/更新、持久化顺序、待确认内容与回执分别明确记录，顺序分配与 pending 写入同事务，确认与移除 pending 同事务，同账号同日记跨标签页共用发送锁。本地未落盘时保留可复制原文，阻止自动重载和基线切换；跨起点转草稿前先查询提交结果，避免重复恢复已保存内容。

网络按顺序自动小批发送：第一笔本机落库后立即发送，等待确认期间继续逐笔记录输入，当前批确认落库后发送已积累的下一批，不为凑批增加等待。首次发送前持久化固定 batchId、上下文及有序成员，重试不重新打包；每笔操作 ID、原更新和时间不变。一个新批对应一个 PG 事务和一个版本，任一笔失败整批不提交，无部分成功 ACK；批回执与移除对应 pending 同本机事务。批量故障恢复仍待验证，五分钟历史分组不影响实时保存。

服务端完成权限校验、数据库持久化及待备份任务登记后才确认写入。未持久化内容不作为已提交内容广播；操作 ID 用于重试去重，重复消息不产生重复文字。

断线重连按编辑操作或协同增量合并，禁止用旧版服务器全文覆盖本地正文。服务端重启、重复确认、乱序消息、同时编辑均不得静默回退合法输入。

本地持久化失败（空间不足、不可用）必须提示，不能宣称“已保存到本机”。用户清理站点数据、隐私模式失效或设备损坏前未上传的文字无法保证恢复；发现失败时保留当前可见内容并提供复制/下载。

权限变化、过期客户端或非法写入可能被拒绝。拒绝时不得把未确认的内容静默抹去；保留可复制的恢复草稿，说明原因并按失败分类处理。该草稿不伪装为已提交的共享正文。不能承诺故障不存在，必须保证状态真实、无静默丢字。

临时网络故障按原批自动重试；登录过期暂停同步，提示登录同一账号；永久校验失败停止该批及后续依赖，不无限重试。提交结果不明时先显示正在确认并查询回执，不重复恢复已提交输入。协议不兼容保留输入并提示升级，不强制刷新。恢复草稿仅查看、复制及本人明确删除，区分插入/删除/替换意图，不自动重放；手动粘贴为本人的新输入。加载当前正文不要求加载全部历史，预览历史不替换当前待发队列。

## 8. 未读与时间 [READ / TIME]

### 8.1 未读

获准版本中的对方新增文字产生未读，私密变化和隐藏/过滤不产生对方未读，不按日记日期判断；在去年日记里插入的新字同样能定位。修改自己的文字产生的新写入对另一方是新内容；仅删除、移动光标、备份或重复同步不制造文字未读。

只有当前活动页面、实际可见区域内的文字满足阅读条件后才标记已读，不能一打开文档就清空全部未读。**实施默认**：连续可见约 1 秒；自身输入不算对方已读，也不为自己产生未读。

未读按文字范围或稳定字符 ID 集合记录，不能只用“最大操作序号”表达：用户可能读到后面的插入而漏过前面的插入。跨设备合并已读范围，互不覆盖；删除后不再可见的文字从待阅读范围排除。

提供有新内容提示及“下一处未读”。只显示当前用户的未读，不向另一方显示已读回执。未读定位标记是临时阅读辅助，不用永久底色区分作者。

重新开放按原字符身份保留已读范围，不重置整篇进度。此前未读的保留文字、私人期间新增且首次获准的对方可见文字仍算未读，不按写入时间早晚忽略；已读旧字保持已读。私人期间写入后又删掉的文字不输出或产生未读；删除后重新输入是新字符。本人的文字不产生自身未读，已删除的文字不留下不可定位未读。

### 8.2 时间

创建、修改、接收、备份等时间点统一 UTC 保存（数据库使用 timestamptz 或等价类型），展示根据查看者的 IANA 时区推导，包含夏令时处理。diaryDate 是独立的 DATE。

**实施默认**：文字记录客户端写入时间 clientCreatedAt、服务端接收时间 serverReceivedAt；前者用于展示用户实际输入时间，后者用于审计，不以设备时钟决定协同顺序或权限。离线补传保留原写入时间，不伪装成重连时才写；设备时间异常时可显示说明。

连续输入可归入同一写入时段；时间粒度不要求每次按键独立显示，同一时段的文字显示该时段的开始时间。**实施默认**：暂停约 30 秒、换日记、移动到新位置或切换编辑模式时开始新的写入时段；具体阈值可调。写入时段只决定显示的写入时间，与网络发送批次、历史点无关。删除/替换保留操作历史，替换的新文字记录新写入时间。

默认正文不逐段展示时间；点文字显示作者和具体时间，跨日期时显示日期，时区需可辨识。

## 9. Google 导出和备份 [GOOGLE]

个人备份与空间导出均需遵守授权版本边界：停止共享不得继续向旧空间输出个人新变化，再次开放也只导出主人与固定搭档的获准文字。备份集成前需明确个人/空间目标及凭据生命周期，不假定重绑可自动复用旧授权；这不撤回已经生成的远端副本。

备份任务绑定明确版本与授权上下文，执行时不能直接读取个人最新全文；重开不打包私人期间历史或已删除私人文字，旧任务不能覆盖已完成的新版本。服务端历史不依赖 Google 连接，已保存、历史点形成、已备份分别判断；协作内核先可靠登记任务，Google worker 后续实现。

Google 登录与 Drive 授权分离，默认申请 drive.file，使用服务端离线授权安全保管 refresh token。连接、拒绝、撤销、过期、重新授权有明确状态；取消连接不删除 Drive 上已有文件。

**实施默认**：空间选择一位成员的 Google 账号作为备份目标，文件属于该账号。另一位通过 Google 原生共享访问；应用不得未经明确操作发送邀请或公开链接。无 Drive 授权仍可写日记，但必须明确尚未启用 Google 备份。

每天生成一个可读 Google Doc，按年/月目录整理，包含固定日记日期、作者名字/颜色图例和按原顺序穿插的正文。保留换行、Unicode 和双方字体颜色。提供手动“导出/更新到 Google Docs”和打开文件入口；重复点击更新同一映射文件，不能不断创建副本。

自动备份还保存带版本和校验信息的数据快照，包含可恢复的协同状态、作者映射、文字顺序、UTC 时间、日期、读取进度与必要配置（个人快照只含本人的读取进度，空间快照不含任何人的读取进度）；不包含登录会话、OAuth 密钥或 refresh token。另行保留数据库级备份。

PG 写入与 outbox 记录在同一事务提交；后台按空间/日记串行处理，合并连续编辑。Google 失败不阻塞写日记，指数退避重试；限流、授权失效、空间不足必须可见。旧任务不得覆盖新版本。

Docs 为应用到 Google 的单向可读副本。发现 Docs 外部修改或被删除时暂停覆盖，保留现有 Google 内容，提示选择重新导出新文件；不自动把 Google 改动导回应用。写入使用版本条件防止检查后又被修改的竞态。

Google Doc 与数据快照分别记录成功版本。只有二者都覆盖某个已提交版本，才称该版本已完成 Google 备份；部分成功明确展示。备份任务以一致的正文版本生成，不导出编辑中途互相不匹配的数据。

**实施默认**：服务正常时，目标在提交后约 60 秒完成备份；此为目标 RPO，不是故障期间的保证。数据快照保留最近 30 天每日版本及最近 12 个月月度版本，删除前先确认仍有可恢复历史；这些保留周期可调整。日记删除不自动清空远端历史。

恢复需在干净环境验证：正文、顺序、作者、日期和时间一致，且可继续协作；凭据重新授权。仅能打开一个 Doc 不等于完整恢复通过。

## 10. 逻辑数据模型

以下是逻辑实体，不是已部署的 SQL schema；协同物理编码由 ADR-0002 的验证决定。

| 实体 | 关键数据与约束 |
| --- | --- |
| User / Identity | 稳定 userId、显示名、IANA 时区；认证 provider + subject 唯一 |
| Space / BindingPeriod / ActiveBinding / Invite | 每账号至多属于一个永久双人空间、原双方历次绑定、每人至多一个当前绑定、一次性邀请及本次范围确认 |
| SharingPolicy / PolicyChange | 主人自己的多段包含/排除日期集合、当前期间确认、revision 和请求幂等；对搭档不公开 |
| Diary | diaryId、ownerId、diaryDate、createdTimezone、createdAt、updatedAt、committedVersion；主人+日期唯一，独立于空间 |
| AuthorizedViewVersion / ShareEpoch | 日记、空间、接收者、绑定期间、授权代次及主人+固定搭档正文版本；live 版本和不可变 frozen 版本分别寻址 |
| AuthoredText / CollaborationState | 有序内容及稳定位置/元素标识、不可变 authorId、写入批次与 UTC 时间、恢复协同所需状态；允许压缩相邻区段 |
| EditOperation | operationId、diaryId、认证 actor、设备/会话、目标稳定标识、载荷、客户端/服务端时间、提交版本；幂等 |
| ReadCoverage | 用户、日记、稳定文字范围/元素集合、已读合并信息；不得用一个最大序号代替 |
| GoogleConnection / ExportMapping | 空间选定目标、凭据安全引用、文件夹和 Doc ID、应用管理的远端 revision |
| Outbox / BackupArtifact | 目标版本、尝试次数、下次重试、错误状态、Doc/快照完成版本、文件 ID、schemaVersion、校验和 |
| LocalPending | 本机缓存、未确认操作、操作 ID、恢复草稿；按账号、个人/空间视图、期间与授权代次隔离 |

authorId、文字顺序与时间不是可任意修改的富文本样式。客户端提交的 actor 字段不可信；服务端以会话身份确定作者。

## 11. 接口语义与安全边界

URL、框架及编码尚未固定，但以下语义须存在：

| 动作 | 输入/结果 |
| --- | --- |
| 打开或创建今天 | 会话中的主人、有效 timezone、幂等请求 ID → created/existing/conflict 与个人 diaryId、diaryDate |
| 打开指定日期 | 本人 date 或授权空间/日期/版本上下文 → 个人或共享版本；未授权内容不泄露存在 |
| 订阅协同 | 日记、视图、period/epoch、已知状态 → 权限范围内更新；不发送未授权日期、版本或停止共享后的私人变化 |
| 提交编辑 | operationId、授权上下文、稳定目标、编辑内容 → 持久化确认或拒绝；旧授权不能自动重放到新 epoch |
| 提交已读 | 日记授权视图、实际可见稳定范围 → 该视图的合并进度；过滤隐藏不算已读 |
| 修改自己的共享范围 | 当前期间、expectedRevision、请求 ID、日期集合 → 原子策略修订与版本冻结/开放 |
| 连接/断开 Google | OAuth state/回调校验，目标账号确认；断开不清空备份 |
| 请求导出、查询备份 | diaryId、所需版本 → 任务状态、成功版本、时间、可访问的 Doc 链接 |

不开放无鉴权的“提交全文”覆盖接口。浏览器协同消息、备份任务和恢复工具不能绕开作者保护。OAuth 使用 state、OIDC nonce/标准库校验，凭据加密存储且不写日志；正文按纯文本渲染，日志默认不记录日记内容。退出登录后隐藏或锁定本机缓存，不让下一个账号看到上一人的草稿；主动清理前提示未同步内容，不能静默丢弃。

## 12. 质量目标与实现顺序

**实施默认的验证环境**：桌面 Chrome/Safari、iOS Safari、Android Chrome；100ms 与 500ms 模拟 RTT、重复/乱序消息、断网、进程重启；至少包含十万字符的单篇日记。

本地输入不等待本机落库、网络或 PG；可见目标 p95 ≤ 50ms、p99 ≤ 100ms。稳定网络下双方各约 500ms RTT，远端正文可见目标 p95 ≤ 2 秒、已知正文上的普通光标移动目标 p95 ≤ 1 秒。边输入边移动时另外测正文与光标最终正确对应的延迟，不以消息抵达代替可见正确。真实编辑器/PG/WebSocket 验收须覆盖长日记、长期编辑积累、大量离线补发和多设备，记录设备、规模、网络口径、样本量及分位数。这些是工程目标，不是已测结果或故障期间的硬保证。

实现依赖：先有认证、关系与范围确认，再完成个人日记、隔离的授权视图及冻结/重开验证，随后接可靠协同、未读与 Google 导出恢复；登录鉴权在所有联调环境必须生效。当前阶段与完成情况只记在开发路线。视觉沿用已选方向，具体字体色、动画及时间浮层后调。

发布前必须通过 [验收清单](./acceptance.md) 的全部 P0。编辑器与协同组合见 [ADR-0006](./adr/0006-formal-stack.md)。部署与 PG 运维细节按后续部署设计落实；不能沿用脚手架的 D1 默认作为已确认架构。
