# @between-pages/web

The React single-page app (Vite, React Router, TanStack Query). Calls the API only through the typed client built on `@between-pages/contracts` ([ADR-0006](../../docs/adr/0006-formal-stack.md)). Diary code is split into the sub-modules of [kernel D11](../../docs/adr/2026-10-26-diary-collaboration-kernel.md): `editor-binding`, `journal`, `sender` and `sync-client`, wired together by the `diary` screen.

| `createSender({ journal, userId, diaryId, transport, onStatus, onDrafts, closes? })` (`src/sender`) | Sends one diary's journal (kernel D13): `wake()` after each append and when the connection comes back; `close(code)` when the document ended outside a submit (a refused subscription), which settles every waiting batch as a submit refused with `code` would, without sending; `stop()`. One batch in flight per account and diary across tabs, under the Web Lock `between-pages-send:<userId>:<diaryId>` (`sendLockName`). Answers by error category: `retry` resends the same batch after 1 s, doubling to 30 s, and new input does not cut the pause short; no answer (`offline`) resends it at the next `wake`, which the screen gives when the connection is back; `reconcile` looks up the receipt and confirms, otherwise drafts; `stop` turns the batch and whatever builds on it into drafts, reported through `onDrafts`, and goes on with the rest; `reauth` and `show` pause until the next `wake`; `upgrade` and `JournalUnavailable` stop for good. |
| `SyncTransport`, `SubmitResult`, `SaveStatus` | What the sender needs from the network: `submit(batch)` → `ack` / `error` / `offline` (no answer, outcome unknown), `receipt(diaryId, batchId)`. `SaveStatus`: `saved`, `syncing`, `confirming`, `offline`, `attention`, `reauth`, `upgrade`, `readonly`. It describes the queue, so `saved` follows `attention` once nothing waits; drafts stay in `journal.drafts` until deleted, and the screen keeps showing them as needing attention. |
| `createReadTracker({ diaryId, visible, onRead? })`, `unread(visible, read)`, `unreadSpans(runs, read)`, `DWELL_MS`, `Span` (`src/read-tracker`) | Reports what the reader saw (kernel D15): every second it asks `visible()` for the other person's characters on screen, and those on screen at two checks in a row on a visible page are added to the reader's own coverage through `reportRead`, starting from what `readRanges` says is already read. `onRead(ranges)` hears the whole coverage when the server's arrives and after each report, never while unknown. `unread` is visible minus read by character identity; `unreadSpans` gives the unread passages of indexed runs as `{ from, to }` text indexes, joined where they touch. `stop()`. The diary screen passes the editor's characters inside the window, and none while "只看我的文字" hides them. |
| `createSyncClient({ diaryId, generationId, epochId?, knownSeq, onCommits, onStatus, onContext? })` (`src/sync-client`) | The `/api/sync` socket of one diary generation, in the partner's epoch when `epochId` is given (subscribe and submit carry it); `onContext` hears `opened` / `stopped` notices (`ContextChange`); `onShared(shared)` hears, at each catch-up of the owner's diary and before `live`, whether it is in a live share; `caret(caret | null)` sends the own caret only while live, never queued, and `onCaret` hears others'; it implements `SyncTransport`. Subscribes from the last delivered seq, hands commits over decoded and strictly in seq order (a gap re-subscribes), resolves each submit with its ACK or error, and reconnects after 1 s, doubling to 30 s. `SyncStatus`: `connecting`, `live`, `offline`, and the final `reauth` (close 4401), `upgrade` (`PROTOCOL_UNSUPPORTED`) and `refused` (the subscription failed, e.g. `NOT_FOUND`). `receipt` calls the contract route through `callApi`. `close()`. |

## Invariants

- No `fetch('/api/...')` outside `src/api/client.ts` and `src/api/auth.ts`. `auth.ts` is the single exception, because Better Auth's endpoints are not in the contract ([authentication-and-sessions](../../docs/adr/2026-10-24-authentication-and-sessions.md) D9); everything else goes through `callApi`.
- Production builds contain no development login (it sits behind `import.meta.env.DEV`).
- An invitation token never enters TanStack Query (keys, variables or data) or the address after it is read; it lives only in the tab's `sessionStorage` until accepted, refused for good, or signed out (spaces-and-invitations D8, D12; tested).
- Relationship screens never say a diary is shared or frozen: they always say "范围已设置，日记共享尚未开放", and saving a range shows the change and asks again before sending (D5, D12; tested in jsdom and three browsers).
- Calendar days are strings end to end (D3): the sharing calendar runs in `timeZone="UTC"`, a `Date` is built only in `src/sharing-range/day.ts` (ESLint refuses `new Date(` in the module's other files; `range.ts` keeps its own UTC day arithmetic), and today comes in as `localToday()`. The sharing-range tests pass under `TZ=Etc/GMT-14` and `TZ=Etc/GMT+11` with the same day strings.
- Server data lives in TanStack Query; diary text lives only in the collaboration modules and, for a history preview, a shared diary's excerpts or a diary of the day feed, in that component's state, never in Query or Zustand ([ADR-0006](../../docs/adr/0006-formal-stack.md) §8). The history list in Query carries no text.
- History is read-only: no restore, rollback or "set as current" exists anywhere. While a version is previewed the editor stays mounted and hidden, so pending input, undo and the caret are untouched, and the scroll position comes back on return (kernel invariant 4, D6; tested in jsdom and three browsers).
- Editor steps are translated into `Y.Text` inserts and deletes as they happen, never by comparing whole texts; Yjs's delta of the same transaction gives the intent (tested with repeated characters that a string diff confuses).
- No edit path deletes or changes a character another user wrote: typing, deleting, Enter, cut, paste, IME and undo/redo over such text are refused or, for Backspace/Delete, jump past it without deleting (EDIT-04/05); every emitted operation passes the server's `acceptBatch` (kernel invariant 3, tested).
- Personal undo covers only this instance's own edits, never applied updates, and starts empty with each generation's binding (kernel invariant 19, tested).
- During an IME composition only the confirmed text becomes an operation; updates arriving meanwhile are shown after it ends (EDIT-11, tested).
- The other person never sees the own caret move over IME candidate text, which `Y.Text` does not hold: it stays where the composition began and moves once the confirmed text is in (tested for pinyin, Japanese conversion, Korean syllables, a dead key, Vietnamese Telex and whole-word Latin keyboards).
- A paste whose operation would not fit one 1 MB submit message (base64 included) is refused at input, without an operation (D13, tested against the encoded message); pasted text is plain, with `\n` line breaks and no control characters.
- `editor-binding` imports no other web sub-module, so it knows neither the network nor IndexedDB (`verify-dependency-direction`).
- Opening a diary never scrolls it; only "跳到第一处", "下一处未读" and the reader's own scrolling move the page, and none of them changes text, sends anything or tells the other person (unread-and-day-page invariants 6, 14; tested in jsdom and three browsers).
- The day page runs one independent session per diary: an edit, an undo or a paste reaches only the diary it was made in, each diary subscribes and submits on its own, and a selection reaching from one editor into the other edits neither; a diary hidden by the view switch stays mounted and is never counted as read (unread-and-day-page invariants 7, 9; tested in jsdom and in Chromium, Firefox and WebKit with two accounts). The own diary is marked "仅自己可见" whenever it is not in a live share (invariant 11), and no page switches between one and two diaries by itself (invariant 13; tested).
- Remote commits, view switches and the own-text-only filter keep the anchor character within one line of where it was in the window, with the caret's character as anchor while typing and focus never taken (invariant 8, SYNC-06; tested in Chromium, Firefox and WebKit with a 40-line insertion above). The browsers' own scroll anchoring is off (`overflow-anchor: none`), so only the app adjusts the scroll; the unread notice keeps its line and the other notices float, so they never shift the text.
- Reading is recorded only for text that stayed on a visible page for about a second, by character identity, and only the reader's own progress; nothing is shown to the other person (kernel D15, invariant 26). Text hidden by "只看我的文字" is not on the page, so it is never counted as read (spec §8.1, EDIT-14; tested).
- Local writes are IndexedDB transactions with `strict` durability, and count only once complete. The `localSequence` is allocated in the same transaction that stores the operation and is shared by every tab of the account; batches follow it, never operation IDs (kernel invariant 22, tested).
- A send batch is stored before its first send and resent unchanged, after a lost answer or a restart (invariants 9, 10, tested). The next batch is formed only after the journal confirms the last one, which removes its operations, stores the receipt and merges the text into the baseline in one transaction.
- An operation written against a generation that is no longer current is checked inside its write transaction and becomes a draft, never pending.
- A refused batch, and every pending or later operation that may build on it, becomes drafts; nothing of it is retried or sent in part, and it never joins a batch with input that does not depend on it (invariant 8). Drafts stay until the user deletes them (invariant 20, tested).
- The screen says "已保存到服务器" only when nothing waits on this device or in flight: the sender leaves `saved` the moment it is woken, before the stored operation is announced (SAVE-01, tested in three browsers).
- "已同步 · 对方可以看到" replaces it only while the other person can read what is saved. For the own diary that is the server's word at each catch-up, then any `stopped` notice, which the server sends after that catch-up; a stop missed while offline is learnt on reconnecting, before anything new is sent (tested in jsdom and three browsers).
- Text the journal could not store stays on screen and in memory, is retried with its operation IDs, and leaving the page asks first; the editor is never rebuilt over it (SAVE-06, tested).
- A batch whose submit came back with a context error is first looked up by receipt: committed means saved, never a draft (invariant 21, tested).
- Without Web Locks the sender stays read-only and sends nothing.
- Commits reach `onCommits` only in seq order without gaps, and the socket's base64 exists only inside `sync-client`; a diary state's `state` is decoded where its text is opened (the session, `day-text`).
- Poking or petting the viewer's own mascot sends nothing; the partner's mascot sleeps only by their sleep schedule and zone, the same rule as "大概在睡", and nothing on the home says whether the partner is online or has seen a poke (window-mascots invariants 1, 3, 5; tested).
- The home page renders no diary text or excerpt: it reads the day list only for dates, who wrote and unread, and requests no diary; diary text appears only after "继续写今天", a recent date, "所有日记" or the header's "日记" (digital-paper-interface invariant 9, opening-book-home invariant 1; tested).
- The site header lists only pages the caller can reach now: no 「一起」 for an account that was never bound, no "两地时间" without a current binding, no "搭档" while bound, the archived space and its records after unbinding; it shows no diary text and nothing of the partner's unrevealed gifts (digital-paper-interface D1, book-frontend-workspace invariant 7; tested).
- `ui` imports no other web sub-module.
- Styles: Tailwind (with its reset) and `fonts.css` come first in `styles.css`, and every page is drawn with Tailwind utilities on its tokens; there is no older stylesheet. The few classes that code sets on text it does not lay out (`author-slot-1`/`-2`, `author-hidden`, `remote-caret`, `remote-selection`, `unread-flash`) sit in the `components` layer, so a utility on the same element wins; the editor's type and the saved line's check mark are in `diary/diary-block.css`, the unread tools' place over the wide day in `diary/workspace.css`. Class names the browser tests find things by stay on their elements (`save-status`, `diary-editor`, `history-text`, `author-info`, `share-state`, `refusal`, `unread-banner`, `day-scroll`, `day-feed-scroll`, `feed-diary`). Titles use the self-hosted Noto Serif SC (`Between Serif`, `public/fonts/`, 101 `unicode-range` slices, SIL OFL), so a browser fetches only the slices of the characters it shows.
- Space features never hide a partner's private record themselves: the server leaves it out of the answer (space-records D9); the page shows what it gets.
- The day feed reports reading only through `createReadTracker`, for the other person's characters inside its scrolling box and the window on a visible page at two checks a second apart; text read ahead off screen, a collapsed diary (never fetched), a hidden page and an unmounted date count for nothing (book-frontend-workspace invariant 5, tested). It never shows the text of a diary being written (invariant 9, tested), and jumping to a date takes two requests around it, never paging from the newest, nor creates a diary (invariant 4, tested). Its ↑ / ↓ show only when that direction has unread and reach an unread date not loaded through `next-unread`, never by reading other dates' text; looking scrolls nothing and reports nothing, and a click scrolls only the feed's box and leaves the focus where it was (invariant 5; tested in jsdom and in Chromium and WebKit by `e2e/feed-unread.spec.ts`).
- The diary page shows one main area, the feed or the day, never both. The day edits only the date in the address and never waits for the feed or the index; the feed's position lives in each history entry's state, never in the address, so going back to the feed from a day opened by the feed, the index or "这一天", by "连续读" or the browser's back, shows it where it was (digital-paper-interface invariant 10; tested in jsdom and in Chromium and WebKit); a deep link to a date with no diary shows "写这天" and creates nothing until it is pressed (book-frontend-workspace invariant 4; tested). The date index reads the day list only, never a diary's text, so it shows no text and counts nothing as read (digital-paper-interface invariant 3; tested). Narrow, the index folds into a date picker and the feed and the day are one page each (book-frontend-workspace invariant 6; tested in jsdom and in Chromium and WebKit at 375 px). In the wide diary page a diary counts as on screen only inside the main area's box, so text scrolled out of it is not read; the window's edges are measured where the editor itself is under the point, so a floating notice or button over the text never makes the rest of it count as on screen (tested in Chromium, Firefox and WebKit by `e2e/reading.spec.ts`).
- `day-text` imports no other web sub-module: it knows no editor, session, socket or API (`verify-dependency-direction`).
- A shared page is the one exception to the next rule: opening it reports it seen (shared-pages D5).
- A space record is reported as seen only after it has been on a visible page for about a second, with the mark it was loaded with, so a change that arrived later stays unread (space-records invariant 9).

## How to test

```sh
npx vitest run --project web
```

- Tier: component tests in jsdom with `@testing-library/react`, rendering the real `appRoutes` in a memory router (`test/render.tsx`); `fetch` is stubbed at the network boundary with contract-shaped responses. See [docs/testing.md](../../docs/testing.md#tiers).
- `sharing-range` tests click the calendar's day buttons by accessible name with a fixed `today`; run them twice, `TZ=Etc/GMT-14 npx vitest run --project web apps/web/src/sharing-range` and `TZ=Etc/GMT+11 …`, when touching the calendar.
- `editor-binding` tests drive a real view with DOM events (keys, paste, composition, `beforeinput`) and the transactions ProseMirror dispatches for typed text; every operation is checked with `packages/collab`'s `acceptBatch`, and the other author's edits arrive as its re-encoded deltas. No network. Tests carry `[adr:diary-collaboration-kernel#N]` for the invariant they verify.
- `journal` and `sender` tests run on `fake-indexeddb` with real Yjs updates and no editor; the sender's Web Locks are a stand-in with the browser's one-holder-per-name order, and its transport a stand-in server that remembers committed batches. `sync-client` tests replace `WebSocket` and `fetch` at the network boundary, parsing what the client sends with the strict contract schemas.
- `day-text` and `day-feed` tests replace layout where jsdom has none: `getBoundingClientRect` (and `Range` boxes) stubbed per element, `IntersectionObserver` with a stand-in whose callback the test calls (without one every date counts as near), and fake `setInterval` for the read tracker's dwell. The feed's tests carry `[adr:book-frontend-workspace#N]`.
- `diary` tests run the real session and screen on the same stand-ins (`test/diary.ts`), with text entered through paste events and storage failure injected at `IDBObjectStore.put`.
- The root `e2e/diary.spec.ts` runs the screen in Chromium, Firefox and WebKit against the real API and PostgreSQL, entering through the workspace ("写今天" at `/days`, a past date through the feed's date jump): SAVE-01/DATE-02, DATE-06, DATE-07 (the feed newest first, in full), SYNC-04 (two devices of one account, the second opening the same date), SAVE-02 (written while disconnected, across a reload), SAVE-03 (lost ACK), SAVE-07/11 (refused batch to drafts), read-only without Web Locks, and EDIT-16 (own history after the server's two-minute rule closes a point, appearing in the open panel: list, read-only preview, return); socket failures are made with `routeWebSocket`. ## Known limitations

- A shared page has no "下一处未读" and clears its mark on opening (shared-pages D5); an open page learns it was deleted, unbound or bound again only at its next submit, reconnect or 30 s refresh; nothing is pushed to it yet.
- The tab icon shows two mascots, so at 16 px they are two coloured shapes without faces; the faces read from 32 px up (the `favicon.ico` size, the home-screen icons).
- The windows are drawn in SVG to the approved effect image's direction, not a copy of it; the grain is one small noise filter per window.
- Confirming a range on the space page opens and freezes diaries, but that page has no editor of its own to pause: a diary open in another tab or device reconciles on the `opened` notice or its next subscription (kernel D7), so opening never waits for other devices.
- The wishes page holds every record in its four tabs, gift wall included, without paging; fine for two people's records. Its "跳到第一处" counts what was unread when the page opened, and the tabs open on "{partner} 的心愿" each time, not on the last one shown.
- Deleting an anniversary, a wish or a gift and revealing a gift still ask with the browser's own `confirm`, and the 「一起」 pages switch between each other through the header's menu: the design package's row of sibling pages under the header is not built.
- The anniversaries page lists everything on one page; the home line refetches every 5 minutes and the page every minute, so a date the partner corrected shows on the next fetch.
- The past-date picker is gone from the home page; the day feed's date jump replaces it.
- The site header reads the relationship and the space features' unread on every signed-in page (cached by Query), so the dots are always current; the old pages still show their own entry dots too.
- The browser's zone is reported from the home page and the clocks page only (opening the app always lands on home); a diary opened straight from a link reports at the next visit to either. The partner's clock follows their last report, with no hint of how old it is (two-clocks open question).
- Relationship state refreshes on focus, after the caller's own changes and with "刷新"; there is no polling or socket, so a partner's unbinding shows on the next refresh.
- The day feed keeps every loaded text mounted, far ones included; it does not unload display nodes yet (D4 allows it), so a very long session holds every date it has shown. Each expanded diary with text runs its own read tracker (one `readRanges` read, a check a second).
- "你在别处正在写" follows the side, not the writer: `writing` on the own diary does not say who wrote, so the partner writing their words in it reads the same.
- The feed asks `next-unread` again for every new window, a page loaded at the other end included, even when its boundary did not move; the server's cache makes the repeat cheap. A loaded passage counts by where it is laid out, so one under a button still counts as on screen. While the list cannot be read, a date's dot still follows a loaded text's own unread, which describes the text on screen.
- "跳到日期" moves the list, not the focus: a keyboard user Tabs from the date input through every loaded date above the target (two links each, up to a page of 20 dates) to reach it.
- The day feed learns of the partner's new text by reading again (entry, focus, every 45 s), not by push; with the server's history-point rule it lags the diary by up to a few minutes (unread-and-day-page D3, book-frontend-workspace D8).
- Only the date index beside the day editor follows the editor's word on the own diary being written (F-08). The feed is never shown beside the editor and reads the list again when it comes back; a feed or index open in another tab or on another device keeps the own avatar hollow, or the date at "还没有写字", until its next read (focus, the page coming back, every 45 s). The index keeps the editor's last word for that date after the day is left, so a change to the same own diary from another device shows there only after this page is opened again.
- The feed's position reaches the history entry 0.4 s after scrolling stops; leaving within that time by back, the site header, the index or "这一天" brings back the place before the last scroll. The feed is unmounted while a day is shown, so coming back reads its dates again around that position (two requests); the date index keeps its own window of the day list, a second read of `GET /api/days` beside the feed's. Going forward again shows the position the entry was pushed with.
- Wide or narrow is decided at 56rem when the page renders and again on a resize across it, which rebuilds the page and reopens the day's sessions.
- An old `/diaries/…` bookmark goes home rather than to its diary (drop-single-diary-page): the date is picked again from the index.

- The history preview still marks runs `author-self` / `author-other` rather than the slot colors of the editor. `src/main.tsx` (excluded from coverage) only mounts providers and the router.
- The day page holds two sessions and two sockets (D6, no protocol change), so memory and rendering double; a 100,000-character diary is already slower than the target in WebKit, two of them more so.
- All three engines keep a selection dragged with the mouse inside the editor where it started, so a selection across both diaries arises only from script; the binding then refuses edits while one end is outside the editor (Firefox also refuses natively). A drag that starts in the own diary and ends over the other selects own text only, which deletes as usual.
- The swapped order is kept per device, not per date or account.
- "只看我的文字" sits in the legend at the top of the page and is not sticky, so a reader far down the text scrolls up to reach it; the anchoring around it matters once the control stays in reach (the visual redesign).
- Direction hints and "下一处未读"'s "after the window" need layout; without it (jsdom) the next passage is the first.
- Author colors are drawn again from `Y.Text` on every change (a walk of the text). On a 100,000-character diary, WebKit takes about 132 ms (p95) from keystroke to paint, against the 50 ms target; Chromium and Firefox stay within it ([measurement](../../docs/validation/diary-kernel-sharing-2026-10-27.md#k17本机输入远端正文与光标延迟)). The whole text is one ProseMirror block (ADR-0006 §11), which WebKit lays out again on every keystroke.
- "已同步 · 对方可以看到" means the other person can read what is saved, not that they have: there is no delivery receipt or presence. A commit landing just after a stop, before its `stopped` notice arrives, shows it for that moment; until the first catch-up, the own diary shows 已保存到服务器 even when it is shared.
- A partner device that was closed when a share froze turns that share's unsent input into drafts the next time the diary is opened there.
- History has no word-level diff (D6: not in the first release).
- Offline, the day list shows no cards, only that it cannot read the list, although diaries opened on this device are in the journal and open and continue offline from their link. Listing them from the journal would need the diary date in the journal's baselines (spec §4 "离线可读本机已缓存……的日记"). The list also reports any failure that is not an API answer as offline.
- Opening a diary while offline works only for one this device has stored; there is no offline list of diaries, and the page itself still needs the server to load (no service worker).
- Refused input typed one character at a time is stored as one draft per character; only the display groups it.
- The journal is not locked on sign-out yet.
- Dragging text into the editor is blocked rather than handled as a paste.
- Undo steps are Yjs's 500 ms capture groups, split whenever typing, deleting and replacing alternate.
- `operationId` uses `crypto.randomUUID`, so the app needs a secure context (HTTPS or localhost), as Web Locks will.
- Authorship checks walk the whole `Y.Text` on each deletion (`authorRuns`); fine at diary size, not tuned for very long documents.
- IME and paste are tested in jsdom; the browser suite types through Playwright's keyboard, not a real IME or clipboard.
- No screen for linking a second login method; the server supports it (ADR D3).
- Browser-level login and diary flows are covered by the root `e2e/` Playwright suite, not here; the browser suites under `prototypes/` remain the editor behavior baseline.
