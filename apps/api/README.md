# @between-pages/api

The Fastify process: registers the routes defined in `@between-pages/contracts`, validates and serializes them with Zod, and publishes the OpenAPI document generated from them. It owns sessions, the personal diary routes, the collaboration WebSocket and the PG commit chain of the [diary collaboration kernel](../../docs/adr/2026-10-26-diary-collaboration-kernel.md) (phase 2: personal diaries; sharing arrives in phase 4).

## Public surface

| Export | Contract |
| --- | --- |
| `buildApp(deps)` (`src/app.ts`) | Returns a ready, non-listening Fastify instance with every contract route and the sync socket registered. `deps`: `publicOrigin` (the only trusted `Origin`), `currentUser(headers)` (the caller or `null`), `db` (diary storage; registration never queries it), optional `authHandler` (mounted at `/api/auth/*`), `logger`, `onClose`, `historyIdleMs`. Tests and the OpenAPI generator use it, so they exercise the same registration production serves. |
| `renderOpenApi()` (`src/openapi.ts`) | The OpenAPI 3.1 document as the exact text committed in `openapi.json`. |
| `npm run dev` / `npm start -w @between-pages/api` | Listens on `HOST:PORT` (defaults `127.0.0.1:3000`), reading the repo-root `.env` if present. |
| `GET /api/health` | Public. `200 { "status": "ok" }` while the process serves requests. |
| `GET /api/me` | `200 { user: { id, displayName } }` for the signed-in user; `401 UNAUTHENTICATED` otherwise. |
| `POST /api/diaries` | `{ timezone, date? }` → `{ created, diary }`: the caller's diary for `date`, or for today in `timezone` from the server's UTC clock; created with its first generation when missing. A future date or a zone that is not an IANA name is `400 VALIDATION_FAILED`. |
| `GET /api/diaries/:diaryId` | `{ diary }`: the current generation's committed state (base64 Yjs update), `generationId`, `seq`, clientID bindings. |
| `GET /api/diaries/:diaryId/receipt?batchId=… \| ?operationId=…` | `{ receipt }` of the caller's committed batch, or `{ receipt: null }`. The same shape as the ACK; answerable forever. |
| `GET /api/diaries/:diaryId/history[?cursor=…]` | History points newest first, 50 per page, computed at read time (kernel D6); the cursor is opaque. `nextPointInMs` is how long until the group being written becomes a point, or `null` when none is open. |
| `GET /api/diaries/:diaryId/history/:publicId` | One committed version as server-rendered author runs; `500 VERSION_UNREADABLE` when its stored parts fail their sha256. |
| `GET /api/sync` (WebSocket) | The collaboration socket, messages per `@between-pages/contracts` `ClientMessage` / `ServerMessage`. Handshake: `Origin` and session, else `403` / `401` before upgrading. `subscribe` → `synced` (commits after `knownSeq`) then live `commit`s; `submit` → `ack` after PG COMMIT, then a `commit` broadcast, or `error` with the D10 code. A session that ends closes the socket with `4401`. |
| Diary routes, everyone else | A diary the caller does not own answers exactly like one that does not exist: `404 NOT_FOUND` / `NOT_FOUND`. |
| Errors | Every failure on our `/api/*` routes is `{ error: { code, message } }` (`src/errors.ts`); internal details are logged, never returned. |
| `openapi.json` | Generated contract for non-TS clients. Never edit by hand: `npm run openapi`. |
| `createDb(url)` (`src/db/client.ts`) | `{ db, pool, close() }`: a Drizzle instance over one `pg` pool. The caller owns it and must `close()` it. |
| `runMigrations(url)` (`src/db/migrate.ts`) | Applies every pending migration in `drizzle/`; already-applied ones are skipped. Used by `npm run db:migrate` and the test setup, so production needs no drizzle-kit. |
| `users` (`src/db/schema.ts`) | Domain users: `id` (UUID issued by the auth layer), `display_name`, `created_at`, `last_seen_at`. |
| `parseConfig(env)` (`src/config.ts`) | Parses the environment at startup; throws `ConfigError` naming every bad variable. Refuses `AUTH_PROVIDER=dev` in production or on a non-local `PUBLIC_ORIGIN`, and `HISTORY_IDLE_MS` (the end-to-end suite's shorter history idle time) without `AUTH_PROVIDER=dev`. Variables: `.env.example`. |
| `createAuth(config, db)` (`src/auth/auth.ts`) | The Better Auth instance: Google (`google`) or the mock issuer (`dev`, via the `genericOAuth` plugin), database sessions, no provider tokens kept, no implicit account merge. |
| `createCurrentUser(auth, db)` (`src/auth/current-user.ts`) | The `currentUser` for `buildApp`: session → `{ id, displayName }` or `null`; creates the `users` row on first use and writes `last_seen_at` at most every 5 minutes. Authenticated HTTP requests count as activity; the WebSocket handshake and heartbeat will too. |
| `/api/auth/*` | Better Auth's own endpoints (sign-in, callback, sign-out, link). Not in the contract or OpenAPI. |
| `src/db/auth-schema.ts` | Better Auth's tables (`auth_*`), generated by `npm run auth:generate`, then hand-edited (timestamptz, unique login identity); see its header. Only `src/auth/` and `src/db/` may import it. |
| `npm run dev:oidc` | Mock OIDC issuer on `DEV_OIDC_ISSUER` for local login: the name typed on the login page becomes `sub=dev-<name>`, `email=<name up to "#">@dev.local`. |
| `diaries`, `diary_generations`, `diary_client_bindings`, `diary_commits`, `diary_operations`, `diary_character_ranges`, `diary_snapshots`, `backup_outbox` (`src/db/schema.ts`) | The personal part of kernel D9: one diary per owner/date with its internal `version` and current generation; one commit row per batch (the receipt), one row per operation (sha256 of the upload only), inserted character ranges per operation, a snapshot every 100 versions, a personal backup task per commit. |
| `drizzle/` | Generated migrations. Never edit by hand: change `schema.ts`, then `npm run db:generate -- --name <what-changed>`. |

Sub-modules of `src/` (kernel D11), top to bottom; each imports only from the layers below, as `verify-dependency-direction` checks:

| Layer | Sub-module | Public surface |
| --- | --- | --- |
| Transport | `routes/` | `diaryHandlers(services)`: the HTTP handlers above; `ContractRequest<Name>`. |
| Transport | `ws/` | `registerSyncSocket(app, deps)`, `SESSION_RECHECK_MS` (60 s), `TRANSPORT_MAX_BYTES`. |
| Service | `commit/` | `createCommitService(store)` → `commit(actor, batch)` (`CommitOutcome`; throws on PG failure, lock timeout or `VersionUnreadable`) and `receipt(actor, diaryId, { batchId } \| { operationId })`. |
| Service | `diaries/` | `createDiaryService(store)` → `open(owner, { timezone, date? })`, `view(viewer, diaryId)`, `catchUp(viewer, diaryId, generationId, knownSeq)`. |
| Service | `history/` | `createHistoryService(store, idleMs?)` → `page(viewer, diaryId, cursor, now)`, `version(viewer, diaryId, publicId)`; `historyPoints(timeline, now)`, `nextPointIn(timeline, now)`. |
| Service | `outbox/` | `registerBackups(locked, version)`: the backup tasks of one commit, in its transaction. |
| Service | `events/` | `createEvents()` → `publish(event)`, `subscribe(diaryId, listener)` (returns unsubscribe). In-process only. |
| Storage | `store/` | `createStore(db)` → `read(fn)` (one read-only snapshot), `withDiaryLock(diaryId, fn)`, `openPersonal(...)`; `DiaryQueries`, `LockedDiary`, `COMMIT_LOCK_TIMEOUT`, `SNAPSHOT_EVERY`. |

## Invariants

- Every route is registered from a `routes` entry in `@between-pages/contracts`; no path or response shape is written inline.
- Responses are serialized through their Zod schema, so a handler cannot return a field the contract does not declare.
- `openapi.json` equals `renderOpenApi()` output (`verify-openapi-current`).
- `access: 'user'` routes run the login guard and answer 401 without a session (invariant 13).
- Only `src/auth/` and `src/db/` touch Better Auth or the `auth_*` tables; everything else gets the caller from `request.user` (invariant 10, `verify-auth-boundary`).
- Better Auth's origin and CSRF checks are pinned on: it disables them by default when `NODE_ENV=test`, so tests would otherwise pass against weaker settings than production runs.
- A first sign-in writes `auth_user` and `auth_account` in one transaction (the Drizzle adapter's `transaction: true`; its default is off), so a failure leaves no orphan user (tested).
- Every non-GET/HEAD/OPTIONS `/api/*` request outside `/api/auth/*` must carry `Origin` equal to `publicOrigin`, else 403 `FORBIDDEN_ORIGIN`, including unknown routes (invariant 7, HTTP part).
- `drizzle/` holds a migration for every change in `schema.ts` (`verify-migrations-current`).
- `users` is written only by this module's code and holds no email, login method or foreign key into `auth_*` tables; no domain table references an `auth_*` table ([authentication-and-sessions](../../docs/adr/2026-10-24-authentication-and-sessions.md) invariant 1, schema tests).
- A batch is acknowledged only after PG COMMIT, and broadcast only after its ACK; a rejected or failed batch writes nothing and is never broadcast (kernel invariants 6, 7, 8; socket and fault tests).
- The receipt lookup by `(diary, batch)` and by operation runs under the diary row lock, so a batch delivered twice, even on two connections at once, commits once; the same batch ID with another payload is `BATCH_CONFLICT`, a committed operation in a new batch `OPERATION_ALREADY_COMMITTED` (invariant 10, tested).
- A commit locks only the diary row, `FOR UPDATE` with a 5 s `lock_timeout`; diary creation takes the owner's `users` row `FOR KEY SHARE` first. Rows a commit writes carry user IDs without a foreign key to `users`, because the key check would lock that row too (kernel D9 lock order, tested against a held lock).
- The in-memory Yjs state of a diary is used only when its version equals PG's under the lock; otherwise it is rebuilt from PG (tested with two service instances).
- The internal `version` appears in no response or socket message (kernel invariant 15, contract test).
- Every socket `submit` re-checks the session, and every connection re-checks it each 60 s (authentication-and-sessions invariant 8, kernel invariant 24, tested with real Better Auth sign-out).
- Only `src/store/` writes SQL for the diary tables; transport never imports it.

## Allowed dependencies

- May import: `@between-pages/contracts`, `@between-pages/collab`, `yjs`, `fastify` and `@fastify/*` plugins (`@fastify/websocket` for the sync socket), `fastify-type-provider-zod`, `zod`, `drizzle-orm`, `pg`, `better-auth` (from `src/auth/` only). `oauth2-mock-server` only in `scripts/` and `test/`.
- Inside `src/`: the sub-module table of `checks/verify-dependency-direction.ts` (transport → services → store; `events` imports no other service; `app` and `server` compose everything).
- Must not import: `apps/web` ([architecture](../../docs/architecture.md#dependency-direction)).

## How to test

```sh
npx vitest run --project api      # *.db.test.ts are skipped without a database
npm run test:db                   # all tests against a disposable PostgreSQL 18 (Docker)
```

- Tier: integration through `app.inject()` — the real router, no network socket — and `*.db.test.ts` against real PostgreSQL. See [docs/testing.md](../../docs/testing.md#tiers).
- Database tests read `TEST_DATABASE_URL`; `test/global-setup.ts` migrates it once per run. Without it they are skipped with a notice locally and fail the run in CI.

## Known limitations

- Personal diaries only (kernel phase 2): no epochs, partner writes, authorized-state reader or space backup targets; anyone but the owner gets `NOT_FOUND`. Those arrive in phase 4.
- Sign-out publishes no event yet, so an open socket learns of it on its next `submit` or within the 60 s recheck (the "session invalidated" event is phase 4).
- Commit events are in-process: one API instance (kernel D11). Correctness does not depend on it; a missed broadcast is caught up by seq.
- The 1 MB cap applies to the JSON message, so base64 leaves about 750 KB for the updates of one batch. The phase-3 paste limit must count the encoded message.
- `backup_outbox` tasks are registered but nothing runs them yet; the worker arrives with the Google backup phase.
- `ws` ships no types and `@types/ws` is not a dependency, so the socket object is untyped inside `src/ws/`.
- Session tokens are stored as issued; Better Auth has no option to store only a digest. The cookie carries an HMAC signature, so the database alone cannot forge a session; the database and `BETTER_AUTH_SECRET` together can.
- Rate limiting is Better Auth's built-in, in memory and production only: reliable for one process, to be moved to the database before running several.
- Re-running `npm run auth:generate` drops the two hand edits in `auth-schema.ts`; `verify-migrations-current` then fails, which is the reminder to re-apply them.
- `drizzle-kit` 0.31 pulls an old esbuild loader with 4 moderate `npm audit` findings. It runs only when generating migrations on a developer machine, never in production; re-check when upgrading to Drizzle 1.0.
- `src/server.ts` is excluded from coverage; it only wires `buildApp()` to a port.
